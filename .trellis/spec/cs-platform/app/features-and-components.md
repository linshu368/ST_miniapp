# CS Platform 功能与组件规范

## Telegram 回访流

画像簇选择/刷新 → 用户列表筛选 → 会话/SOP → 发送消息 → 状态推进/特殊备注；并支持群发与导出。用户、画像、会话和消息的 ID 不得互换。筛选/选中是 UI 状态，服务端列表与消息是 Query 状态。

## MiniApp 客服流

独立选择 test/production backend → 拉取客服会话 → 选中会话 → 轮询消息 → 回复。环境是所有 support query key 和 mutation 的组成部分；切换时清空选中与旧消息。

## 交互硬规则

- 空态、loading、error、success 必须可区分；失败保留输入并允许安全重试。
- 发送、群发、状态推进和备注保存期间禁用重复提交；未知提交结果不得自动重复写入。
- 群发必须展示目标条件/人数、消息内容和不可逆影响；结果展示成功、失败和可重试子集。
- 导出视为敏感数据操作：最小字段、明确触发、不把 token 写入文件、不长期缓存导出内容。
- 新能力设计需说明部分成功、Telegram 限流/超时、会话过期、重复回复和人工恢复路径。
