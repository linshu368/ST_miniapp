# 我的页面官方社群入口与入群奖励

## 1. 背景与目标

在“我的”页面增加“官方社群”入口，点击后从底部拉起说明弹窗，引导用户进入 Telegram 官方社群。系统仅在确认用户真实入群，且 Telegram 身份与当前 MiniApp 账户匹配后，一次性赠送 500 星尘，并在“消息中心 → 官方”发送到账通知。

本任务当前只完成需求、技术方案和任务拆分；用户确认前不进入开发。

## 2. 成功口径

- 用户能稳定找到官方群入口，并理解奖励条件和手动入群兜底方式。
- 点击或拉起 Telegram 不等于入群，不得因此发奖。
- 同一账户对同一官方社群终身最多获得一次奖励和一条到账通知。
- 奖励、钱包流水、领奖记录、官方通知保持一致，不重复、不丢失。

## 3. 核心定义

- **当前账户**：MiniApp 签名登录态中的 Telegram user id → `app_core.users.tg_id` → App 用户 UUID。
- **官方社群**：本期唯一配置的 Telegram 群/超级群，以稳定 `chat_id` 为业务标识；群 username 仅用于展示和跳转。
- **真实入群**：Telegram 成员状态为 `member`、`administrator` 或 `creator`。打开预览、提交申请、`left/kicked` 均不算。
- **入群奖励**：500 bonus 星尘，只面向奖励活动启用后新产生的有效入群事件；活动启用前已在群的既有成员不可领取。奖励只发一次，退群不追回，再入群不补发。

## 4. 功能需求

### 4.1 “我的”页面入口

- 位于常规功能列表“消息中心”下方、“消费明细”上方。
- 左侧为天蓝色纸飞机图标；名称为“官方社群”。
- 说明：`加入秘境官方社群，与大家一起交流。`
- 右侧展示暖金色 `500 星尘`、星尘图标和弱化右箭头。
- 沿用当前暖暗棕紫色板与独立 22px 圆角功能行样式。
- 入口显隐由后端运行时总开关控制，测试与生产配置隔离。

### 4.2 底部弹窗

- 点击入口后先从底部拉起 Sheet/Popup，不直接跳转。
- 标题：`加入官方社群`。
- 说明：`即将为你打开官方纸飞机社群。系统确认已实际入群并完成账户 ID 匹配后，将自动发放 500 星尘。`
- 初始主按钮：`打开官方社群`；返回 MiniApp 后提供 `我已加入，立即验证`。
- 弹窗适配底部安全区，可下滑、点遮罩或关闭按钮关闭。
- 验证/发奖中按钮防重复提交；打开 Telegram 本身不改变领奖状态。

### 4.3 跳转失败兜底

- 优先使用 Telegram Mini App 官方 bridge/SDK 打开群链接。
- bridge 不可用或调用抛错时展示兜底卡片；不声称能可靠获知外部页面是否真正打开。
- 完整展示 `@MijingAI_Official`，提供复制按钮和手动搜索说明。
- 跳转失败、复制账号均不发奖。

### 4.4 入群确认与账户匹配

- 主链路：官方群 Bot 作为管理员接收 `chat_member` 更新，仅处理目标 `chat_id` 的有效入群状态。
- 辅助验证链路：用户点击“我已加入，立即验证”，后端以当前签名登录态 user id 调用 `getChatMember`，并查询是否存在活动启用后记录的合格入群事件。`getChatMember` 只能确认“当前是否在群”，不能证明入群时间，因此不得单独据此向既有成员发奖。
- 两条链路均使用 Telegram 数字 user id 匹配账户，不使用 username、昵称或手机号。
- Webhook 校验 secret token，并按 `update_id` 去重；未知群、未知账户、非入群状态不发奖。
- 用户在活动启用后通过指定入口入群、但当时尚未建立 MiniApp 账户映射时，系统保留合格入群事件；后续登录并主动验证后可领取。
- 匹配失败不发奖，本期不提供人工补发 UI。
- 活动启用前已经在群的成员，即使上线后主动验证，也返回不符合本期资格；不得仅凭当前 member 状态补发。

### 4.5 一次性奖励与通知

- 满足条件后增加 500 bonus 星尘。
- 唯一领奖凭证为 `(app_user_id, community_chat_id)`。
- 重复点击、验证、Webhook 重放、并发回调、退群再入群均不重复入账。
- 金额从后端运行时配置读取，首发 500；前端展示以后端响应为准。
- 奖励事务同时生成仅该用户可见的官方定向通知。
- 标题：`您的 500 星尘已到账`。
- 正文：`欢迎加入秘境大家庭！为您赠送500星尘作为见面礼，感谢您的支持与喜爱。`
- 通知金额与实际金额来自同一配置；重复事件不重复通知。
- 到账后刷新钱包余额和消息未读数。

### 4.6 弹窗状态

| 状态 | 表现 |
| --- | --- |
| 加载中 | 查询配置和领取状态，按钮禁用 |
| 未验证 | 展示规则与“打开官方社群” |
| 待验证 | 展示“我已加入，立即验证” |
| 验证中 | 防连点，不提前显示到账 |
| 已到账/已领取 | 展示金额和到账状态，不再发奖 |
| 未入群/待审批 | 提示完成入群后重试 |
| 既有成员不符合资格 | 说明本奖励仅面向活动上线后的新入群用户，不发奖 |
| 配置关闭 | 入口隐藏且不允许新领取 |
| 服务异常 | 提供稍后重试及手动入群信息 |

## 5. 明确不做

- 不新增其他社群、社群列表或社群运营页。
- 不以点击、跳转、复制或提交入群申请作为发奖条件。
- 不支持手填 username/手机号，不做账户合并或奖励转移。
- 不做退群扣回、连续留群奖励、群活跃奖励。
- 不改签到、充值、消费明细、客服和邀请中心规则。
- 不提供人工补发入口、定时全群扫描或复杂运营看板。

## 6. 依赖与上线门槛

- MiniApp Bot 加入测试/生产目标群并具备成员事件和成员查询所需权限。
- Webhook 订阅包含 `chat_member`；环境分别配置 chat id、群链接、备用账号和 secret。
- 数据库 migration 先在测试环境手工执行，验证并发幂等、账务对账和回滚说明。
- 测试通过后由经年确认上线；未确认则停留测试环境。

## 7. 待确认决策

1. 是否允许当前 MiniApp Bot 作为官方群管理员并接收 `chat_member`（推荐：允许）。
2. 测试环境仍需提供测试群的稳定数字 `chat_id` 与测试邀请链接；生产公开入口已确认为 `@MijingAI_Official`（链接按 `https://t.me/MijingAI_Official` 规划），仍需在 Bot 入群后读取并确认生产群数字 `chat_id`。
3. **已确认：活动启用前的既有群成员不可领取。** 主动验证必须同时存在活动启用后的合格入群事件，不能只看当前成员状态。
4. 总开关是否同时控制入口和新发奖（推荐：同时关闭；不影响历史记录）。
5. 奖励金额、入口开关、链接和文案是否均由后端配置（推荐：是）。
6. 到账时效（推荐：Webhook 正常 1 分钟内；漏事件通过主动验证即时补偿）。

## 8. 验收标准

- [ ] 入口顺序、图标、文案、500 星尘提示及暗色视觉符合参考图和现有页面。
- [ ] 点击后从底部拉起弹窗；安全区、遮罩、关闭和按钮状态可用。
- [ ] 能尝试打开官方群；失败时完整显示并可复制备用账号。
- [ ] 点击、复制、待审批、匹配失败均不会发奖。
- [ ] 真实入群事件能按 Telegram user id 匹配账户并发放 500 bonus 星尘。
- [ ] 主动验证同时校验当前成员状态和活动启用后的合格入群事件，不会把奖励发给既有群成员。
- [ ] 领奖记录、钱包、ledger、官方通知在同一事务成功或回滚。
- [ ] 唯一约束吸收重复与并发，余额和通知仅增加一次。
- [ ] “消息中心 → 官方”出现约定通知，未读/已读状态正确。
- [ ] 到账后余额刷新；失败时不显示虚假到账。
- [ ] 退群再入群、重复事件、重复验证不重复发奖或通知。
- [ ] 未建立账户的群成员不会误发，后续登录验证可领取。
- [ ] 活动启用前已在群的成员主动验证、退群再入群或重复尝试均不会领取本期奖励。
- [ ] 测试/生产配置隔离，关闭总开关后不产生新奖励。
- [ ] shared/backend/frontend 检查、测试环境 UAT 与账务对账通过。
