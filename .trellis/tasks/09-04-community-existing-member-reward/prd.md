# 调整社群老成员验证奖励

## Goal

让活动上线前已经在官方群的用户通过手动验证领取一次性奖励，同时保持活动上线后新入群用户由 Telegram webhook 自动发奖。

## Requirements

- 社群入口必须区分“尚未入群/待自动发奖”和“活动前已在群”两类未领奖用户。
- 只有活动前已在群的用户显示“我已加入，立即验证”按钮，不要求其先点击“打开官方社群”。
- 活动前已在群用户点击验证后，后端必须实时确认其仍是有效群成员，再原子地发放一次性奖励。
- 尚未入群用户不显示手动验证按钮；加入后继续由现有 `chat_member` webhook 自动发奖。
- 保留奖励幂等、活动开关、群 ID、奖励额度、钱包流水和通知等现有安全边界。
- 数据库变更使用新的手工迁移，不能改写已发布迁移 108；生产执行前需先在测试环境验证。

## Acceptance Criteria

- [x] `community_reward_exclusions` 中的用户在入口契约中被标识为既有成员，并能看到手动验证按钮。
- [x] 普通 `unclaimed` 用户不显示手动验证按钮，点击“打开官方社群”后也不显示。
- [x] 既有成员通过 Telegram 实时成员校验后可获得奖励，重复验证返回已奖励且不会重复入账。
- [x] 非群成员、活动关闭或配置异常时不能通过手动验证获得奖励。
- [x] 新成员 webhook 的资格判断和自动发奖行为保持不变。
- [x] shared、backend、frontend 类型检查通过，相关社群测试通过。

## Notes

- “既有成员”来源为迁移 108 上线前导入的 `community_reward_exclusions` 基线。
- 迁移回滚策略：先关闭活动；如尚未产生手动 claim，可恢复 RPC 并将 `telegram_update_id` 改回非空。已产生的奖励、流水和通知作为审计事实保留，不自动删除。
