# 预设对话平台系统规划

## 1. 背景与目标

新增一个位于 `packages/` 下、独立于 Admin 和 MiniApp 的内部“预设对话平台”。运营与测试人员可在多个互不干扰的会话中组合 OpenRouter 模型、自建预设、生产角色卡和脱敏真实用户输入，直接验证模型回复效果。

首期是内部探索测试工具，默认进入测试环境，不阻塞 MiniApp 已确定功能的测试与上线。平台必须通过显式配置分别对接现有 Supabase 测试和生产环境；任何生产数据导入均只读，不得修改角色卡、线上会话或真实用户输入。

## 2. 用户与权限

- 目标用户：内部运营、测试人员；非普通 MiniApp 用户。
- 角色建议：`viewer` 可查看；`operator` 可创建会话、发送和保存草稿；`publisher` 可发布/回滚平台默认预设；`owner` 管理成员（首期可沿用既有 Admin 账号体系而不实现管理页）。
- 权限由服务端与数据库共同校验；隐藏按钮不构成授权。
- 测试和生产 Supabase 登录态严格隔离，切换环境不得复用 session。

## 3. 范围内需求

### 3.1 独立工作台

- 新建独立 workspace 应用，建议目录/包名为 `packages/preset-platform` / `@miniapp/preset-platform`。
- 使用独立域名、部署项目、环境变量与 CORS origin；不得嵌入 `packages/admin`。
- 新建独立数据库归属域 `preset_platform`，预设、草稿、发布版本、测试会话、测试消息与平台审计均由该域管理，不归属或写入 `admin` schema。
- Admin 仅可作为登录账号/认证能力的候选复用来源，不因此拥有 Preset Platform 的业务数据、RPC 或生命周期。
- 默认进入测试环境，顶栏持续展示当前目标；生产环境采用更醒目的风险提示与确认。
- 左侧导航采用多页面工作台：对话测试、OpenRouter 模型、预设库、平台预设、测试素材、预设草稿箱。

### 3.2 OpenRouter 模型

- 读取当前可用模型列表，支持搜索、浏览、筛选和选择。
- 至少展示模型名称、厂商、模型 ID、简介/适用说明、上下文长度和最近同步时间。
- 目录加载失败时优先展示最近成功缓存并标明陈旧；无缓存则展示明确不可用状态。
- 发送时模型不可用或上游失败，不生成伪造回复；该轮保留失败状态和可重新发送入口。

### 3.3 多会话

- 支持创建、重命名、切换、归档/删除和保留多个测试会话。
- 每个会话独立保存模型、预设绑定方式/版本、角色卡只读引用、消息历史和最近状态。
- 会话 A 的配置、请求和迟到响应不得覆盖会话 B；同一会话同一时间只允许一个生成请求。

### 3.4 预设库与自建格式

- 展示已发布预设的名称、简介、标签、版本和状态，可查看并一键应用到当前会话。
- 应用只影响当前会话后续请求，不修改历史消息或其他会话。
- 预设格式必须自建、版本化、可校验；不得复活已删除的 ST 酒馆格式、宏、世界书或旧 schema。
- 首期最小格式包括元数据、系统指令正文、模型采样参数白名单和 `schema_version`；复杂 prompt 段编排待质量验证后扩展。

### 3.5 平台默认预设

- 提供编辑、保存草稿、发布并立即生效、查看发布版本和回滚入口。
- 发布生成不可变版本，不原地改写历史发布记录。
- 未显式选择独立预设的会话，在下一次发送时解析并使用最新平台默认版本。
- 已绑定独立预设版本的会话不自动切换；可手动恢复为跟随平台默认。
- 发布/回滚须防重复提交、校验并发版本、记录操作者与审计摘要，成功后重新读取权威状态。

### 3.6 生产角色卡只读导入

- 可搜索/分页读取目标环境角色卡的必要字段：稳定 ID、名称、简介、状态和生成所需上下文。
- “用于本会话”仅保存测试所需只读引用/快照，不回写生产角色卡。
- 角色卡下架或删除后保留已有测试历史，并提示重新选择。

### 3.7 脱敏真实用户输入

- 仅在已选择角色卡范围内按有界时间窗、分页读取历史用户输入。
- 返回平台前必须在可信服务端脱敏；浏览器不得获得用户 ID、Telegram 信息、联系方式或未脱敏原文。
- 仅展示脱敏正文、粗粒度时间和不可反查的临时样本 ID；使用后只写入当前输入框，仍需主动发送。
- 列表、缓存、日志、错误和遥测均不得携带原始正文或身份字段。
- 脱敏策略、可见周期、最小样本长度和高敏拒绝规则须在实现前由产品、安全和工程确认。

### 3.8 草稿箱

- 草稿可命名、保存内容、查看编辑时间、编辑、重命名和一键用于当前会话。
- 名称为空时拒绝；同名时明确选择覆盖或另存，不静默覆盖。
- 草稿未发布前不影响平台默认预设或其他会话。
- 并发更新采用版本前提；冲突时保留本地内容并要求刷新/另存。

### 3.9 状态与体验

- 发送前一眼确认当前环境、会话、模型、预设来源/版本和角色卡。
- 明确区分平台默认、会话独立预设、草稿未发布、发布生效、生成中、失败、取消/超时。
- 视觉沿用参考图：浅灰绿背景、白色卡片、teal 主色、约 240px 侧栏、64px 顶栏和 8/10/12px 圆角。
- 适配常见桌面宽度；窄屏允许分栏收起，不要求首期移动端完整体验。

## 4. 约束与非功能需求

- 优先使用 React 18、Vite、TypeScript strict、Ant Design、Supabase JS、Zod、Vitest；服务端继续 Fastify/Pino/Supabase/OpenRouter。
- 应用包不得互相 import；跨应用通信走 backend HTTP/SSE，共享 DTO 位于 `packages/shared/src/api/*`。
- OpenRouter key、service-role、数据库连接串和原始用户内容不得进入浏览器或 Markdown。
- LLM 调用必须复用 backend `features/generation/` 的上游原语/安全边界，不新增第二套密钥与网络调用。内部测试首期不计入 MiniApp 钱包/免费额度，但须有资源保护。
- 外部调用有明确超时；读取只在安全瞬时错误下有限重试，写操作没有幂等键时不自动重试。
- 列表分页/限量；正文设长度上限；生成设整体 deadline 与并发限制。
- 迁移只进入 `packages/shared/migrations/`，先测试后生产、每次一个文件、手工执行。
- 所有 Preset Platform 自有表、RPC、RLS、grant 与审计对象统一位于 `preset_platform` schema；禁止为了复用 Admin 登录或发布模式而放入 `admin` schema。
- test 与 production 不保证同构；project ref、API base、Supabase client 必须成组切换并 fail fast。

## 5. 明确不做

- 不向普通 MiniApp 用户开放，不修改 MiniApp 聊天页、线上角色卡或线上用户会话。
- 不做批量导入导出、预设社区、多人实时协作、模型费用看板。
- 不兼容 ST preset payload，不支持宏、世界书、正则脚本和任意 provider 参数透传。
- 首期不把测试会话复用为 MiniApp 正式会话，不产生 MiniApp 钱包扣费或免费额度消耗。
- 首期不新增消息队列、独立微服务或通用插件框架。

## 6. 验收标准

- [ ] 独立应用可启动、构建和部署，默认连接测试环境；缺变量时 fail fast，不回退生产。
- [ ] 数据库存在独立 `preset_platform` 归属域；平台自有表/RPC/RLS/grant 不落入 `admin`，Admin 数据模型无新增 Preset Platform 业务对象。
- [ ] 能加载、搜索和选择 OpenRouter 模型；失败时展示带时间的陈旧缓存或明确错误态。
- [ ] 会话 A/B 可分别配置并发送，切换后历史、配置和回复不串线。
- [ ] 预设库应用只改变当前会话后续发送，历史和其他会话不变。
- [ ] 发布默认预设后，跟随默认的会话下一次发送用新版本，绑定独立预设的会话保持原版本。
- [ ] 草稿支持保存/重命名/编辑/一键使用；空名、重名、并发冲突行为明确。
- [ ] 可只读选择生产角色卡并使用服务端脱敏输入；生产角色卡及线上会话无写入。
- [ ] 浏览器响应、日志和遥测不包含用户身份、联系方式或未脱敏输入。
- [ ] 模型不可用、超时、SSE 中断时显示真实失败，可安全重试且无伪助手消息。
- [ ] 发布/回滚具备权限、并发前提、审计和恢复路径；生产操作二次确认。
- [ ] Shared、Backend、新平台 typecheck/test/build 及数据库验证通过，并完成环境隔离人工回归。

## 7. 待产品/工程拍板

1. 首期预设仅供测试平台，还是发布后也成为 MiniApp M4 运行时预设。规划默认仅测试平台，为未来消费保留版本化契约。
2. V1 仅单段 system instruction + 采样参数，还是必须多段 prompt 顺序。建议先单段。
3. 真实输入时间窗、单卡数量、脱敏规则、可见角色和审计保留期。
4. 内部测试预算、速率/并发上限及高价模型范围。
5. 会话/草稿私有还是团队共享；建议首期私有会话、团队共享已发布预设。
6. 生产模式是否允许在生产库独立 `preset_platform` 域保存工作台数据；默认允许但绝不写 `admin` 或 MiniApp 业务域。若安全不允许，则由测试库的 `preset_platform` 域存储、受控 backend 只读生产素材。
7. 是否沿用 Admin 的 Supabase 账号/角色表；默认沿用认证能力以避免第二套身份体系，但平台授权关系及业务数据仍由 `preset_platform` 独立管理，不归属 Admin。
