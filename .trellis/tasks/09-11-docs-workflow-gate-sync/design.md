# 设计

## 规则分发

采用一条统一语义、多个执行入口承接：process spec 说明长期同步责任；package specs 说明编码边界；implement/check agents 负责子代理动作；Cursor check skill 负责 inline 路径；workflow 的 Phase 2 负责顺序和不可跳过的验证。避免在每处复制长篇背景。

## 统一措辞

> 对复杂方法、业务编排、非显然约束、关键状态转换和边界处理，尽量补充解释“为什么这样做”的必要注释；简单、直观、代码已能自解释的方法无需注释，不添加复述代码行为的注释。项目要求的结构化注释仍必须保留。

> 默认不因新增或修改代码自动创建测试文件。只有用户明确要求、审核后的规划/验收标准确认需要，或明确风险评估认定必须用回归测试锁定时才创建。无论是否创建测试文件，适用的现有测试、typecheck、lint、build、静态检查与人工回归仍必须执行并报告。

## 兼容与恢复

不改变现有测试脚本和 CI，只改变 AI 的“是否新建测试文件”决策。若 workflow-state breadcrumb 内容变化，必须同步 walkthrough 与回归；分开提交根文档和流程规则，便于独立回滚。
