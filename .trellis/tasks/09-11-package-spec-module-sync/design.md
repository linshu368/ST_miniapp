# 设计

## 更新顺序

先更新工程规则（package/database/shared specs），再更新功能事实（module specs），最后重建索引。这样 module 文档引用的是稳定规则，而不是临时口径。

## 模块范围

初始声明覆盖会话生成、增长/社区、运行时数据基建、计费支付、schema/迁移基建和数据库环境公共配置。执行前根据基线最终矩阵复核；如模块集合变化，先更新 `task.json.meta.module_impact` 与 `module-updates.json`，再请求审核。

## 最小化与恢复

不新增 spec 层级或平行索引，不重写未漂移章节。模块知识由脚本校验，单独提交便于回滚；若代码与已审核基线冲突，停止并回到审计，不强改实现。
