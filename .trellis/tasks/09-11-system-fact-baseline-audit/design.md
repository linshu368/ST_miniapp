# 设计

## 方法

以领域矩阵组织审计，而不是逐文件漫游：包拓扑、契约、会话/生成/计费、钱包/发奖、前端编排、数据库迁移、部署/环境、测试/CI、Trellis 流程。每格记录“当前事实—证据—文档差异—置信度”。

## 证据优先级

1. 当前实现、workflow、配置和 migration guard；2. 明确完成某决策的 commit；3. ARCHITECTURE；4. package/module spec；5. README 和实施方案。生产控制台状态若无仓库证据则标记待确认。

## 风险控制

主要风险是把留档当现状或把单次提交当最终状态。审计范围必须追到当前 HEAD，并用至少两个来源交叉核验高风险结论。无运行时可靠性、事务、容量或回滚风险。
