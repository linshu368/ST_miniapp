# 用户行为回放系统

## 目标与用户价值

集成 PostHog Session Replay，让产品和工程团队能够按用户、角色卡、聊天会话、时间、异常和付费墙结果检索 Telegram MiniApp 的真实使用过程。重点解决两类问题：

- 还原角色卡聊天中的实际体验，包括交互、流式文字节奏、重生成、网络等待/失败和 Markdown 呈现，而不是仅从数据库查看模型原始文本；
- 为当前未定位的支付 P0 提供可关联的操作证据，覆盖用户触发余额不足、进入充值、发起外部支付、回流或放弃的完整 MiniApp 内路径。

## 已确认事实与约束

- 仓库尚未集成 PostHog；前端已启用 Sentry Session Replay（启用环境下当前采样率为 100%）。需求方明确保留 Sentry 录制，并接受与 PostHog 双录制带来的成本和数据暴露面；PostHog 是本期产品检索与付费墙证据通道，Sentry Replay 继续承担既有排障回放。
- 聊天页面为 `/chat/[characterId]`，会话 ID 位于 `session` query；聊天的发送、流式处理和失败分流集中在既有 hooks/SSE client。
- 余额不足会统一跳转 `/profile/recharge`；充值页支持余额不足提示、邀请入口、创建订单和外部支付拉起，订单结果页轮询服务端订单状态。
- 外部收银台由 Telegram `openLink` 打开，PostHog 的 MiniApp 浏览器录制无法获得该页面、Telegram 原生界面、支付 webhook 或支付 cron 的画面。
- 当前前端规范已于 2026-09-15 增加受控例外：Session Replay 画面允许完整聊天正文（PostHog 与现有 Sentry Replay）；事件、日志和错误上报仍不得包含消息正文。仍不得记录支付密码、支付账号、验证码、完整 initData、支付 URL/参数、密钥或服务端凭据。书面记录见 `research/t1-decision-record.md`。
- Session Replay 数据按当前 PostHog 套餐上限保留并到期自动删除。**当前为 Free 套餐，最长 30 天**；不得把 60 天写成当前能力。PostHog 云区域为 US Cloud。T7 核验 30 天开关与套餐截图。
- 聊天无操作超时为 15 分钟。`user_cohort`（新/老用户）本期跳过，不进入检索标签。

## 范围内需求

### R1：聊天会话自动录制

- 所有用户进入角色卡聊天页时开始一段新的回放；正常离开聊天页、退出 MiniApp 或达到 15 分钟无操作超时后结束。下一次进入任意角色卡聊天页必须创建新段，不与历史段合并。
- 若用户由余额不足从聊天页进入充值，该逻辑回放上下文必须覆盖充值、订单结果与邀请页，直到返回聊天、支付流程结束、退出 MiniApp 或超时；不得因内部路由跳转切断付费墙后的证据。外部支付可能令 Telegram 新建 WebView，因此一个逻辑上下文可关联多个 PostHog recording，不承诺物理上只有一段录像。
- 回放应覆盖页面滚动、点击、输入、长按、发送、编辑、重生成、加载、网络等待、卡顿和错误提示。
- 回放必须呈现流式文字的增量显示及时序，以及用户实际看到的换行、加粗和 Markdown 渲染。
- 聊天用户输入与模型回复正文均允许出现在回放画面中（2026-09-15 已批准）；不将这些正文复制到事件属性、URL、应用日志或错误上报。

### R2：付费墙与支付路径证据

- 余额不足拦截触发后，持续记录用户在 MiniApp 内的余额不足提示、关闭/停留、邀请入口、进入充值、套餐与支付方式选择、创建订单、外部支付拉起、订单等待、结果、回流和返回聊天后的动作。
- 无论用户最终付款成功、失败、超时、取消或直接离开，均记录对应的 MiniApp 内路径与最后操作时间。
- 外部收银台不作为画面回放的验收对象。系统必须以关联事件保留订单创建、尝试打开外部支付、回流/未回流、服务端订单终态、结算来源和阶段耗时，以定位盲区所在阶段。即使用户不回到 MiniApp，支付结算后的服务端终态也必须按订单 ID关联。
- 付费墙后的用户选择与最终支付结果必须分离：`invite` 仅表示用户选择邀请；`payment_completed`/`payment_failed`以服务端订单终态为准；`abandoned` 仅表示约定观察窗口内离开且无继续/终态事件；无法判定时为 `unknown`。不得以页面卸载或 pending 订单推断支付失败。

### R3：业务上下文与检索

- 每段回放附带稳定的 Telegram 用户 ID、角色卡 ID、聊天会话 ID、开始/结束时间、选中的模型标识，以及当前可得的用户标签（付费状态、累计对话轮数）。新/老用户分群（`user_cohort`）本期不做。
- 必须记录并可按关键事件筛选：发送消息、开始/完成/失败流式回复、重生成、余额不足、邀请入口、创建订单、打开外部支付、订单回流和订单终态。
- PostHog 中应能按用户 ID、角色卡 ID、时间范围、用户标签、异常（网络失败、reply-stalled、重生成超过 2 次、错误提示）和付费墙结果定位到回放或关联事件。当前没有“编辑消息”或自动重试产品能力，本期不新增它们。
- 回放使用 PostHog 原生 0.5x/1x/2x、暂停和逐帧能力；显式事件必须构成可跳转的关键时间线。

### R4：安全、隐私与访问控制

- 录制和事件属性不得包含完整 Telegram initData、支付密码/账号/验证码、支付 URL/支付参数、服务端错误正文、token、secret 或其他运行时凭据。
- 对支付相关控件和敏感输入使用可验证的录制屏蔽策略；不得依赖字段命名或 PostHog 默认设置推断其安全。
- 完整聊天正文只允许出现在经批准的回放画面，访问限于获授权的产品/工程人员；必须具有最小权限、访问审计责任人和到期删除责任人。
- PostHog 不替代订单、余额和支付结算的事实来源；支付是否成功仍以服务端订单状态为准。

## 明确不做

- 不录制 Telegram 原生 UI、外部收银台画面、第三方支付表单、支付 webhook、支付 cron 或外部网络环境本身。
- 不引入对 `miniapp_analytics` 的运行时依赖，不把 PostHog 作为数据库分析管道。
- 不新增支付渠道、不改变订单结算逻辑、不修改聊天/支付既有 UX、文案或业务规则。
- 不新增消息编辑、自动重试、通用事件框架、跨业务状态机或持久化分析数据库。
- 不将完整聊天正文、支付地址或鉴权材料写入自定义事件属性、前端日志、Sentry 或后端 Pino 日志。
- 不关闭、降采样、替换或改造现有 Sentry Session Replay；本期也不用 Sentry Replay 替代 PostHog 检索。
- 本期不做精细化采样实验、运营端自建回放列表/播放器或替代 PostHog 原生检索体验。

## 验收标准

- [ ] 在 PostHog 中可按指定 Telegram 用户 ID找到其聊天回放，并可看到关联的角色卡 ID、聊天会话 ID、模型标识和时间；PostHog 项目级采样与手动 recording 对该范围均为 100%。
- [ ] 可按角色卡 ID和时间范围定位至少 10 个不同用户的聊天回放；回放可显示滚动、交互、逐字流式输出、重生成、网络等待/失败和实际 Markdown 呈现。
- [ ] 发送消息、开始回复、回复完成/失败、重生成、触发余额不足、邀请、创建订单、外部支付拉起、回流和订单终态均在回放时间线中可定位。
- [ ] 已知支付失败订单可以关联到其 MiniApp 内付费墙、套餐/支付选择、订单创建、外部拉起、返回或未返回、服务端失败状态及阶段耗时；即使未回到 MiniApp也能按订单 ID得到后端终态。验收不要求外部收银台画面。
- [ ] 可筛选“触发付费墙后选择支付但未成功”“选择邀请”“未邀请未支付即离开”的会话；`abandoned` 使用记录的观察窗口定义，且不把未知、未结算、仅离开页面或可重开 expired 订单误标为支付失败。
- [ ] 回放和事件中无法检索到完整 initData、支付 URL/参数、支付密码/账号/验证码、token、secret 或服务端敏感错误正文；屏蔽策略有可重复验证记录。
- [ ] 经批准后，完整聊天正文只在有权限的回放内可见；PostHog 数据的实际保留期为当前套餐上限（**Free：30 天**）并有到期删除证据。不得用 60 天描述当前项目。
- [ ] PostHog 不可用、初始化失败、事件发送失败或录制被浏览器阻止时，聊天、充值、支付回跳和订单结算保持可用；系统仅安全地降级为无回放/无分析事件。

## 上线前置条件与停止条件

- 隐私负责人已书面批准“完整聊天正文进入第三方回放”的规范例外，覆盖 PostHog 与既有 Sentry Session Replay。PostHog 区域为 US Cloud；访问限产品与工程；审计/删除责任人与隐私责任人同一人；保留策略为当前套餐上限（**Free：30 天到期自动删除**）。项目级 DPA、30 天保留开关与 100% 采样的互证在 T7 完成后方可生产启用。Sentry Replay 维持现有启用策略，不作为本期改造对象。
- `user_cohort` 本期跳过，不进入 shared 契约与后续实现。
- PostHog 项目 token 与环境配置仅以公开浏览器配置形式注入；任何服务端 secret 不得进入前端。
- 在 test 环境完成 Telegram WebView、常规移动浏览器、支付跳转/回流、失败订单和敏感字段屏蔽验证后，才能发布生产。
- 若无法满足聊天正文例外审批、当前套餐上限内的到期删除（Free 为 30 天）、敏感字段屏蔽或外部支付事件关联中的任一项，停止生产上线；不得通过扩大录制范围、降低脱敏要求，或把 60 天写成已具备能力来规避。
