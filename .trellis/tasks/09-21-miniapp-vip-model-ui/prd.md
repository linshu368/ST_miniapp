# MiniApp VIP 功能构建与模型显示 UI 更新

## Goal

在 MiniApp 测试环境交付一套可审计、可恢复且可由运营安全调节的 VIP 时长权益：用户可购买或续费周卡/月卡，获得签到加成、标准/旗舰文本模型及高级图片使用资格、三档文本模型折扣；同时明确充值钱包与专项钱包用途，提供语音和初级图片的全局免费体验，把模型切换入口移到聊天页顶部，并在 Admin 新增“VIP策略”页集中管理已确认的 VIP 商品与权益参数。

支付、权限、价格、钱包分配、免费次数与退款均以后端和数据库为最终真相。测试环境验收通过后，必须由产品负责人明确确认才可进入 Production。

## Requirements

### 1. VIP 商品与有效期

- 周卡默认人民币 13.99 元、有效期 7 天、不赠送星尘；月卡默认人民币 28.88 元、有效期 31 天、每次成功购买赠送 3000 专项星尘。价格、有效天数和月卡赠送专项星尘改由 Admin“VIP策略”发布配置，以上数值作为首次迁移时的兼容默认值。
- 周卡/月卡标题、说明和角标由同一份 VIP 商品配置管理；运营修改只影响发布后的新展示与新订单，不得重算历史订单、缩短已履约会员有效期或追回已发放专项星尘。
- 有效期从支付成功并完成履约的时刻开始计算；会员有效以 `valid_until > 当前时间` 为准。
- 有效期内续费从当前 `valid_until` 顺延对应天数；已过期或从未开通时从本次支付结算时间起算。
- 并发或重复支付确认只能履约一次；两笔不同且真实成功的订单均应串行顺延，不得覆盖剩余时长。
- 本期不做自动续费、会员等级、成长体系、专属客服或专属角色卡。

### 2. VIP 权益

- 有效期内，每日签到除基础专项星尘外获得 VIP 加成。Admin 可选择“与当次基础奖励相同”或“独立固定数值”两种方式；首次迁移默认保持“基础奖励 × 1”，即当前基础 60 时合计 120。同一次签到动作原子到账，额外奖励每天只发一次，过期后不补发。
- 有效期内解锁标准、旗舰文本模型和高级图片的使用资格；权益只解锁使用资格，不免除正常扣费。
- 有效期内轻量、标准、旗舰三档文本模型按 Admin“VIP策略”发布的折扣率计费，首次迁移默认 95%，按四舍五入得到整数星尘；免费轮次优先，免费时不叠加折扣。每次生成必须固化本轮折扣快照，后续改价不得重算已受理请求或历史消费。
- VIP 文本折扣不适用于初级图片、高级图片、语音或 VIP 商品本身；标准与旗舰文本模型原价不在本任务中调整。
- VIP 过期时，签到加成、文本折扣、标准/旗舰文本模型和高级图片权限同时失效；若当前选择的是标准或旗舰模型，下一轮回复自动使用轻量模型且不阻断对话。历史消费记录不得重算。

### 3. 双钱包与支付范围

- 现有 `main_credits` 定义为充值钱包，现有 `bonus_credits` 定义为专项钱包；VIP 不是第三个钱包。
- 所有现金充值所得进入充值钱包；签到、邀请、运营赠送、VIP 签到加成、月卡 3000 等非充值奖励进入专项钱包。
- 轻量文本可同时使用两个钱包，并固定优先扣充值钱包，充值钱包不足时由专项钱包补足。
- 标准/旗舰文本、高级图片只允许有效 VIP 使用，并且只能从充值钱包扣费。
- 初级图片和语音不要求 VIP，但付费轮次只能从充值钱包扣费。
- 一笔消费的权限校验、价格快照、余额校验、双钱包分配、扣款与业务成功状态必须原子收口；余额不足不得部分扣款。
- 重复结算不得重复扣款。生成失败不扣款；已经扣款后需要退款时，必须按原始 `main_delta` / `bonus_delta` 精确原路退回，重复退款不重复入账。
- 我的页总余额继续显示两钱包合计，并明确显示“内含专项星尘 XXX”；余额不足提示需说明当前功能要求的可用钱包，不得用总余额误导用户。
- 到账与消费明细需能区分充值/专项来源、组合扣款拆分、当次 VIP 折扣率和原路退款。

### 4. 支付与页面入口

- 沿用现有微信支付创建订单、异步回调、同步回跳、前端查单和定时对账四条路径；VIP 履约必须收敛到同一幂等支付结算出口。
- 支付订单必须固化商品类型、商品 ID、金额、时长和赠送额度，结算不得读取已变化的前端状态重新定价。
- 我的页星尘卡内新增更醒目的金色 VIP 胶囊入口，与“星尘充值”并排。未开通为常规态；已开通显示“VIP · 剩 N 天”；过期回到未开通态。
- VIP 入口首次显示当前文本折扣角标（默认“95折”），用户首次点击后永久消失，过期或重装不得再次出现。
- 新增 VIP 详情页：静态可替换权益图、当前折扣说明、四条权益、周卡/月卡互斥选择、金额联动支付按钮。
- 充值页在现有星尘套餐后增加 VIP 区；星尘套餐与 VIP 档位全页互斥单选，已开通用户使用“续费”口径。
- Admin 新增一级业务视图/tab“VIP策略”，集中展示和发布 VIP 购买开关、到期提醒开关、周卡/月卡商品、文本折扣、签到加成和媒体免费次数。复用现有草稿、发布、版本与回滚链路，不建立第二套配置后台。

### 5. 模型权限、定价与切换 UI

- 聊天页角色名正下方居中展示当前模型金色描边胶囊，点击展开复用现有模型分组面板。
- 工具箱“对话设置”移除模型选择入口，语音、图片等其他工具项保留。
- 非 VIP 仍能看见标准与旗舰档位，但显示锁图标和 VIP 标识；点击展示说明、两档当前价格与“前往 VIP”入口，不直接选择。
- VIP 面板展示每档文本原价、`原价 × 当前 VIP 折扣率` 的计算值、最终四舍五入实扣整数，以及“VIP 折扣已生效 · 剩余 N 天”；展示价、预校验价与最终结算价必须使用同一已发布配置和价格快照。
- 输出过程中切换模型不影响当前回复；当前回复继续使用启动时的模型和价格快照，下一条回复使用新选择，并给出明确轻提示。
- 模型选择与每次生成均须由后端重新校验 VIP、价格和可用钱包，不能信任前端锁定态。

### 6. 语音与图片免费体验

- 功能上线后，每个账号的语音与初级图片成功生成免费次数分别由 Admin“VIP策略”配置，首次迁移默认均为 3；两类额度独立且对存量用户同样生效。
- 免费轮次显示“免费体验 第 N/上限 次 · 本次不消耗星尘”；额度耗尽后显示原价并按现有成功后结算链路扣费。调低上限不得删除历史消费事实；已使用次数达到或超过新上限时不再分配免费次数，调高后可继续获得新增序号。
- 失败、明确未成功或未形成可用产物的调用不计免费次数且不扣款；清缓存、重装、重复请求或并发请求不得刷新或超领额度。
- 高级图片不参与免费额度，始终要求有效 VIP 且只可使用充值钱包。
- 初级/高级图片的具体模型和价格仍以受控运行时配置为准；高级图片配置未完整或不可验证时不得开放入口。

### 7. 到期提醒与消息中心

- 只通过消息中心“官方”区向对应用户发送站内提醒，不发送短信、邮件、系统推送，也不新增 App 内到期弹窗。
- 当前有效期剩余 3 天时发送“VIP 即将到期”；到期当天发送“VIP 今日到期”。同一会员周期、同一提醒类型只发送一次，同一用户同一天不得重复。
- 续费改变有效期后，旧周期尚未发送的提醒必须取消；已经发送的历史消息保留。
- 消息列表保留未读标记，只有用户点击具体条目时才标记该条已读，不能因打开列表批量读掉。
- 新增消息详情页，展示标题、发送时间、当前会员状态/剩余有效期、正文和“立即续费”按钮；按钮跳转 VIP 详情页。

### 8. Admin「VIP策略」配置范围

- 必须纳管：`vip_purchase_enabled`、`vip_reminders_enabled`、周卡/月卡价格与有效天数、月卡赠送专项星尘、VIP 文本折扣率、周卡/月卡标题/说明/角标、VIP 签到加成方式及固定加成值、语音与 basic 图片各自的免费次数。
- 首次发布必须等价于当前已审核规则：购买/提醒开关保持 false；周卡 13.99 元/7 天/0 赠送；月卡 28.88 元/31 天/3000 专项星尘；文本折扣率 95%；签到加成模式为“与基础奖励相同”；语音/basic 图片免费次数均为 3。
- 到期提醒仍固定为“剩余 3 天”和“到期当天”，提醒文案与 `Asia/Shanghai` 时区本期不进入 Admin。
- 语音价格、语音计费开关与语音提示文案，以及高级图片完整配置，待产品另行确认后再决定是否进入 Admin；本次“VIP策略”不得顺带纳入。
- 配置发布必须有 Shared 与数据库双重校验。价格使用正整数分，有效天数使用正整数，赠送和固定签到加成为非负整数，折扣率必须大于 0 且不超过 1；语音与 basic 图片免费次数均为 `0..20` 的整数，默认 3，配置为 0 表示关闭该功能的免费体验。
- Admin 只提交受控字段，不接受任意钱包策略、权益类型、SQL、provider URL、token 或密钥。VIP 有效判断、钱包分配、幂等、退款和提醒去重仍是不可运营修改的系统不变量。

### 9. 兼容、隐私与范围

- 上线前后存量 `main_credits`、`bonus_credits` 数值不搬移、不互换，合计余额必须守恒；历史流水和历史消费记录保持可读。
- 既有星尘充值订单、四路支付确认、轻量模型免费额度、旧通知、语音和初级图片请求需向后兼容。
- 日志与埋点只记录允许的内部 ID、商品/权益类型、结果摘要、耗时、钱包拆分和失败阶段；禁止记录 token、密钥、完整 `initData`、支付 URL、敏感 URL 参数或响应正文。
- 本期不重做消费明细信息架构，不创建第三个钱包，不引入隐藏的部分扣款或客户端记账。

## Acceptance Criteria

- [ ] 非 VIP 从我的页首次看到当前折扣角标，点击后跨重装不再出现；使用首次默认配置完成月卡支付后显示约 31 天有效期，3000 星尘仅进入专项钱包。
- [ ] 周卡/月卡价格、有效期、续费顺延和并发双订单行为正确；四种支付确认来源重复触发时，每个订单只履约一次。
- [ ] Admin“VIP策略”存在且只包含已确认配置；草稿、发布、版本、回滚和环境隔离复用现有 Admin 配置链路，非法值无法发布。
- [ ] 首次发布保持当前默认行为；运营修改商品、折扣、签到加成或免费次数后，仅影响规定的后续请求/订单，历史订单、会员期限、消费与免费额度事实不被重算。
- [ ] 普通签到使用基础配置；有效 VIP 同一次签到按已发布加成模式原子到账，响应与 UI 分行展示，重复/并发签到不重复发放。
- [ ] 非 VIP 的标准/旗舰模型和高级图片后端均拒绝使用并提供去 VIP 路径；VIP 可用但按规则正常收费；到期后下一轮自动回落轻量。
- [ ] VIP 三档文本折扣统一按运行时原价 × 已发布折扣率四舍五入到整数；免费优先；面板、余额预检、账本和明细金额一致，改价不影响已受理快照。
- [ ] 仅专项余额、仅充值余额、两钱包均有三组账号均通过矩阵验证：轻量主钱包优先再专项补足；其余付费媒体只扣充值钱包；不发生部分扣款。
- [ ] 同一扣款请求重试不重复扣费；失败不扣费；已扣后退款按原扣款拆分分别恢复两钱包，重复退款只返回已退款结果。
- [ ] 语音和初级图片分别按已发布上限提供成功免费次数；超过上限后只扣充值钱包；失败不计数，两类互不影响；调高/调低、并发和重放均不能超领；高级图片无免费额度。
- [ ] 模型胶囊位于角色名下方，工具箱不再含模型入口；输出中切换不影响当前回复，下一轮使用新模型。
- [ ] 充值页星尘/VIP 档位互斥，支付按钮金额正确；VIP 页面、续费文案、权益图位和已开通状态符合需求。
- [ ] 剩余 3 天与到期当天提醒各仅一条并位于官方区；续费后不发送旧周期后续提醒；点击单条才已读，详情页状态和续费跳转正确。
- [ ] 存量双钱包数值与合计在 migration 前后完全一致，历史订单、流水、消费明细与旧客户端兼容。
- [ ] 在 test 按失败、重试、并发、超时、回调乱序和回滚场景完成验证；未获产品上线确认前不启用 Production。
