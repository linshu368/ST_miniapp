# MiniApp 语音前 3 次免费接入

## Goal

在父任务提供的统一免费额度和钱包结算底座上，把语音能力改为每账号前 3 次成功生成免费；失败不计次，第 4 次起按现有语音原价只从充值钱包扣费，同时保持现有可播放产物、幂等和失败状态语义。

## Requirements

### 范围与依赖

- 父任务：`09-21-miniapp-vip-model-ui`。
- 本子任务可在父任务 T2 完成并通过 test 数据库验证后开始，不依赖父任务 T3 或 T4。
- 父任务必须先提供稳定的免费额度表/预留原语、`main_only` 钱包扣款原语、Shared 公共免费状态形状和功能开关；接口版本或 migration 尚未稳定时不得自行复制一套实现。
- 本任务只接入语音模块及其 UI/API，不修改图片、VIP 商品、LLM 折扣或通用钱包规则。

### 免费与计费规则

- 功能启用后，所有存量和新增账号均从语音免费成功次数 0 开始；不回溯历史语音调用。
- 每账号前 3 次形成可播放语音并成功收口的调用免费，两类重试必须归属于同一个稳定 audio/reference ID。
- 上游失败、超时、取消、Storage 失败、无可播放 URL及其他未成功终态不消费免费次数、不扣星尘。
- 第 4 次及以后沿用现有语音原价，但只能从充值钱包 `main_credits` 扣款；专项钱包余额不得用于语音。
- 免费和付费都必须保持“成功结算与 audio ready 原子收口”；余额不足不得展示成功音频，也不得部分扣款。
- 重放同一请求不得重复消费免费次数或重复扣款。已扣后补偿必须调用父任务提供的原路幂等退款，不手工改余额。

### 预留与并发

- 在调用语音上游前，以 audio attempt ID预留一个语音免费序号；同一账号并发请求最多只能成功消费 1、2、3 三个序号。
- 调用期间按父任务契约维护 reservation；明确失败必须释放。过期并被其他请求占用后的迟到成功不得静默转为付费。
- 免费额度不可由清缓存、重装、重复点击、并发请求或 worker 重试刷新。

### API 与 UI

- 语音配置/确认数据返回服务端权威的 limit、used、remaining、next ordinal 及当前展示价格。
- 免费范围内显示“免费体验 第 N/3 次 · 本次不消耗星尘”；用尽后显示现有原价。
- UI 展示只作提示；最终免费次数、钱包和价格由后端结算裁决。
- 保留现有语音文案、长度限制、上游超时、Storage 和播放交互，不做语音体验整体重构。

### 可观测性与安全

- pino 只记录内部 user/audio/reference ID、ordinal、reservation/settlement 状态、扣款摘要和耗时，原始错误使用 `{ err }`。
- 禁止记录语音文本正文、音频内容、签名 URL、token、完整响应或敏感参数。

## Acceptance Criteria

- [ ] 同一账号第 1、2、3 次成功生成语音均显示正确序号、形成可播放产物且不扣星尘；第 4 次按现有原价只扣充值钱包。
- [ ] 只有专项余额时，第 4 次语音在调用上游前被余额预检拦截；不发生专项扣款或部分扣款。
- [ ] 上游、超时、Storage、ready 收口失败均不消费次数、不扣款；重试成功后仍使用应有序号。
- [ ] 20 个并发/重复请求无法消费超过 3 个免费成功名额；同一 audio/reference ID重放只产生一个结果。
- [ ] reservation 过期、续租失败和迟到成功不会产生意外付费或双重成功。
- [ ] 功能开关关闭时保持旧语音行为；开启后旧客户端仍可解析响应。
- [ ] 相关 Backend/Shared/Frontend 测试、typecheck、Frontend build 和 test 数据库事务验证通过。
