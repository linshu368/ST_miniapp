## 需求

### R1 原文与展示

处理新生成的 AI 文本回复和重生成的新 revision。保存模型原文，后续 prompt、计费、语音、图片继续使用原始内容；展示 HTML/按钮/CSS 不得写回正文。用户消息不应用规则；没有规则版本的旧消息维持原有 Markdown 展示。

### R2 有序且独立的规则

每条规则有稳定 ID、名称、说明、正则、flags、模板、CSS、启用状态、备注。列表顺序即执行顺序；选中仅表示编辑，预览应用全部启用规则。先命中的区间生成组件后不再由后续规则处理；未命中保留原文，空匹配、异常或超时跳过该规则。备注不进入提示词。

### R3 配置自由与安全

允许新增自定义正则、组合白名单 HTML 结构、捕获组替换、隔离 CSS。支持文字、段落、列表、表格、卡片及常用颜色、字号、背景、边框、间距、布局、响应式样式；提供模板示例、字段帮助、捕获组预览和明确错误。

禁止脚本、事件属性、外部资源、任意跳转、表单提交、越界样式及覆盖 APP 操作区域。非法配置指出规则/字段/位置并阻止发布；客户端仍独立防御不可信内容。交互只能使用预置的折叠/展开和发送动作。

### R4 预置交互

提供对白、`[highlight]`、`[status]`、`[choice]` 四类起始模板；原型默认启停/flags 不直接成为线上配置。状态卡默认折叠，运营可改为展开，用户操作不被后续增量重置。

选项纯文本经正常聊天流程发送。仅当前会话最新一条完整模型回复且会话空闲可点击；生成中、旧消息、空选项、超长选项禁用。同回复任一选项提交后全部禁用，双击不能重复发送。失败沿用现有输入恢复/错误提示，不自动重发；已提交按钮不自动重新启用。重载后按服务端末尾消息状态重建资格，网络结果未知须先回读。

### R5 Admin 工作台与一致预览

使用原型三栏信息结构：列表 → 编辑器 → 原文/预览，并适配窄屏。支持搜索、状态筛选、新增、复制、删除确认、上下移、启停和解析/样式/说明页签；新建/复制默认停用。

编辑立即更新草稿预览，显示全部规则匹配数、首处匹配/捕获组、错误和耗时。提供完整/普通/残缺/选项示例及模拟流式开始/暂停/重置；支持移动宽度、主题和预览用户名。两端使用同一处理与渲染实现。Admin 选项为明确标注的本地模拟，显示发送文本，不调用模型或计费。

#### R5 补充：Admin 页面复现 Demo（2026-09-29）

- 复现 Demo 的视觉与交互：浅灰背景、白色连体三栏、紫色强调/选中态、紧凑标题与操作区、统一边框/圆角/间距；不以现有分散 Card 布局替代。页面仍处于现有 Admin 外壳内。
- 左栏复现规则数量、新增按钮、搜索、状态筛选、规则卡片（顺序、名称、说明、启停、样例匹配数）、空态和“按顺序执行”提示。
- 中栏复现顶部上移/下移/复制/删除图标工具栏、名称和启用开关、辅助编号、解析规则/展示样式/协议备注页签；flags 用带含义的勾选项，当前规则首处匹配与捕获组卡片紧邻解析编辑，错误就地可见。
- 右栏复现实时预览标题、全部启用规则提示、原文输入、示例下拉、字符数、自适应/375px 宽度切换、主要效果区域和底部处理状态/耗时；当前规则统计进入中栏，全部规则统计进入左栏，避免长诊断列表把效果挤到页面下方。
- 新增弹窗复现模板卡片选择、名称填写、取消/创建；使用现有对白/高亮/状态/选项及自定义起点，新建/复制仍默认停用。删除保留确认，排序边界按钮禁用。Demo 的四格结构可因保留对白起点扩展为五个选项。
- 响应式复现宽屏三栏、中等宽度左栏加右侧上下编辑/预览、窄屏横向规则卡片加纵向编辑/预览。断点按 Admin 主内容可用宽度适配，避免外壳侧栏导致挤压或页面横向溢出。
- 必要适配仅包括：Admin 身份/导航/环境；真实草稿、发布、历史与请求恢复；现有 System Instructions 独立入口；共用安全 renderer；现有流式、主题、用户名工具；契约支持的 flags 和稳定规则 ID。其位置与 Demo 风格一致，详细设计见 design.md 第 10 节。
- Demo 的本地存储、示例默认启停/顺序/flags、iframe 模拟、额外模拟回复和指令示例不成为线上配置或真实运行链路；展示正文使用真实 renderer，因此不能以 Demo 模拟 HTML 的像素效果替代 APP 一致性要求。

### R6 草稿、发布与版本

保存草稿不影响线上，显式发布才切换正式配置。新开轮按请求时读到的已发布版本绑定，整轮固定；历史消息和生成中的旧轮次不跟随发布变化。重生成的新 revision 使用当次新开轮版本。

发布历史保留差异、操作人/时间和回滚入口；回滚创建新版本，不修改旧快照。消息引用版本不得删除。测试/生产隔离；viewer 只读，owner/operator 需有当前环境权限；并发冲突不能静默覆盖，重复请求和结果未知有明确恢复方式。

### R7 流式与稳定性

未闭合标记暂按原始文本安全展示，完整命中后生成组件；不针对任意正则猜测未完成标记。流式选项不可点击。解析有容量/时间上限且可中止，不阻塞浏览器/API 主线程。规则、配置读取或渲染失败保留可读正文；未知协议或缺失历史版本降级，不能用当前版本冒充。

### R8 独立指令与运营便利

链接已有 System Instructions 配置入口，规则和指令独立保存/发布。备注和测试文本不自动进入指令。提供语法帮助与模板示例；第一版不新增配置导入导出、模型调试调用或提示词自动改写。

## 范围及规划默认

R1–R8 全部在范围内。第一版不处理人工维护的角色开场白、用户输入、客服/通知/CS 回复，不批量改写旧消息，不新增生成/计费渠道，不允许任意脚本/外部资源。Admin 回复富文本规则工作台按 R5 补充复现 Demo，Admin 外壳及 APP 正文主题保持既有职责。未配置规则时保持原有展示，不预设强制上线样式。

## 验收标准

- AC1（R1）：原文和下一轮 prompt 无 HTML/组件污染，计费/语音/图片既有验证通过。
- AC2（R2）：启停、顺序、重叠、非 global、跨行、捕获组、无匹配均有确定结果，组件不重复命中。
- AC3（R3）：能创建四类之外的安全结构；脚本、危险属性/CSS、空匹配和超限明确拒绝或降级。
- AC4（R4）：卡片键盘/触屏可用、状态不被增量重置；选项正确发送一次；旧消息、生成中、双击、余额不足、离线和结果未知行为可复现。
- AC5（R5）：同原文/规则/主题/宽度/用户名/交互状态，两端展示和交互一致；覆盖逐片输入和终态。
- AC6（R6）：草稿无线上影响，新旧轮次不串版本，重生成使用当次版本；回滚形成新快照，旧版本仍可读取。
- AC7（R6）：匿名/viewer/跨环境写入拒绝；并发编辑、发布和重复提交正确处理；快照、当前配置、发布记录、审计四项原子提交。
- AC8（R7）：灾难性正则、长文本、慢规则、Worker 失败、缺失版本和渲染错误不冻结、不丢正文、不影响生成/计费。
- AC9（R8）：指令单独发布不改规则/原文；Admin 模拟清楚标注，不产生模型请求或扣费。
- AC10：shared/受影响包测试、全部消费者 typecheck、适用 lint/迁移静态检查及 Frontend/Admin/CS build 通过；TEST 联调与 Telegram WebView 验收另记实证，未执行检查说明原因。
- AC11（R5 补充）：工作台逐项对照 Demo 的布局、视觉和交互；列出所有必要差异及原因。桌面、平板和窄屏可完成选规则→编辑→预览→保存操作；效果区不被全量诊断挤走，弹窗/图标按钮键盘可用、关闭后焦点恢复。原型本地文件的浏览器查看已被安全策略拒绝，本轮只有源码调研，不声称已完成像素或视觉验收，也不得绕过该拒绝。
- AC12（R5/R6/R8）：重排后仍区分未保存修改/已保存草稿/正式版本；错误和冲突保留输入，未知写入结果仍可查询；viewer 与环境隔离不变。示例切换/预览/模拟不发起模型或业务写请求；既有规则 ID、顺序、flags、模板、CSS 和启停不因页面升级自动改写，System Instructions 独立保存发布。

- 发布或回滚成功后应立即更新当前实例；其他实例通过短周期后台刷新最终收敛。允许短暂沿用上一不可变正式版本，不允许用最大版本、未发布草稿或客户端编译冒充当前版本。
