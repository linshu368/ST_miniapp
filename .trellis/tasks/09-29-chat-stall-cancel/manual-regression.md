# 发布前人工回归（尚未执行）

目标为 TEST/Preview，同一部署版本 frontend+backend；不以单测代替 Telegram/真实钱包结果。Production 尚未授权。不要在日志/报告记录用户正文、initData、token。

1. 首字等待：发送一条测试消息，8 秒未增长出现等待提示。点击取消（上游 HTTP 响应头尚未到也需覆盖），服务端确认后保留用户消息，失败回复下显示“重新生成”。点击后同一 turn 新 revision，用户消息不重复；成功后可继续发送。
2. 部分正文：在回复到一半时取消，保留已有正文、显示取消结果与“重新生成”。核对取消轮 deduction=0，免费额度 used_rounds 无增量，reservation 最终释放。
3. 恢复：断网后重新连接/页面刷新，服务端 streaming 仍显示取消按钮；生成正常完成恢复发送。制造超过 120 秒的残留 streaming 后进入会话，恢复终态并可重新生成。
4. 完成竞争：在最后 token/终止帧附近取消；取消先赢不得扣费，完成先赢保留完整消息和原有正常扣费，不能宣传未扣费；重复取消/再次点击无重复账。
5. 请求隔离：取消旧回复后立即生成或发送；快速切换会话/角色；旧 SSE delta/done/error/finally 不得影响新会话、新回复、额度提示或输入草稿。
6. 失败恢复：上游空流、流缺 done、网络挂起、prepare/context/setHistory 异常均终态收口；取消请求失败须显示可重试提示而不能假装成功。模拟详情刷新挂起不能无限显示生成中。
7. 权限与绑定：非本人 session 返回失败；取消错误 assistant ID、老 revision ID 不影响当前回复；重复请求幂等返回该条实际状态。两设备同会话同时发送相同内容、同预期轮次，取消输掉开轮竞争的请求不能取消胜出的另一设备回复；上游请求不含取消关联 request_id。
8. 设备：Telegram WebView 与移动浏览器、320px 窄屏、键盘弹出；取消/重新生成点击区域可用，ARIA 标签和文案符合状态；已成功回复的“换一个回复”、图片/语音入口维持现有行为。
