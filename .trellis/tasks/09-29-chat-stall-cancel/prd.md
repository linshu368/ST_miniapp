# 文字回复取消与恢复

用户已在 2026-09-29 明确批准上一轮方案并要求实施，从最新 main 创建 hotfix。补充：取消后失败回复下方显示“重新生成”，复用原用户输入。

## 需求与验收

- 8 秒无正文增长继续显示等待提示，等待期间可取消；重新进入后仅有服务端 streaming 也可取消。
- 取消必须服务端收口对应回复、释放会话；取消成功未完整回复不扣费、不消费免费额度。
- 取消与自然完成竞争以服务端原子状态转换为准；已经成功的不逆转。
- 首字前、正文中断、无 done、连接挂起、落库异常、旧 streaming 必须有有限超时/恢复路径。
- 取消后原用户消息保留，对最新失败回复显示“重新生成”；无需重新输入。新发送/重生成不能被旧请求回调覆盖。
- 非本用户会话/错误消息 ID、重复取消、迟到取消不得取消另一条回复；同一用户两个设备同时请求相同预期轮次，取消仅作用于本次被接受的请求。
- 不改无关 UI、媒体、价格。无提交/push/部署/实库写入授权。

## 当前证据

use-conversation-turn.ts 的 abort 只断开本地，serverBusy 禁用发送；真正上游超时 120 秒，开轮后组 prompt 失败未统一收口。服务端已有 startRegeneration 复用 user_input、行锁与陈旧回收。取消接口尚不存在。用户故障日志未核验。
