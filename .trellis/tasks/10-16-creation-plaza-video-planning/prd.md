# 创作广场扩展视频创作（仅规划）

## 目标与范围

在保留图片广场全部现有能力的前提下，增加视频发现、详情播放与视频创作。优先保证列表、工作室、详情首开速度和现有系统视觉一致性。

本次交付仅限需求、技术设计、执行计划和验收清单；不修改产品代码、不创建或执行 SQL migration、不发布配置、不调用付费生成、不将任务启动为 in_progress。所有方案均待审核，模型名称不是供应商能力的证明。

## 功能需求

1. 广场有可点击的“全部 / 图片 / 视频”筛选；全部展示图片、视频混排，统一按点赞与分享时间排序，不分开分页后拼接。
2. “全部风格”弹窗支持分类多选，默认全选，取消选择后只保留其他已选分类（OR 匹配，不全局排除命中取消分类的作品）；展示每类作品计数。继续基于中文提示词 `prompt_zh` 字面包含匹配，而不是改成仅匹配作品 tags 数组。
3. Admin 扩展分类配置，同时保留已有标签功能与发布、回滚流程。
4. 创作入口增加“图片 / 视频”选择。图片原有模型、参考图、编辑、报价、生成、历史、用同款、点赞、分享与返利不受破坏。
5. 视频创作每次总共允许上传 0～1 张图片，不支持多图。上传图片按所选模型经验证的能力映射为首帧图、参考图或垫图，显示实际用途、上传进度、替换/移除及模型限制，不提供多图分区、排序或用户自由选择角色。无图时仅允许支持文生视频的模型提交；必须有图的模型明确提示补图或切换模型，不静默补图、丢图或更改用途。
6. 视频模型独立配置，与图片目录具备同等级的名称、说明、启停、默认值、排序、供应商映射、能力及价格配置。六个目标模型：
   - MiniMax H3 Max
   - MiniMax H3 Max R2V
   - Seedance 1.5 Pro
   - Seedance 2.0 R2V Enhanced
   - Wan 3.0 Pro
   - Wan 3.0 Reference
7. 同一会话可交替生成图片与视频，每次提交由对话框当前类型选择确定生成类型，不因切换类型创建新会话。每次生成独立绑定输入与参数快照，历史按统一时间线展示；视频任务与图片任务的处理可以相对独立。
8. 视频列表只展示封面和必要标识；详情由用户点击播放，不自动播放或在列表下载视频。加载、重试、失效、下架状态有清晰反馈。
9. 界面沿用系统字体、色彩、圆角、间距、组件和移动端安全区；原型用于交互参考，不引入独立视觉体系。
10. 视频沿用成功后扣费。服务端调用前按所选模型及参数的权威报价检查可用星尘，余额不足提示充值，不调用供应商；不预扣、不冻结。
11. 图片与视频共用返利规则、返利配置与账户级首次分享资格；已有图片首次分享记录对视频同样有效，不新增视频首次资格。
12. 视频生成供应商已确认为 Venice，参考现有图片创作接入方式；默认开启自动优化提示词、关闭 Venice 系统提示词和 `safe_mode`。这些是产品默认要求，不代表视频端点已验证支持同名参数；不能静默忽略后声称生效。
13. `D:/JobExe/ST/翻译包/civitai_venice_nsfw_videos.xlsx` 是视频初始作品数据源，后续功能完成后须全量导入 Supabase，不仅作原型参考或少量演示。保留原始提示词、中文提示词、来源身份、模型标签、热度和候选垫图信息；视频及封面需可靠存储、可播放。导入不触发生成、扣费、分享返利或消耗账户首次资格。

## 约束与非目标

- 外部契约先于消费者；服务端数据沿用 React Query hooks；配置沿用正式配置发布链；生成与计费编排进入既有 generation 边界。
- 保留旧图片 URL、作品身份、报价与历史数据；不重写历史迁移，不以测试库结构冒充生产实况。
- 不新增消息队列、转码集群、通用媒体插件框架、搜索服务或第二套钱包。
- 首版不承诺视频剪辑、视频上传作为输入、音频上传、批量生成多段视频、自动播放或自适应多码率。
- 本轮不做生产/测试库结构采集；未来迁移要先确认目标，再独立核验。

## 已确认产品决策（2026-10-16 用户补充）

分类采用已选分类 OR 匹配且需要作品计数；视频输入最新确认为总共 0～1 张、按模型能力作为首帧图/参考图/垫图，取代此前多图方案；同一会话按单次提交选择图片或视频；视频调用前余额校验、不足提示充值且不调用、成功后扣费；返利与首次分享资格跨媒体共用。以上不再列为待确认需求。

追加确认：供应商为 Venice；自动优化提示词默认开，Venice 系统提示词与 safe_mode 默认关；上述 Excel 为后续全量 Supabase 导入范围，不构成本轮数据库写入授权。

## 边界细则与待验证项

- 分类边界建议：全选不限制（保留未分类/未译文旧作品），空选返回空；部分选择匹配任一已选分类。搜索仍匹配 prompt 或 prompt_zh，并与分类 AND。
- 计数口径建议：在当前媒体类型、关键词及可见范围内，每类统计匹配作品数，不受分类勾选或当前分页限制；重叠作品可分别计入多类，结果总数按作品去重，不能将分类计数相加当总数。全选总数包含未分类作品。计数只用服务端数据，不按已加载卡片推算。
- 产品输入上限固定为总共 1 张；逐模型验证无图/单图支持、是否必填及单图用途映射，不推断 R2V 支持任意组合。供应商即使支持多图也不开放多图；仅支持至少两图的模式不在本轮开放。
- 成功后扣费不等于资金预留：调用前余额检查通过后，其他消费仍可能导致结算时不足；实现必须覆盖该竞争路径，不能承诺预检消除了全部成本风险。
- 六模型真实 API/价格/能力和实际性能仍待核验；产品决策确认不代表技术方案整体审核或实施授权。
- 本地只读统计为 5,097 条记录，其中 15 条缺少 prompt_zh，901 条包含“可能的垫图列表”。缺失译文需补齐或明确待处理；候选垫图不是已验证的输入角色。媒体可达性、转存/公开使用授权、内容审核、容量与目标环境仍待验证，异常不得静默丢弃或虚报全量完成。

## 验收标准（未来实施）

- [ ] 三个媒体筛选、关键词、分类组合正确；覆盖全选、空选、重叠分类、缺失译文、删除分类与无结果。
- [ ] 混排由服务端完成，分页不按媒体拆开；静态数据下无重复/遗漏，动态点赞下有明确刷新与去重行为。
- [ ] 六个模型能在后台管理；每个启用模型均有供应商文档与 test canary 证据；不可用模型保持关闭并明确标识，不伪造参数或价格。
- [ ] 分类计数覆盖媒体/关键词切换、重叠分类、零匹配、未译文、下架和目录变更；计数加载/失败不阻塞列表，未知计数不冒充 0。
- [ ] 视频 0～1 张上限在 UI、Shared 与服务端一致执行；无图文生视频、单图用途映射与快照正确，第二张/伪造多图请求拒绝；必填图缺失、非法文件、切换不兼容模型、上传失败及替换/移除均可解释，无静默丢图。
- [ ] 同一会话完成图片→视频→图片，刷新/分页后各轮类型与快照不变，切换输入类型不改变在途任务或历史；旧客户端不会收到不能解析的视频对象。
- [ ] 视频受理时和实际供应商提交前余额不足均不调用上游，提示充值并保留输入；检查出错也不调用；余额足够生成成功后才幂等扣费，覆盖最终余额竞争。
- [ ] 视频异步任务断网/离页不取消，重启可恢复；重复提交不重复生成/扣费，结果未知不自动重投。
- [ ] 视频分享、点赞、播放签名均鉴权并校验可见性；重复分享不重复返利；图片先分享、视频先分享、两类并发首次分享均共用账户首次事实及返利规则；私人参考图不因分享而默认公开。
- [ ] 未播放前列表/详情/历史不请求视频正文；点击播放、暂停、拖动、签名过期恢复在 Telegram iOS/Android 与移动浏览器验证。
- [ ] 与实施前基线比较首屏和打开延迟；达到审核后的性能预算，且图片核心场景不回退。
- [ ] 通过 shared 测试、所有消费者 typecheck、受影响包既有测试、适用 lint/build 和单独授权后的 test migration 验证。
- [ ] Venice 默认配置经发布、读取、提交快照和实际请求验证：自动优化开、系统提示词关、safe_mode 关；不支持项明确阻塞/说明，不以未知字段冒充支持，不影响旧图片配置。
- [ ] 功能完成后全量导入 5,097 条来源记录并对账；重复执行不重复作品/对象、不改用户点赞，不产生扣费或返利。缺译文、失效链接、未授权素材和格式不符均有可恢复清单，未解决前不得标记全量交付完成；仅审核且媒体就绪的作品公开。
