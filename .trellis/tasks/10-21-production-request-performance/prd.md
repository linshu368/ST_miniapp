# 大厅首载、进入会话、消息回复与连接治理规划

## 目标

形成可审核的 Markdown 排查及优化对比文档，仅聚焦高影响模块，不立即实施优化。

## 需求与约束

- R1：围绕大厅列表初次加载慢、点击列表进入会话卡顿、发送消息后回复慢三个生产反馈，分别定义用户等待链路，区分源码事实、用户反馈、历史记录和待验证假设。
- R2：覆盖连接池耗尽、锁等待、后台任务竞争与页面持续加载的排查方法。
- R3：给出优化前后对比、优先级、最小改动范围、失败路径、验收及回滚。
- R4：不得削弱鉴权、资源归属、额度预留、计费快照、CAS 和幂等恢复。
- R5：本轮仅改文档，不执行生产写入/配置变更、迁移、压测或 AI 生成；不新增依赖或测试文件。
- R6：生产未知项保持待验证，不能把 TEST、本地网络样本或官方默认参数当生产基线。
- R7：Prisma 连接易满、影响其他请求是核心治理项；覆盖连接层级、资源预算、后台竞争、异常释放和负载回落恢复，不能仅列为后置调参建议。
- R8：首次加载不能用缓存命中冒充提速；进入会话区分新建/继续历史；回复速度覆盖首正文、流中停顿与完整回复，不削弱输出质量与业务正确性。

## 验收标准

- [x] 交付四主线的证据、主要修改范围、排查矩阵、P0/P1/P2、失败路径和回滚；进入会话与连接治理均有独立批次。
- [x] 分开定义大厅首载、进入会话 ready/可交互、后端准备、供应商首正文、浏览器首字、完整回复与连接恢复指标。
- [x] 标明生产取证缺口及后续审核门禁；性能目标不得冒充测量结果。
- [x] 本次补充后的文档引用、秘密/业务行边界、格式、JSON/planning 状态及工作区检查完成。
- [x] 规划保持待审核，不以文档交付代替生产实施验收。
