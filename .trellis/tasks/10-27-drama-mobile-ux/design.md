# 设计与复用

## 参考证据

红果官方 App Store（https://apps.apple.com/cn/app/id6451407032）明确单列沉浸推荐、剧场找剧、一键追剧和选集播放。已查看官方宣传截图及外部历史UI截图；作为结构参考，不声称复制最新版所有细节。用户已确认红果为主、只改短剧、保留demo素材。

## 最小方案

复用现有 DramaPlayer、EpisodeSheet、drama API hooks、selectDramas、手势判定、短剧遥测和媒体生命周期。主页组合推荐/剧场/追剧，播放器增加嵌入模式。只新增短剧本地状态store，已有Zustand管理界面状态，React Query仍独占服务端数据。首页和详情共用播放器与追剧状态，不建第二套播放器或新接口。

本地状态按Telegram用户ID隔离（浏览器演示用local），最多保存200条ID/集数/秒数/追剧状态；不落视频签名或完整响应。观看进度节流5秒、暂停/退出补存，详情失效时回退有效首集。搜索和剧场滚动仅保留当前会话。明确本设备限制，云同步以后另议。

## 故障与边界

- 复用API现有有限超时/重试，取消无限自重试；错误保留明确重试。
- 媒体由单一播放器持有；换集/换剧/退出保存进度后释放，迟到Promise不可修改新流。
- 自动播放被拒绝时至多静音重试一次，仍被拒绝保留播放按钮。
- 不批量取视频，只按当前剧请求，沿用点击预取；原有签名过期由既有refetch处理。
- localStorage/sessionStorage损坏/禁用/写满降级内存，保留实际播放；只存有界标量，未知字段丢弃。
- 手势、range和Sheet隔离；reduced-motion关闭入场效果。窄屏优先可点击和视频主体。
- 无支付、服务端写入、计费、事务或迁移；不需要新幂等键/补偿/新服务。

## 演进与恢复

旧详情URL继续有效，返回/dramas恢复最近栏目；后端/DTO不变。回滚仅前端，新增本地key可忽略。此次仅本地给用户评审，尚未授权上线。

## 两个一级入口调整

用户已确认五导航，首页中心播放符号。复用 DramaPlayer，拆出 DramaHome 给根路由；`/dramas` 只负责剧场/追剧。既有角色页移到 `/characters`，所有角色返回链接、会话浏览状态与首屏指标机械更新路径，旧 sessionStorage 的 `/` 视为发现页历史。只调整必要导航，不重新设计角色/影像。固定验收同步原角色路径，并增加中央入口回归。

## 第二轮增量设计（已根据用户截图与明确授权审核）

复用现有 Sheet、React Query、apiClient、getOrCreateDbUser、drama_archive repository 及本地追剧 store。前端统一“收藏”用语，追剧栏目容纳收藏与历史。视频加载不等待互动请求；只加载当前剧的互动摘要，评论抽屉打开才请求列表。

### 数据归属与不变量

依据用户“全部放在短剧 schema”要求，扩展既有 `drama_archive`（其原八域之外的归档归属见已有 10-21-drama-archive-access 任务），不创建兜底 schema。新增 `drama_likes` 和 `drama_comments` 完全随短剧互动功能生命周期，可在功能下线时归档删除；不改 telegram-video-archive 管理的原表。权威写入方为本项目经过 Telegram 鉴权的 backend；frontend 只用 DTO/API，运营/角色/影像不消费。

- drama_likes：一位用户一部剧至多一条，复合 PK，PUT 写目标状态，重复提交幂等。仅服务端可读写。
- drama_comments：UUID 幂等键、剧 ID、用户 ID、1–500 字纯文本、创建时间。评论作者仅展示稳定匿名“剧友”编号/“我”，不输出 Telegram 身份信息。删除仅允许作者，通过 user_id 条件更新 deleted_at，保留墓碑防止重试复活及删除绕过限流。普通文字渲染，不执行 HTML。
- 两表 FK → drama_archive.dramas(id) 与 app_core.users(id)，删除根实体级联清理；不复制用户根实体。评论按 (drama_id,created_at,id) 游标分页20条；用户时间索引支持限流。
- 评论发布 RPC 用按用户事务锁串行化 3条/分钟限流及幂等重试，先检查同 UUID 已提交再限流。只插入，不开放任意更新。固定 search_path，撤销 PUBLIC/anon/authenticated，service_role 专用；两表 RLS 无公开策略。点赞使用 PostgREST 目标状态写，所有数据库调用5秒超时，无自动无限重试。
- 未迁移/接口失败只降级互动，不能阻塞看剧；写失败不伪报成功，点赞恢复真实状态，评论保留原草稿和幂等键。日志只含事件、剧ID、状态、耗时和错误，不含评论正文。

### 发布/恢复

仅本地实现，不执行生产迁移。未来先执行单个新增 migration（空表、局部短锁），再 backend，最后 frontend。原接口不变，旧客户端不受影响。回滚先前端再后端，保留互动数据；确认不再需要数据后才删除两表/RPC。不创建跨设备收藏同步、关注关系、评论嵌套回复/点赞、通用社交框架。

### 验证与风险

新契约、鉴权和数据库权限需要回归验证：复用 backend Vitest 架构增加互动路由权限/输入/幂等映射测试；在本地隔离 PostgreSQL 验证迁移、FK、权限、重复、限流，不连接业务库。现有 UI fixtures 增加互动状态及失败，扩展 @drama 验证收藏/点赞/评论、草稿恢复、评论不干预播放、320px布局。shared 测试、所有消费者 typecheck、受影响 build 及已有短剧测试。

## 夜间氛围微调（用户最新确认）

产品主要在夜间使用，调性带一点暧昧/私密感。沿用已通过的红果式结构与操作，仅将纯黑白/暖橙改为暖炭黑、柔和米白、低饱和玫瑰灰点缀。避免大面积高亮与艳色渐变；保持正文、按钮和状态的辨识度。不增加新流程、接口或数据，不改角色/影像内部主题。复用既有短剧移动布局场景查看截图即可，无需重跑数据库和其他业务测试。

## 连续观看修正（用户明确要求，2026-10-27）

- 打开/关闭评论不干预视频播放，原本暂停仍暂停。评论期间同样续播，评论面板锚定打开时的剧，自动跨剧不关闭面板或清掉输入；面板标题说明归属。复用现有评论组件，将其生命周期提升到未按剧ID重建的页面层。
- 最后3秒预取下一视频的元数据/播放签名（单次有界，仍只有一个视频发声）；保留当前片尾，在 ended 自动滑入同剧下一集，末集接下一部。使用轻量纵向过渡，不加倒计时/教学提示/结束卡片。减少动态偏好下无动画。
- 正在手动选集时等选集操作完成，后台隐藏时不自动换剧/发声；评论不阻塞续播。无下一条时安静停在最后画面，仍可重播。不擅自循环推荐队列。
- 删除“已经看到最后一部”及常驻上下滑提示。仅改前端与既有 @drama 验收，验证评论续播/草稿不丢、末集跨剧、前后台/选集边界、单视频及静音状态；无需数据库/后端改动。

### 播放页手势归属修正

现有原生禁用收起手势挂在按剧ID重建的播放器上，换剧会恢复再禁用；移到稳定的主布局，仅 `/` 与 `/dramas/:id` 启用，换剧/打开面板不释放，退出播放场景恢复原状态。Telegram 官方支持 disableVerticalSwipes（Bot API 7.7+）：https://core.telegram.org/bots/webapps#initializing-mini-apps 。页面触摸统一在播放器原生 capture 监听（非 passive move）处理，避免 React 被动委托和父层手势争抢；多指/取消/横滑不换剧，评论与选集滚动不拦截。复用现有 @drama 测试加入 Telegram 桥消息记录，检查切换期间无 enable、退出恢复，并核对触摸默认动作阻止和面板滚动。浏览器桥模拟不能证明原生 Android 宿主动画。

评论容器放在稳定 MainLayout 播放场景 Provider 中，跨动态路由也不重建，避免 Next.js 换剧时丢掉正在输入的草稿。

实测修正：SDK 3.11.8 的 mount 会立即把竖滑设为 false，必须在 mount 前记录恢复目标；跨集时浏览器会将 playbackRate 恢复到 defaultPlaybackRate，两者同步设置。保留会话静音/倍速，自动跨剧不突然恢复声音。

## 标签信息层级（用户确认，2026-10-27）

复用已有 DTO tags 与运营顺序，不重新分类/打分、不改接口/数据库。增加一个仅负责展示的 DramaTags 组件供三处复用：卡片最多两行两列（4个以内全显，超过4个显示前3个与+N）；播放页一行前2个与+N，完整标签随“查看完整简介”进入简介面板。详情全部自然换行，长标签可折行；卡片/播放页的长词省略，详情查看全称。低对比灰玫瑰、小字号、轻底色，无高亮彩色徽章。简介独立一行，不能覆盖标签；无标签不占空白。只扩展现有虚构数据和 @layout 剧场→简介场景，检查390/320宽、多个/长/空标签、完整标签和可关闭性；前端及验收类型检查、现有相关UI与lint，无新增测试文件或持久化。

## 高频动作手感修正（用户要求从产品体验出发）

标签最终选择覆盖前述初稿：用户确认剧场卡片先不放标签；保留同期编辑的播放页6个以内完整换行、超出+N、简介全部展示。不恢复已移除的卡片标签。

验收标准是用户自然动作与即时反馈匹配，而非按钮逻辑可用。按用户最新纠正：画面单击仅切换控件/纯净模式；双击任意空白处暂停/继续。使用320ms窗口区分，双击不执行单击的界面闪烁；中央图标保留直接播放，双击该图标不让第二击改变界面。纯净模式在首页同时收起顶部与底部入口，单击随时唤回；不会因暂停强制显示控件。滑动后的合成点击不触发播放。剧名/简介与中央播放图标允许起手竖滑，真正的按钮/进度条/列表保持各自用途。手指按住或正在选倍速时，自动续播暂等；滑走/换源清理点击状态。倍速展开直接点选 1/1.25/1.5/2，当前项可见，选后收起、外点关闭，不再循环试探。复用原组件与状态，无后端/契约/数据库变更。扩展既有短剧验收覆盖单击/双击、图标与空白混合落点、滑动不误播、按住不自动切、倍速直达及键盘基本操作。标签增量已通过8项手机布局验收与4项fixture协议检查，保留成果。

### 评论/选集面板的下拉手感（2026-10-27）

用户看到顶部横杠会自然下拉，当前装饰横杠没有响应。本轮仅短剧两张面板：横杠连同标题空白形成稳定拖动区，关闭按钮仍独立点击；内容列表、标签、选集按钮和输入区域不参与收起。单指向下且纵向位移明显大于横向时轻微跟手，达到72px松手关闭，未达阈值/斜滑/多指/取消时回弹；减少动态偏好下即时归位。关闭评论不改变媒体状态。

复用检索：现有 character-detail-sheet.tsx 的整面板拖拽依赖其滚动位置与自建 portal 生命周期，create/page.tsx 为列表拉刷，都不适合直接复用，也不改其他闭环。增加一个短剧局部 useDramaSheetDismiss hook 供两个面板共享，保持现有 Radix Sheet 的遮罩、焦点与关闭动画。使用标题区原生 TouchEvents、非 passive move；位移直接写面板样式，避免拖动重渲染评论列表。只在打开时绑定，关闭/卸载清理监听，document 捕获第二触点用于取消跨区域多指手势。无接口/数据库/全局 Sheet 改动。主代理在现有 @drama 验收中补充拖动关闭、短拖回弹、斜滑/多指/取消不关、正文滚动不关、X仍可点及减少动画场景。

## 第六轮落地设计（已获六项整体授权）

复用：DramaPlayer现有原生touch capture、媒体生命周期、双击判定、预取、Zustand及@drama固定验收；复用drama-playback方向工具。拆一个短剧专用进度组件，避免将指针拖动的高频状态塞入全播放器；不引入手势库。跟手样式仅写局部transform，拖动过程不重渲染整页，不加载第二个发声video。

手势：单指先锁纵向意图，竖向跟随，边缘阻尼；根据距离或短时速度提交，未提交/取消回弹；动画完成换源，仍预取签名；详情只切本剧可播上下集。评论/选集/进度独立，换源/卸载/后台清理手势与计时。既有自动连续播放保留，末集安静停止于详情，首页可接下一部。

进度：全宽>=44px触区，指针捕获；拖动预览时间与加粗轨道，松手提交，取消恢复；拖前暂停状态保留，原本播放在松手后恢复，后台不强行恢复；键盘原生range可用。无缩略图服务或数据库字段。

继续看：已有本地history加兼容可选的有效观看标记，真实累计播放达到简单阈值或主动选集才更新；快进跳秒不冒充观看。保留全部history，优先有效未完剧，不让短暂试看抢位。老记录安全回退，无跨设备同步。搜索时暂时忽略分类，退出恢复原分类。追剧行用覆盖link与独立收藏button，不嵌套交互。

可靠性与恢复：无网络新接口/重试/计费/生产迁移。主要风险为拖动与点击/自动续播争抢、动画残留、seek到末尾、媒体换源迟到恢复。通过本地取消与当前媒体校验、有界过渡解决。UI与本地可选字段向后兼容，可回退展示，不清用户历史。不做推荐算法、长按倍速或跨设备同步。

验收：扩展已有drama.spec.ts覆盖拖动中transform/取消回弹/快划/详情换集首页换剧，进度大触区与按下暂停松手恢复/原暂停保持/取消/后台，搜索跨分类/恢复，试看不抢继续看，整行与收藏独立，单击显隐持续及纯净双击反馈。复用390/320和既有全部短剧/角色场景；frontend/ui typecheck、相关单测、lint/build。无需新建测试文件。

### 用户补充：发现入口与专注追剧（2026-10-27）

首页下方「观看完整短剧」是路由入口，不直接弹选集；进入详情沿用当前集与秒数，详情下方改为「选集」。首页上下滑/自动结束均换不同的剧，详情上下滑/自动结束均切本剧集数，末集停留。`from=feed`记录返回语义，返回首页仍保持刚才的剧和进度；剧场入口仍回剧场。沿用已有媒体、列表和本地历史，无数据库字段。
