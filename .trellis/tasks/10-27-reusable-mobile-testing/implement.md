# 执行计划

1. 场景/协议：整理公开 DTO，建立类型化数据与固定状态，未知接口显式拒绝。
2. 启动与控制：固定预览服务、热更新、独立缓存与本机场景入口；自动验收用独立端口。
3. 用户路径：按 profile / roleplay / chat / image 分组编写可复用 Playwright 用例；共用网络、错误与截图收集。
4. 验证：工具 typecheck、场景服务集成检查、浏览器常见/窄屏实际运行、前端既有测试和构建。
5. 记录：使用说明、AGENTS 入口、前端测试规范、覆盖与剩余边界、最终变更清单。

不改既有业务行为；遇到上游缺陷先记录，不擅自混入产品修复。不添加自动完整发布流水线。用户已追加授权提交并通过dev发布main；按最终文件白名单执行，原有两个VIP留痕文件不纳入。

6. 发布：更新最新dev并复验，创建dev功能PR；合入后以main为发布基线提取本次已验收提交，防止带入未发布短剧。按分支保护处理审核，禁止擅自绕过。
