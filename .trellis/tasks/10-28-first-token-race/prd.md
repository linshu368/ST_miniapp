# 首发与兜底竞争交付

用户授权：修复剩余策略问题；测试通过后先合 dev 再上线。最新澄清：赢家确定后立即停止败方；败方只保存已经收到的内容用于排查，不继续生成完整回复，不发给用户、不另扣费、不阻塞首字。

## 目标

- 保住10秒总首字预算内能交付的回复；4秒是启动兜底阈值，不是取消首发时刻。
- 两路最多一次用户交付、一次原型号权益/价格结算。超时无交付仍免扣；主动停止按既有规则。
- 同型号静默等待不重复发请求，继续至总截止；明确失败最多一次顺序兜底重试。
- 赢家确定立即停止败方。仅异步保存已收到的有界排查片段和原因，不扩大数据库日常压力。
- 运营文案与看板准确表达阶段参数，AI自动调参保持未启用。

## 验收

1. 首发在4秒之后、10秒之前仍可回赢；兜底超过原2秒但在总截止前也可获胜。
2. 同步/相邻微任务同时出字仅一方获胜，另一方立即abort/cancel；无双流混合，无二次结算。
3. 到绝对总截止无首字即终止所有尝试；晚到数据不能获胜。已获胜回复仍可正常生成完毕。
4. 双失败、早期错误、同型号、用户停止、离页、慢/失败数据库写、晚到headers等路径受控。
5. 败方不会进入chat_history正文、上下文、用户恢复或计费补录；诊断片段长度受限、Grafana无正文权限。
6. 无新增定时任务、查询轮询、逐token写入；统计/诊断不阻塞交付。TEST真实流与计费、生产版本/轻量查询窗口独立核对。
