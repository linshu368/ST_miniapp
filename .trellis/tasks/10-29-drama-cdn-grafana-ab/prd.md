# Grafana 短剧 CDN A/B 对照

## 目标

在现有「工程｜03 短剧启动与播放」（UID `st-engineering-drama`）中比较约20% Bunny与80% Supabase的起播体验和播放质量，支持是否扩大实验流量的人工判断。

## 已确认事实与约束

- 用户最终指定 `st-engineering-drama`，不恢复旧 `st-drama-playback` SQL写入，不改原分流比例、签名、播放、预取、恢复或超时策略。
- 现有响应 `DramaDelivery` 已含实验ID、原始桶、实际节点和选择原因；Faro投影及出口白名单尚未携带这些维度，不能仅改查询就生成完整分桶统计。
- Faro已有非采样的启动结果与耗时投影、成对播放/卡顿增量窗口；Backend Loki的`drama.startup_diagnostic`仅含达到5秒的final/network明细，不能充当总体。
- 实验按用户稳定分桶。一次用户可贡献多次启动和多个质量窗口，观察数量不能冒称人数或检查20/80用户分流是否异常。
- 初始start发生在取址返回之前，取址失败、提前离开及旧客户端可能没有delivery；未知归属不得补成Supabase或静默丢掉。
- 首播成功必须沿用首帧与playing证据。首页文档入口耗时、单次播放尝试耗时、重试累计耗时有不同起点，不能混算。

## 范围

R1. 在同一看板增加独立CDN A/B对照区，保留现有面板含义与筛选；实验筛选仅作用于实际携带实验维度的新区，说明适用范围。

R2. 全量启动终态、成功耗时/阶段及播放质量窗口补充受控实验维度，实际节点与原始桶分别保留。旧数据缺标签不回填。

R3. 主指标为「已归桶、已收到的前台启动终态中，单次播放尝试在5秒内成功的比例」；明确显示分母、未知归属、后台和结果构成。左滑/退出未开播算未达标但不归为供应商错误。重试与原始尝试分别展示，默认主比较排除retry。

R4. 辅助指标为成功启动P50/P95与有效N、成功启动耗时区间占比、错误/不可播/自动播放受限/退出构成；护栏为同条质量窗口加权卡顿占比及有效窗口数。

R5. 按原始桶出主结论，实际节点用于回退解释；按相同实验、时间、release、平台、网络、页面和适用入口比较。无数据不补0；开始/终态窗口计数不能称逐尝试配对覆盖率。

R6. 验收覆盖两个桶、disabled回退、缺delivery、旧版本、阈值边界、迟到network、首次失败后重试、播放质量边界、非法/敏感属性及遥测故障隔离。

## 验收标准

- AC1 / R1：新增区域同时显示Bunny/Supabase，旧看板查询和首张画面区域保留；新增筛选范围有说明。
- AC2 / R2,R5：实验ID、原始桶、实际节点、原因在实际Faro输出中可读；未知归属独立展示；禁用回退仍属原Bunny桶。
- AC3 / R3：同一终态事件携带结果和5秒分类，阈值使用原始精度、5000ms达标、5000ms以上超标；后台单列、原失败不被retry覆盖；seek和network不重复进入启动分母。
- AC4 / R4：成功分位与各自N对应；卡顿比为Σstall/Σ(play+stall)，使用同一批合法成对窗口，未恢复卡顿保留；暂停/seek/后台/初始等待排除。
- AC5 / R5：历史缺实验标签不补对照；分母为0返回无数据；不声称有去重人数、SRM或全访问覆盖率。
- AC6 / R6：既有单测、受影响包typecheck/lint/build、真实本地Faro→Alloy→Loki验证通过；Cloud新字段、真实Telegram和线上指标须分别提供新证据。
