## 复用调研

- 后端 `/routes/drama.ts`：保留鉴权、ownership、分段和 `private, no-store`，扩现有 `/play`，不另起播放 API。
- `features/drama/signed-url.ts`：复用私有短期能力、Bunny HMAC、TTL、容量 500 和 single-flight。缓存加环境／源配置隔离，本次 provider 作为显式选择，不按用户重复签同对象。
- `platform/runtime-config.ts`：统一解析开关及环境安全边界；路由不直接读环境变量。
- shared `api/drama.ts`／`api/drama-timing.ts`：兼容扩展 playback context、seek 及恢复链；旧客户端缺字段是 unknown。
- 前端 `lib/api/drama.ts`：复用查询／预取，新播放意图须确认当前策略，旧缓存只作候选。
- `drama-timing`／`drama-media`／`drama-observer`：复用单调时钟、首帧与平台。启动结束后不能观测 seek，补独立生命周期；不更换播放器。
- `DramaProgress`：当前先写 currentTime 后回调，补写入前诊断点；仍只在提交时 seek，键盘入口也覆盖。
- telemetry／Pino／`import-drama-timing.ts`：复用白名单和 NDJSON 格式，比较只读，不增加遥测服务。
- 现有 timing repository／processor／分析 RPC：保留 startup 功能；新实验／seek 统计以日志为来源，不能假设旧 SQL 会保存或聚合新字段。本任务不改 DB 函数／migration。

## 分组、配置与生产回源

保留 `DRAMA_CDN_ENABLED` 为唯一开关，默认关闭。实验版本、专用服务端 HMAC key、CDN 主机和环境目录经 runtime-config 配置，HMAC key 与 CDN 签名 key 分离；具体名字随实现写入 `.env.example`，不填写真实值。

鉴权后 `HMAC(experiment_key, version + environment + user)` 推导 0–9999 桶，低于 2000 选 Bunny；另一域隔离 HMAC 作实验用户去重码。实验期间固定版本／比例／key，保证跨实例／部署一致。关闭不改变原分组，但实际路径为 Supabase。

生产源来自当前解析的 `config.supabase.url`，校验完整 origin、私有桶、规范路径和源 token。TEST／production 使用隔离目录、签名配置与缓存 key，生产拒绝 TEST origin。继续只给 Bunny 对象级短期能力，无项目／service-role key。

分流在签名缓存外决定；不同路径／环境／配置不共用结果。签名或媒体失败保留真实失败，不静默回 Supabase 后当作 Bunny 成功。

## 契约、计时与去重

Playback 兼容增加实验版本、原分组、实际 provider、关闭／恢复原因等有限字段。尚未取得地址时实际路径为 unknown，不猜测 Supabase。接收端根据已鉴权身份生成并附加用户去重码，不接受客户端自报身份／去重码。日志保留环境／前后端 release；不记录原始 ID、URL 或凭据。

每次观察有 ID、播放根 ID 和恢复父 ID。start／slow／final／network 按观察 ID 合并，不重复计次数。seek 在接收端分支处理，不误入仅支持 startup 的既有分析持久化流程。旧数据缺实验字段保持 unknown。

5 秒仅为观测阈值，不中断视频；最终耗时持续到真实结果。以未格式化值判断 `elapsed > 5000ms` 后再展示，避免舍入隐藏边界。起播包括用户触发、取址、路由、媒体准备至实际首帧；自动首页同时保留文档导航至首帧总时间，主动浏览时间单列。

## 快进与重试

提交前记录单调起点、目标与 buffered 状态；已确认未缓冲才纳入核心 seek 对比，读取失败是 unknown。记录 seeked 和目标首帧分段；首帧须匹配当前媒体代际和目标附近，旧帧／seeked 不能判成功。

优先 rVFC；不支持时使用明确标记的播放推进观测。暂停 seek 如不能证明目标画面出现，记未验证，不能算 0 秒／达标。离开、后台、错误、切源、新 seek 均收口旧观察并解除监听，保留真实结果。

失败终态不可覆盖；失败起播后的用户重试生成子观察，保留原根单调起点、原失败和累计等待，记录重试间隔，不能仅展示重试后短耗时。换剧／换集是新播放意图，建立新根。

## 关闭恢复

不新增策略接口或轮询。每个真实新播放意图通过现有 `/play` 确认当前策略，两组执行相同流程，不能只给 Bunny 多加一次请求。后端签名缓存继续复用，前端旧值／已完成预取未获本轮确认不能写入 src；确认失败也不能回放旧 Bunny 地址。迟到响应按意图代际隔离。

若开关是部署时生效，必须以所有服务实例启用新配置并验证为生效点，不宣称修改变量即瞬间关闭。生效后新播放重新拿 Supabase，当前已播视频不强制切源，保留位置／暂停语义。这项前端确认是关闭要求所需，两组一致、address_wait 可见；其他性能策略冻结。

## 首次比较

只读脚本复用 NDJSON 解析，明确环境／实验／版本／窗口并限制大小／行数。按平台、观察类型、原分组和实际路径输出：尝试／独立用户／超标及分母、受影响人数及分母、失败／退出／未收口、逐条真实等待和分段。回退后的 Supabase 成功不归为 Bunny 成功；总体人数去重，不能简单相加平台人数。

列出重复／冲突、缺 final、未知身份／路径、截断及上报丢失边界。5 秒前退出不算达标；超过 5 秒还没结果是超标下界，最终时间未知就写未知。保留冷／热缓存和未知样本，不通过过滤美化结果。比较不新增看板／SQL。

实际开流后 12 小时首次检查；先看失败／等待恶化，再看长尾。样本少只报证据不足，不设置到时即成功或自动扩比例。

## 可靠性与演进

- 超时／重试：沿用签名／API 的明确预算，不用 5 秒目标替换；不增加自动媒体重试或探针，原重试不重置根等待。
- 幂等／并发：分组为纯确定性计算，签名 single-flight；观察 ID 去重，过期事件隔离。
- 事务／补偿：无新业务写入、DB 对象或迁移；关闭＋重新取址恢复，无数据回滚。
- 限流／容量：继承 telemetry body／事件／频率／队列上限，seek 不绕过；验证新增报文不占播放优先槽，日志导出只在本地临时安全目录。
- 发布：兼容 Backend 先于 Frontend，同一生产版本供两组使用；先开关关闭预检，再单独确认生产配置／CDN 规则／发布／开流。TEST 不影响生产或反向污染。
- 停止：Range、私有访问、热缓存签名、代际隔离、关闭重取址任一失败不开流；连续不可播或明显恶化可人工关，不等 12 小时，不建自动熔断。

## 取舍与暂缓

无主路径之外的附加实现。扩现有测试，不新建测试文件。完整平台、自动熔断、新看板和实验数据落库暂缓；首轮需人工导出比较，并承担既有日志保留／送达限制。生产启用和 12 小时实况不以本地验证替代。
