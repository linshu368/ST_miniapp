# Grafana 监控迁移与页面服务性能验收

状态：已获实施批准。2026-10-29 用户在规划与远端版本核验后明确要求“没问题就开始干活”，并指定页面体验、角色扮演交互、短剧为三个工程主线。允许代码和本地/测试验证；生产启用仍需独立确认。

## Goal

Grafana 同时服务经营判断与工程验收：保留现有低开销经营统计，新增不依赖生产数据库的页面/服务性能监控，使工程能够发现受影响最大的慢点、定位责任阶段、按同口径验证优化成果。

优先级：看板第一层为“页面体验”“角色扮演交互”“短剧播放”三个独立大类；API、数据库、运行时及采集健康为解释这些体验的下钻证据，不以服务端指标取代客户端体验。

## Acceptance criteria

- AC1 / R1,R8：数据库业务事实和计费回归不变，新通用遥测代码路径无数据库 I/O；经营核心看板继续可用。
- AC2 / R2,R3：页面覆盖表列出已接入/不适用/待接入；关键入口至少覆盖首页、角色、大厅/会话、短剧列表/详情与播放、图片广场、个人中心、充值/VIP，其余已登记用户页一并接统一 ready。接口榜覆盖所有模板路由，普通与生成分组。
- AC3 / R2,R3：用慢响应头/慢 body、排队重试、缓存、新旧动态 ID、后台/离页、错误 UI、SSE 200 后失败、首发/兜底竞争等场景证明时钟与终态定义；缺失不冒充成功。
- AC4 / R4,R5：工程看板可从页面/API 找到慢点并跳转日志或 Sentry；同一版本/分层的前后窗口可比。低样本显示观察，不抹掉慢/失败入口。发布前后 P95 不可脱离样本、成功率、覆盖与预算超标率单独验收。
- AC5 / R6,R7：只初始化一次 exporter/采集器，不竞争 Sentry tracer provider；标准化未知路由/供应商；队列饱和、端点断网/401/429、关闭开关、进程退出均有界；运行时资源与新增包体在合成负载对照中报告，无无界增长。
- AC6 / R7：构建产物/测试 payload/日志扫描无 Cloud 写入凭证、聊天或个人敏感内容；高基数只作受控明细，非指标/日志索引标签；遥测请求不递归观测。
- AC7 / R8：记录环境、运行 SHA、端点配置状态、采集健康、切换窗口、停止/恢复步骤；未收到真实样本不得标记迁移成功，生产无数据不能被解释为零故障。

## Scope / non-goals

- 本任务是一条跨前后端的统一观测链路，分阶段验证但不分别部署多套独立监控框架。
- 本期不改变任何性能优化业务行为，不升级计费/生成策略，不重做页面 UX；仅建立可复用工程标准与数据链路。
- 不引入 Kafka/ClickHouse/自建存储集群；不建立第二套 Session Replay 或全链路 tracer；不修改其他 TextBot 项目。
- 不删除或重写历史记录，不改变钱包、免费额度、首字交付与恢复 RPC；不自动生产发布、提交或 push。
- 本期以当前 MiniApp/Backend 为覆盖范围；支付 Worker/Cron 保留已有监控并登记覆盖，独立服务需逐项实测后再标为已接入；独立客服仓库不在本次改动范围。
