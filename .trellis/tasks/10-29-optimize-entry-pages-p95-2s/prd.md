# PRD：三处入口 p95 两秒性能优化

## 1. 背景

首页 `/`、角色卡 `/characters` 和短剧广场 `/dramas` 是高频入口。现有生产证据显示，Railway 计算资源未饱和，页面慢主要来自冷启动数据等待、客户端到响应头的链路、关键媒体下载/解码和缓存未复用，而不是服务端 CPU 或内存不足。

本任务只定义可实施、可验证、可回滚的优化方案。规划评审通过并将任务切换到 `in_progress` 前，不修改产品代码或生产配置。

## 2. 目标

以“用户能看到并操作首个关键内容”为打开完成，而不是仅以 React 挂载或 JSON 返回为完成：

| 页面          | 主指标                                                     | 目标       |
| ------------- | ---------------------------------------------------------- | ---------- |
| `/`           | `first_visual`：播放器海报、首帧或明确可用占位三者最先成功 | p95 ≤ 2.0s |
| `/characters` | 首屏角色卡可操作，首个可见头像成功/失败均已收敛            | p95 ≤ 2.0s |
| `/dramas`     | 第一行卡片可操作，前两张关键封面成功/失败均已收敛          | p95 ≤ 2.0s |

辅助目标：

- 首页视频 `first_frame` 首阶段 p95 ≤ 3.0s，CDN 灰度阶段争取接近 2.0s；不以牺牲播放成功率达标。
- 三页后台新鲜数据完成 `page_fresh` p95 ≤ 2.5s，但不得阻塞缓存内容首屏。
- 每页分别达标，不用三页算术平均掩盖单页退化。
- 按冷启动、暖缓存、document、SPA 导航拆分统计；生产门禁以冷启动和全量总体均不退化为准。

## 3. 非目标

- 不通过扩容 Railway 掩盖客户端和媒体链路问题。
- 不重做播放器、React Query 基础设施或通用缓存框架。
- 不改变付费、鉴权、播放权限和业务排序语义。
- 不创建数据库 migration，不迁移已有媒体对象，不把图片直接迁入 Bunny。
- 不重复已完成的请求取消、单次重试、同请求去重、角色详情懒加载等工作。

## 4. 验收标准

### 4.1 指标正确性

- 保留既有 `page.ready`、`page.fresh` 历史口径，新增或复用低基数的关键视觉收敛指标；不得用“缓存数据已读出”冒充图片/视频已可见。
- 关键媒体记录 DNS/连接/TTFB/传输/解码、HIT/MISS 或等价缓存来源；不得记录 URL、签名、token、完整 initData 或内容正文。
- Sentry、Grafana 和 Railway 按同一 release、环境、时间窗对照；至少收集每个关键 cohort 100 个样本，样本不足时延长到 7 天，不宣称达标。

### 4.2 Grafana p95 合格线

Grafana 是本任务上线后的主验收面板。当前 24 小时值只作为方向基线；最终判断必须按 production、release、route、navigation type 和 cache cohort 过滤，不能把 document、SPA、冷缓存和暖缓存混成一个总体值。

| Grafana 指标/cohort                      |                当前 p95 |                                     合格线 | 用途                                                                     |
| ---------------------------------------- | ----------------------: | -----------------------------------------: | ------------------------------------------------------------------------ |
| `/` `page_ready`, document               |        5713.5ms（n=47） |                                   ≤ 2000ms | 首页打开主门禁；新关键视觉指标上线后以其为主、此项保持不退化             |
| `/` `first_visual`, document             |    5146.8ms（成功 n=4） |                                   ≤ 2000ms | 首页关键媒体门禁；当前样本不足，只指示方向                               |
| `/characters` `page_ready`, SPA          |        2126.5ms（n=68） |                                   ≤ 2000ms | 角色卡打开门禁，并新增关键头像 settled p95 ≤ 2000ms                      |
| `/dramas` `page_ready`, SPA              |         605.0ms（n=36） |             ≤ 2000ms 且不高于基线 20% 以上 | 防止目录缓存优化反而拖慢已较快的 SPA 路径；关键封面 settled p95 ≤ 2000ms |
| `/` `page_fresh`                         |                4921.0ms |                                   ≤ 2500ms | 首页后台校准门禁                                                         |
| `/characters` `page_fresh`               |                4795.2ms |                                   ≤ 2500ms | 角色数据后台校准门禁                                                     |
| `/dramas` `page_fresh`                   |                2324.9ms |                          ≤ 2500ms 且不退化 | 短剧目录后台校准门禁                                                     |
| drama `st_api_total`                     |                4496.5ms |                                   ≤ 2000ms | 客户端完整 API 长尾门禁                                                  |
| drama API `headers` stage                |                3446.0ms |                                   ≤ 1500ms | 网络、边缘、鉴权到响应头的主优化方向                                     |
| drama API `body` stage                   |                 440.2ms |                                    ≤ 500ms | 响应体读取守门，不作为首要改造方向                                       |
| drama API `queue` stage                  |                  65.1ms |                                    ≤ 100ms | 客户端调度守门                                                           |
| Railway `/api/dramas`、`/api/characters` | 最慢小时约 1079ms/935ms | 各自 p95 ≤ 1000ms，且不高于同 release 基线 | 服务端回归守门；不是页面达标的替代指标                                   |

合格判定同时满足：

- 每个页面的关键视觉 p95 和 `page_ready` 门禁分别达标；不能仅凭暖缓存总体 p95 通过。
- 24 小时窗口达标后，7 天滚动窗口仍达标或趋势稳定；每个主 cohort 至少 100 个终态样本。
- latency 只统计有明确终态的事件，但 error、timeout、aborted、`page_left` 必须单独计率；错误率或提前离开率上升 ≥ 0.5 个百分点即不合格，不能通过排除慢失败制造“幸存者 p95”。
- p50 用于识别大多数用户是否改善，p95 是发布门禁；p99 只做异常诊断，不因少量极端样本阻塞本目标。

### 4.3 用户体验

- 本地安全目录缓存命中时立即显示内容并后台校准；缓存缺失、过期、损坏或版本不兼容时自动回到网络路径，不白屏、不无限重试。
- CDN 图片失败时保留现有失败占位和可操作性；视频 CDN 失败不得绕过鉴权，回滚后新请求恢复 Supabase 签名 URL。
- 弱网、路由快速切换、请求超时、429/5xx、签名过期和 Range 请求均有有限失败路径。

### 4.4 性能与稳定性门禁

- 主指标连续 24 小时达标，并在 7 天窗口无明显回弹；页面错误率、`page_left`、播放错误率不得显著上升。具体数值以 4.2 的 Grafana p95 合格线为准。
- CDN 灰度停止条件：关键 p95 未改善至少 20%，或错误/提前离开上升 ≥ 0.5 个百分点，或卡顿率上升 ≥ 1 个百分点，或出现持续 403/Range/签名异常。
- Railway `/api/dramas`、`/api/characters` p95 不高于基线；CPU/内存不因新逻辑持续增长。

## 5. 约束

- Node.js ≥ 22、pnpm workspace、严格 TypeScript、禁止 `any`。
- 服务器状态继续通过 `src/lib/api/` React Query hooks 获取。
- 外部调用有明确超时；重试有限且只用于安全读操作。
- Supabase public image transformation 和 CDN 配额/费用必须在灰度前确认。
- Bunny 私有视频配置必须保持服务端 secret、环境和数据库目标门禁，生产配置与 TEST/PR 525 隔离。

## 6. 本地验收提醒

这是跨页面、接口、缓存与 CDN 的完整性能流程，实施时应扩展 `packages/ui-tests` 现有 `@drama`、`@roleplay` 场景，而不是另建一次性浏览器脚本。真实 Telegram 移动端、真实 CDN Range 和供应商链路仍需人工验收，模拟页面不能替代。
