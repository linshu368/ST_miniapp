# 首字交付修复：去误报、服务端计费、连接保温、兜底备份与耗时归因

## 目标

用户点击到看见首字的耗时要真实下降；6 秒不再一刀切。只有确属用户网络、我们优化不了的时间才不计入；凡是能靠优化改善的，全部算我方。

## 已核实事实（2026-10-30 11:25 至 11-02 16:53，3,081 次已知结果，338 次超时）

- 上行 ≥1 秒 205 次（6.7%）；服务端 ≥5 秒才出字 47 次（1.5%）；下行/其他 31 次（1.0%）；服务端真超时 55 次（1.8%）。上行由 `client_reported_at − request_received_at` 反推，服务端超时组作为对照成立。
- 客户端“超时”的 279 条回复全部 success/stop 完整交付，账本实扣 0，本应 4,252 星尘（聊天收入 9.2%）；用户还看到“再试一次”误报。
- 距上一轮结束 <60 秒超时 0.6–1.5%，60 秒后爬升至 5–15%（排除 2 个异常用户）。Railway 边缘 HTTP/1.1 空闲 60.0 秒断开，HTTP/2 本机 7 分钟未断（不代表用户路径）。
- 2 个用户占客户端超时 47%，其上行集中在 2–3 秒窄峰，具体机制未证实。
- 1017 作首发时兜底启动 0 次，服务端超时 4.9%（主力模型 1.5%）。
- 已排除：事件循环（P99≈23ms）、到上游连接（P50≈90ms）、fetch 前前端耗时（P99 56ms）、渲染、写库阻塞 SSE、普通请求的隐藏思考。

## 需求

R1 去误报：服务端未判失败时，客户端 6 秒计时不得提示重试，改为低干扰的“网络有点慢”；服务端明确失败才提示重试。首个 token 提交后提示自动消失；轮次结束不残留。

R2 服务端计费：服务端按时出字且回复完整交付即正常结算（含消耗免费额度）；服务端真超时才免扣。客户端计时不再影响计费或释放额度。`client_outcome=missing`（无任何回报）维持原有保守免扣。

R3 连接保温：聊天页可见且用户近 5 分钟有操作时保持到 API 源站的连接温热，请求不查库、无业务副作用、频率有界、失败静默。CORS 预检缓存提升到 7200 秒。

R4 兜底备份：所选模型等于兜底模型时也必须有第二路：首发走该型号优先供应商顺序，第二路用相反顺序；保持唯一交付、单次计费和 6 秒总上限。

R5 耗时归因：每轮上报协议、是否复用连接、建连耗时、网络开销和传输耗时。归因规则：建连（DNS/TCP/TLS/排队/预检）算我方；已建立连接上的传输算用户；证据不全算我方。`实际等待 − 用户传输耗时 ≥ 总预算` 才算我方超时。迟到首字记录真实时长。

R6 看板：主指标“我方责任超时率”（含服务端超时），并列展示用户实际等待 P50/P95、被排除为用户网络的占比，排除量不得隐藏。

## 约束

不新增 Supabase 监控写入、扫描或 cron；6 秒总上限和各型号阈值不变；不改历史迁移；既有 v4 观测口径保留以便前后对比；不改用户 `missing` 免扣；首字不再被客户端计费门控后，服务端交付事实是唯一计费依据。

## 验收

- 客户端超时但服务端按时：无重试提示，回复展示，正常扣费且只扣一次，免费轮次被消耗。
- 服务端真超时：提示重试，免扣，额度释放。主动停止、离页规则不变。
- 服务端晚于预算才出字：免扣。
- 1017 首发卡住时第二路在阈值启动且供应商顺序相反；任一路获胜另一路取消；只计费一次。
- 保温在隐藏页或空闲超 5 分钟停止，节流上限生效，失败不影响聊天。
- `roleplay.network` 指标按字段上报，无 RT/无 start 时归我方。
- 本地 PG 计费回归、前后端单测、`pnpm -r typecheck`、build、`pnpm test:ui --grep @chat` 通过。
- 上线后按版本对比：点击到首字 P50/P95、我方责任超时率、复用连接占比。

## 范围外（需用户决策）

首发启用延迟优先：Wafer 每千次调用 $9.66，Crusoe $1.98、Relace $1.62、Parasail $2.34，平台首 token P50 分别 628/1113/1017/1447ms。全量切换约增加该型号成本 60%，平均约省 200ms。接入 CDN/自有 API 域名涉及基础设施变更，待归因数据证明传输占比后再定。
