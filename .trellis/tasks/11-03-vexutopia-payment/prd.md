# 支付供应商替换为 Vexutopia

## Goal

原支付供应商子千易已完全不可用。把 MiniApp 的会员购买和星尘充值整条支付链路（下单、收银台、回调验签、查单对账、过期、告警、配置与文档）全面切换到 Vexutopia，并删除子千易实现。

## 背景与已验证事实

- 2026-11-03 用户已在 Vexutopia 注册、开通支付宝与微信收款并配置提现钱包；独立测试中 ¥1 支付宝、¥1 微信均已到账。该测试未绑定秘境用户、订单或权益，也未配置 Webhook。
- API：`POST /v1/payments` 建单（`payment_method` = `ALIPAY`/`WXPAY`，`currency` = `CNY`），`GET /v1/payments/:id` 查单，`Idempotency-Key` 24 小时内同 key 同 body 返回原结果。
- China Pay 单笔 ¥1–1,000；收银链接 1 小时过期；微信不可用时 `WXPAY` 请求会被按支付宝创建。
- Webhook：`POST /v1/webhooks` 注册端点并一次性返回 secret（文档写 `whsec_` 前缀，实测为 64 位十六进制串）；签名头 `X-Vexutopia-Signature: t=<秒>,v1=<hex>`，HMAC-SHA256(`{t}.{原始 body}`)，时间差 ≤ 300 秒；同一事件可能重复投递，按支付 id 去重。注册端点接收整个组织的事件。
- 官方状态页不提供支付宝/微信粒度的状态，也没有机器可读接口；渠道健康只能靠我们自己的建单/回调/查单信号判断。
- 没有退款 API；退款/拒付只以 `payment.refunded` 事件出现。每笔争议另收 50 美元。

## Requirements

1. 下单：用户选择会员或星尘套餐后，服务端按权威商品配置定价，先建本地订单，再建 Vexutopia 订单，并把 Vexutopia 交易号保存到本地订单；前端拿到收银台地址打开支付。
2. 入账：只认三种可信来源——验签通过的 Webhook、服务端主动查单（前端轮询时、快速对账任务、判过期前对账）。回跳页面、前端“已支付”按钮或用户截图都不能发放权益。
3. 幂等：重复通知、多路并发确认、重试都只发放一次权益，沿用现有 `settlePaidOrder` + `complete_payment_order` 唯一出口。
4. 校验：入账前核对订单存在、金额（分）、币种 CNY、运行环境、交易号与本地记录一致。
5. 回跳：支付完成后回到 MiniApp 订单结果页，回跳本身只做导航和一次服务端查单。
6. 多环境：生产、dev/TEST、PR 预览环境共用一个 Vexutopia 组织时，各环境只处理自己创建的订单，不因别的环境的事件报错或触发告警。
7. 可观测：建单、回调、查单结果按稳定错误分类写入现有支付操作事件，渠道维护、限流、供应商不可用能被现有告警规则识别。
8. 退款/拒付：收到 `payment.refunded` 时记录并告警，不自动扣回权益（第一版人工处理）。
9. 子千易整体废弃：删除其网关、路由、表单解析、诊断脚本、配置项和文档描述，不做任何兼容或过渡分支（用户 2026-11-03 确认）。数据库里的历史订单行不动，也不为它们写特殊逻辑。

## Constraints

- 密钥只放服务端环境变量（Railway），不写入代码、日志、URL、测试 fixture 或 Markdown。交接文档里出现过完整 API Key，正式部署前必须换新 key。
- 不新增数据库迁移；`provider_transaction_id` 已存在，`complete_payment_order` 对它是 `COALESCE` 写入。
- 所有外部调用有明确超时；重试有限，只对可安全重试的错误重试，建单重试必须带同一个幂等键。
- 套餐单价必须在 ¥1–1,000 之间，超出时建单前就拒绝。
- 发布走现有路径：TEST 验证 → 合 dev；生产发布分支基于最新 main。

## Acceptance Criteria

- [ ] TEST 环境用真实 ¥1 级别套餐分别完成支付宝、微信的星尘充值和 VIP 购买，各只到账一次；订单 `settled_by` 记录实际入账路径。
- [ ] 关闭 Webhook（或拒收）时，前端轮询或对账任务仍能在订单有效期内通过查单入账。
- [ ] 同一 `payment.completed` 重复投递、Webhook 与查单并发确认，钱包流水只有一条，VIP 只延长一次。
- [ ] 签名错误、时间戳超出 300 秒、非本环境订单、金额或币种不符时不入账；前两者返回 401，后几种返回 200 且留下事件/日志。
- [ ] 用户在收银台取消或关闭页面，回到 MiniApp 能继续付款或看到订单未支付；订单过期后不能再付款入账以外的方式改状态。
- [ ] 没有 Vexutopia 交易号的订单（建单中途失败留下的）不发起查单、不计入查单失败，不会让判过期任务因“查单失败率过高”跳过整轮过期。
- [ ] 渠道维护（503 `PAYMENT_METHOD_MAINTENANCE`）、限流、供应商不可用在建单失败事件里有独立错误分类。
- [ ] 仓库内不再有子千易实现、配置项和路由；README、ARCHITECTURE、env 示例、Railway 文档和相关 spec 已同步。
- [ ] `pnpm -r typecheck`、backend 支付相关测试、shared 测试通过。

## Android/iOS 性能 P95 门禁

- 受影响页面：`/profile/recharge`、`/profile/recharge/:orderId`、`/vip`（页面代码基本不改，目标是不退化）
- 受影响接口：`POST /api/payment/orders`（建单耗时换成新供应商）、`GET /api/payment/orders/:id`（轮询时内联查单）
- Android 页面加载 P95：基线 无可见样本（规划阶段未采集）/ 目标 3000 ms
- iOS 页面加载 P95：基线 无可见样本（规划阶段未采集）/ 目标 3000 ms
- 接口 P95：基线 无可见样本（旧供应商已不可用，旧数据不可比）/ 目标 建单 3000 ms、订单详情 1500 ms
- 数据来源与观测窗口：Grafana Loki Faro `st_page_ready`（按 route、tg_platform 分组）；接口取后端 pino 结构化日志 `recharge.order.create` 与请求耗时，按路由分开计算。发布后取至少 7 天。
- 发布后验证、无可见样本/低样本及不适用说明：旧供应商已停用，没有可比的接口基线，null 表示无可见样本而非 0。单组有效样本少于 100 时标为低样本并延长观察，不宣称达标。

## Out of Scope

- 自动续费（会员按一次性购买 N 天处理）。
- 退款 API、自动扣回权益、争议处理自动化。
- 前端支付页面视觉改版。

## Notes

- 用户已决定使用 Vexutopia，不等待真实 USDT 提现验证。
- China Pay 是否像其他区域通道那样把父交易置为 `cancelled`、在子交易上完成，文档没有明确，必须在 TEST 用真实支付确认（见 design.md 风险）。
