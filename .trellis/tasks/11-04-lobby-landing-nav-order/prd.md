# 首屏改为角色大厅并调整底栏顺序

## 背景

当前主力是角色扮演闭环（点角色卡 → 聊天），资深用户再去创作。但 10-27 起冷启动落地页 `/` 是 AI 视频流，角色大厅在底栏最左。

生产数据（Faro `st_page_started`，2026-10-28 ~ 11-04）：`/characters` 1911 次、`/chats` 588、`/chat/:id` 1255；创作相关（`/creation` + `/create*`）合计约 243 次；`/` 1104 次（主要来自冷启动落地）。最近 2 天角色大厅 561 次、创作合计 26 次。

## 需求（用户 2026-11-04 确认）

1. 新用户进入、或关闭后重新打开，首屏是角色大厅，不再是视频流。
2. 底栏：放映 | 剧场 | 秘境（中间） | 创作 | 我的。
   - 中间位给最高频页面；按上面的数据定为角色大厅。
   - 名称按页面职责取：放映=沉浸刷剧，剧场=找剧追剧（与该页标题一致），秘境=落地的角色大厅。
   - 视觉（用户 2026-11-04 从三套交互稿中选定）：悬浮圆角岛 + 选中项香槟光底滑动 + 中央凸出的星芒圆钮（比稿中缩小到 50px）；主色与大厅/创作页统一为香槟金。
3. 实现放在代码里：视频流移到独立路径 `/watch`，`/` 统一跳到 `/characters`；不依赖 BotFather 配置。

## 约束

- 角色 tab 继续在 `/characters` 与 `/chats` 之间记住上次视图；冷启动落地固定为大厅 `/characters`。
- Telegram 启动参数（hash 中的 `tgWebAppData`、query 中的 `tgWebAppStartParam`）跳转后必须保留，支付回跳、邀请、归因不受影响。
- 视频流、短剧库、短剧详情的播放、评论、计时行为不变，只换路径。
- 不改后端接口；短剧计时报告的 route 枚举加入 `/watch`（保留 `/` 兼容旧客户端）。

## 验收标准

- [ ] 打开 `/`（含带 hash/query 的 Telegram 启动 URL）落到 `/characters`，启动参数仍在，登录正常。
- [ ] 底栏顺序与高亮正确：`/watch` 高亮放映；`/dramas` 高亮剧场；`/characters`、`/chats` 高亮中间的秘境；创作、我的不变。
- [ ] `/watch` 播放、上下滑、隐藏底栏、评论与原 `/` 一致；短剧库「去首页看」类入口和详情页返回都回到 `/watch`。
- [ ] 性能埋点里视频流路由由 `/` 改为 `/watch`，仓库内看板同步。
- [ ] frontend typecheck、相关单测、lint、build 通过。
- [ ] TEST 环境用真实 Telegram（Android、iOS 各一）冷启动验证落地页与登录。
