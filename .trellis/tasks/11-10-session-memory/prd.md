# 会话长期记忆与 token 水位截断

## Goal

产品形态是"用户给出行动或指示，模型续写大段故事情节"。为控制成本和生成质量，发给模型的历史会被截断，早期章节离开窗口后，用户会感觉"写着写着就忘了"：人名变了、死去的人物复活、关系被重置、伏笔没有下文、提过的要求失效。

本任务做两件事：

1. 用"正文字数双水位"替换现有"按轮数 75/50"的截断策略。
2. 被截断的章节由后台模型压缩成会话级"前情档案"（下称记忆），在后续生成时注入，补回已离开窗口的剧情、人物、设定和用户要求。

唯一的质量目标：**不让用户感觉聊着聊着就忘了重要信息。**

## 硬原则

1. **用户无感。** 记忆的生成全程在后台；读取与生成链路并行，不串行等待。任何失败（读取超时、任务失败、模型报错、结果不合法）都不阻塞、不拖慢生成，不向用户展示错误。失败时沿用旧记忆，没有就不注入。
2. **只做会话级记忆。** 按 session 隔离，不跨会话。分支会话从源会话继承一份记忆后各自演进。
3. **近期原文永远优先。** 记忆只补回已离开窗口的内容，不描述当前场景；与近期原文冲突时以原文为准。
4. **可运营。** 压缩 prompt 和关键参数（水位上下限、保底轮数、字数上限、模型、总开关）在运营平台可编辑、可发布、可回滚，改完无需发版。

## 已核实的现状（2026-11-10，基于 origin/dev 140ead48）

- 现有截断在数据库开轮 RPC 内按轮数执行（`apply_context_window_flood`，`max_context_turns=75`/`retain_context_turns=50`），窗口起点存 `experience.chat_sessions.context_window_start_turn`，只增不减，历史行不删除。
- 编辑/删除只允许最近 10 个逻辑轮，由数据库 `change_chat_message` 强制（P0424）。保底轮数大于 10 时，用户编辑永远碰不到已压缩区间。
- **开分支没有 10 轮限制**：前端允许从任意已完成回复开分支，`fork_chat_session` 只校验锚点是已完成回复，并按"最后 A 轮"继承。原方案"开分支只限最近 10 轮"的前提不成立，本任务按"可从任意位置开分支"设计，不改产品规则。
- AI 回复原文 = 正文 + 富回复尾部（`[choices]`/`[status]`/`[memory]` 面板）。shared 已有 `splitEditableReply` 能切出正文。可见的 `[memory]` 面板与本系统无关。
- 兜底模型来自模型目录 `fallback_model_id`，缺省 `deepseek/deepseek-v4.1-flash-1017`（OpenRouter）。

## Requirements

### R1 截断（替换旧策略，不保留兼容）

- 计量：只算对话正文字数——用户输入 + AI 回复正文（去掉富回复尾部）+ 本轮用户输入。角色卡 system、开场白、记忆块都不计入。字数 = 去掉空白后的字符数。
- 触发：窗口内总字数 > 高水位 U，且保底之外可移除的完整轮数 ≥ 最少可移除轮数。
- 切法：从窗口起点按完整轮逐个移除，直到 ≤ 低水位 L；最近"保底轮数"个轮次不可移除；不切进轮次内部；起点只增不减。
- 保底生效且仍超过 U 时允许超出，并记录 `floor_binding`。
- 旧的 `max_context_turns`/`retain_context_turns` 配置和按轮数的逻辑删除。

### R2 记忆生成

- 窗口前移与创建记忆任务在同一事务内完成。
- 后台 worker 领取任务，压缩范围在执行时现算：`(已覆盖到的轮次 + 1) ~ (窗口起点 - 1)`。
- 同一会话串行；超时租约可被重新领取；失败按指数退避有限重试。
- 范围过长时按轮次边界分块，逐块迭代，每块通过校验后单独写一个版本。
- 结果由代码校验，不合格重试一次，仍不合格丢弃并保留旧版本。
- 压缩模型默认跟随兜底模型，可在运营平台单独指定。

### R3 注入

- 读取最新记忆与生成准备并行，设短超时；失败、超时、为空都直接跳过。
- 渲染时去掉轮次标注，套上边界说明，放在角色卡 system 之后、历史之前。

### R4 分支

- 用新逻辑重写分支继承，删除按"最后 A 轮"继承的旧逻辑。
- 新分支继承一份记忆（覆盖范围必须早于锚点），再继承"记忆未覆盖的部分 ~ 锚点"的原文，此后两个会话各自演进。
- 从任意位置开分支都不能把锚点之后的剧情带进分支记忆。

### R5 运营平台

- 新增两个 managed config：
  - `story_memory_prompt`：压缩 prompt 全文（文本）。
  - `story_memory_config`：总开关、高低水位、保底轮数、最少可移除轮数、记忆字数上限、附带近期轮数、分块字数、压缩模型、温度。
- 草稿 → 差异 → 发布 → 回滚，走现有运营平台和 CLI，不另建页面。

### R6 监控

1. 任务成功率与 P95 耗时。
2. 校验拒绝率，按原因分类。
3. 同一会话连续失败 ≥ 3 次告警。
4. 空窗率：窗口已截断（起点 > 1）的生成中，没有注入记忆的比例。
5. 调参用：`floor_binding` 次数、每次截断移出的字数。

### 不做

向量检索、跨会话记忆、用户可见或可编辑的记忆、编辑触发重压缩、存量会话回填、把可见 `[memory]` 面板当记忆来源、规避记忆更新带来的一次缓存未命中、软水位预判。

## Acceptance Criteria

- [ ] 生成链路额外等待 ≤ 100ms：记忆读取与现有准备并行，用到时最多再等 50ms；人为让记忆读取超时或报错，生成照常完成，不出现用户可见错误。
- [ ] 每个截断周期 prompt 前缀只变化一次：超水位时先压缩、记忆落地后窗口与记忆同一轮切换；压缩失败时超过 U + (U-L)/2 才强制截断。
- [ ] 截断按正文字数生效：富回复尾部不计入；超过 U 时退到 L 以下（允许多出不超过一轮）；最近保底轮数永不移除；可移除不足时不截断并记录 `floor_binding`；起点只增不减。
- [ ] 窗口前移后，同一事务内存在待处理任务；worker 完成后新版本 `covered_end_turn = 窗口起点 - 1`。
- [ ] 任务失败（模型报错、超时、校验不过）时旧版本不变，按退避重试，连续 3 次失败有告警；进程重启或租约过期后任务能被重新领取。
- [ ] 校验覆盖：板块标题齐全、非空、无思考标签、不超过字数上限、未达上限时不得异常缩水；不合格内容不会被注入。
- [ ] 分支：从最近位置开分支，继承最新记忆与未覆盖原文；从早期位置开分支，只继承覆盖范围早于锚点的版本，锚点之后的剧情不会出现在分支里；两边后续压缩互不影响。
- [ ] 运营平台能编辑、发布、回滚 prompt 与参数，CLI 可用；非法参数（如 L ≥ U、保底 ≤ 10、prompt 缺占位符）在发布前被拒绝；发布后 5 分钟内生效，无需重启。
- [ ] 总开关关闭时停止生成和注入，截断照常。
- [ ] 开发完成后做基本测试：窗口计算、结果校验、渲染的单测；迁移在隔离 PG17 回放（结构、RPC 行为、分支）；用真实压缩模型跑一段样例故事，人工检查档案质量。

## Android/iOS 性能 P95 门禁

- 受影响页面：无页面加载变化（前端不改）。
- 受影响接口：`POST /api/v1/conversations/:id/messages`、`POST /api/v1/conversations/:id/regenerate`（多一次与准备并行的记忆读取、一次不等待的窗口前移写入）、`POST /api/v1/conversations/:id/branch`（RPC 内多复制一条记忆）。
- Android / iOS 页面加载 P95：不适用，前端不改。
- 接口 P95：目标为不退化——点击到首 token 的 P95 与派发前耗时 P95 不高于发布前同窗口；分支接口 P95 不退化。基线发布前从 Grafana 读取，当前无可见样本，不填数字。
- 数据来源与观测窗口：Grafana 客户端首 token 与后端派发耗时，按 release、型号、平台分组；取发布前 3 天与发布后等长窗口。
- 发布后验证：另核对记忆读取耗时分布与超时率（目标超时 < 1%）、窗口前移写入失败率。

## 已确认的决策（2026-11-10）

- 早期阶段（DAU 约 50），不做影子期和灰度，只保留一个总开关；上线即开启。
- 旧的按轮数截断全部删除，不准备回滚迁移。
- 存量会话不做特殊处理：第一次触发新截断时，记忆从第 1 轮自然补齐。
- 水位默认值（2026-11-10 用户要求调高后）：U=60000、L=40000（正文字数，用户最终确认），分块 40000，保底 15 轮，最少可移除 6 轮。每次截断约移出 2 万字（约 10 轮），分块不小于移出量，每个周期只改写一次档案。上线后看 `floor_binding` 和截断字数再调。
- 上线时正在进行的长会话会在第一轮被强制截断、记忆需后台补几分钟：用户确认接受，不做预热。
- 压缩模型后续由用户换成 Gemini 4，本次先用兜底模型参数。
