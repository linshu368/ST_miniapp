# 本地移动端性能验收与规划门禁

## 目标

本地运行真实前后端连接 Supabase TEST，以自动化性能证据约束后续功能开发、功能修改和问题修复。规划确定范围，完成时提交当前版本实测；不达标须调整并复测，或取得开发者针对本次结果的明确豁免。

## 用户确认与现状

- 2026-11-11 已确认：每个平台、每个受影响页面及接口、每个关键场景分别至少 20 个有效样本，P95≤2秒；不能合并平台或页面计算。
- 已确认 Android 使用 Chromium、iOS 使用 WebKit 本地模拟，报告明确标注模拟，不声称真机或 Telegram WebView 实测。
- 已确认不达标默认阻断，只有开发者明确豁免本次结果才可例外放行；沉默、之前的实施授权和 AI 自批无效。
- TEST 为 `zoqelpfhurwehlvypryl`；上轮本地应用在 TLS 校验开启时访问 REST 根入口返回 HTTP 200，只证明当时可连接。每次仍需目标、结构和权限预检。
- 实施前 ui-tests 是 Next dev＋mock API＋Chromium 两种尺寸，Trellis 只检查性能规划声明。现已新增独立实库采样与结果门禁；保留原功能验收环境，实测状态见 task.md。

## 需求

- R1：真实链路为本地生产构建前端→本地Backend→TEST Supabase REST→数据库，不能以mock历史API替代；保留现有UI功能测试。
- R2：双平台及冷文档/SPA、普通/长历史、首屏/深页等受影响关键场景分组。每组预定N≥20，固定算法与计时；失败、超时、重试、指标缺失必须保留，不补跑凑20次成功。
- R3：页面终点为真实内容可见且主要操作可用；普通接口覆盖队列、网络、内部重试、完整body和契约校验。SSE/异步接口必须规划首个可用结果/受理与最终完成两阶段，不能只测headers。
- R4：每次修改声明页面/接口/场景，公共helper、鉴权、数据库或配置改动展开消费者；未知范围不得自动不适用。
- R5：区分实测 passed/failed/incomplete 与人工 developer_waived；开发者豁免保留原始失败事实，并绑定本次代码、报告及精确范围。
- R6：start校验可执行计划，不要求未实现代码先出成绩；完成/归档/PR检查当前版本实测证据。变更使旧证据与豁免失效；finish清活动指针不代表验收完成。
- R7：专用虚构数据、运行清单、有限并发/速率/时长/容量；不清共享TEST、不改真实用户/运营配置、不触发真实模型费用。迁移仍走逐文件workflow，清理仅限本次创建记录。
- R8：保留原任务更严约束：绝对P95≤2000ms不能替代聊天新旧不退化、零缺失、正常回复不受影响等验收。
- R9：最终实施交付含采样器、报告判定器、Trellis/CI门禁和文档。测试机制本身有失败路径回归，不能仅靠说明文档认定完成。

## 验收标准

- AC1：两浏览器均连接指定本地应用与TEST；错项目/生产地址、mock API、dev构建、TLS关闭、缺迁移/凭证在采样前阻断。
- AC2：每必测组独立N≥20，nearest-rank P95≤2000ms。N=20取排序后第19项；2000ms通过、2000.001ms失败，不先四舍五入。
- AC3：缺平台、19样本、混场景、重复ID、缺body或页面终态、隐藏失败、摘要与样本不符、过期版本均不能通过。
- AC4：固定计划尝试中任一非预期业务/网络错误使组failed；采集故障/缺指标为incomplete。内部重试计同一逻辑样本；无请求缓存命中不生成0ms接口样本；复测完整新批次，旧失败批次保留。
- AC5：豁免含开发者身份、时间、确认来源、代码/报告摘要、组别、原因、风险、修复跟踪及期限；过期/撤回/跨版本/AI自批无效。豁免不改P95或measured_status。
- AC6：规划字段不完整start阻断；无有效结果归档阻断且不改变状态/目录/module知识；过期归档不能绕过。
- AC7：PR检查识别代码范围并重算证据，不要求不受信任PR持有TEST凭证；删除声明、遗漏任务或把产品改动伪装为docs-only均阻断。
- AC8：首批试点 `/characters`、`/chat/:id` 与大厅/会话详情接口；普通/长历史、首次/深页独立样本，聊天完整性及功能回归仍保留。
- AC9：报告含模拟标识、机器/浏览器、时间窗、代码/计划/数据摘要、样本及错误数、P50/P95/P99/max、阈值、结论和豁免，无密钥、签名身份、业务正文或真实用户标识。
- AC10：相关Python/TS回归、消费者typecheck、适用build/lint通过；清理失败保留精确清单，不能假报完成。
