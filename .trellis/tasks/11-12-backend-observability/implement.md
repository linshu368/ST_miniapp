# 执行计划草案

## 规划收敛

1. 对照 backend/shared 及消费者模块规范补齐影响清单，确认当前代码及重叠任务变化。
2. 逐入口、方法、client、provider、job 建覆盖清单，逐失败分支补错误码与消费者矩阵。
3. 核对全量日志峰值/字节预算、Railway 限额、现有 collector 能力；形成出口、缓冲窗口、保留期和查询延迟的可审批方案。
4. 完成 task.json mobile_performance 和 module_impact，向用户提交完整设计和验收审批。

错误码专项：以 docs/backend-error-code-review.md 为目录依据，将第 2—11 节条目及第 13 节每项差异映射到真实分支；矩阵补清单引用、目标/兼容公开码与状态、outcome/outcome_known、日志等级、Sentry 归属、消费者和发布/回退批次。按第 12 节核对 SSE/ACK/代理/媒体任务/后台例外；不把目标状态当当前事实，不强制把所有内部码公开到 shared。

策略专项规划：盘点 AlertEvaluation、Publisher、事故/outbox、投递过滤与既有指标/窗口设施；确定每条规则的权威执行方、通知所有者、事件作用域、分母/阈值、跨实例状态、去重检查点、迟到/重放及恢复方式。提交策略输入/决策/动作契约、配置校验与优先级组合规则、容量预算和生产启用范围，避免双重告警与并行状态源。

## 审批后执行

1. shared 错误契约和观测核心，兼容旧码及消费者。
2. HTTP 切面、Pino/Sentry 与基础记录输出，验证早退/异常、关闭可选插件和请求隔离。
3. DB、第三方 client 与业务方法边界，验证同步/异步、返回错误、timeout/abort、事务和响应流行为。
4. 分批迁移生成/SSE/媒体、支付/回调/对账、其他业务与后台脚本，逐批核对覆盖与旧日志收口。
5. 完整性、低侵入扩展、峰值与故障注入验证，落地 Quality Gate、规范和运行手册。
6. TEST 后分批发布，按 release 核对可检索性、真实状态、重复率和 P95，缺失或业务回退时停批并回滚。

错误码实施顺序：先登记 shared 公开契约和 backend 内部映射，保留旧公开码；再完成 frontend API/SSE、admin-client/CLI、Bot/代理及商户协议消费验证，逐批切换状态与公开响应。重点迁移支付建单原因拆分、模型 409/余额 402、鉴权依赖分类、模型测试超时 504、图片描述技术失败、支付冲突与免费额度状态细分。分批独立回退映射，保留已产生的真实业务事实。

策略专项执行：核心事件定稿后接入有界异步评估、类型化规则注册与模拟动作，再接入既有告警发布/投递链路并核对允许范围。先 observe 对照固定输入及完整窗口，再 TEST 核对 accepted/delivered/恢复，审批后按规则灰度 active；支持独立关闭动作与回滚配置，不改变业务或基础记录。聚合/持久化设施未确认的窗口规则不启用生产通知。

## 验证

错误码专项按清单第 14 节执行，覆盖第 13 节全部差异及第 12 节误判场景；断言实际 HTTP/流内码/ACK、outcome/outcome_known、等级、单次 Issue 和关闭日志告警时零通知。已恢复 attempt、未知提交和恢复耗尽需独立验证，正常业务拒绝不能误报技术失败，数据库/供应商故障不能误报用户参数/登录失败。运行 shared 既有相关测试与全消费者 typecheck，补录消费者人工场景和未验证风险。

日志告警开关：在 platform/config.ts 集中解析 LOG_ALERTING_ENABLED，默认 false，经 runtime-config 统一暴露。默认关闭时不启动该来源消费者、不评估/发布；投递 worker 同步按来源暂停其待投递/重试项，既有业务告警不受影响。实施前核对来源隔离契约，实施时同步 .env.example、README、架构和运维手册。验证未配置/false/true/非法值、observe/active、全部实例重启生效、在途边界和重新开启恢复；配置回退不得绕过关闭开关。

运行受影响的既有 backend/shared 测试、pnpm -r typecheck、适用 lint/build 与 pnpm lint:complexity。高风险新增测试随最终计划审批。独立执行计数核验日志，覆盖断网/挂起/崩溃/背压/重放、SSE 断连、支付结果未知、DB 错误返回及并发串线。

本地界面复用 ui-tests 的聊天、个人页/充值、图片、短剧和创作者场景。真实商户/供应商/平台检索与 Android/iOS 真机独立验收。当前文档阶段只检查规划文件，运行时代码验证随实施批次执行。

策略验证覆盖状态/等级/错误码组合、SSE 200 后失败、上游 401/429、取消、兜底成功、支付结果未知；核对同作用域分子/分母、最小样本和无流量/缺报不恢复。复现多实例重复、迟到/乱序、重放、静默到期、升级/恢复、坏更新保留有效版本、启动无配置、策略/动作挂起与拒绝、outbox 失败、队列满及自诊断防递归。验收计数分别记录原始事件、命中、抑制、accepted、delivered；人工验证 TEST 规则触发→持续失败去重→恢复，并演练独立停止通知与配置回滚。新增回归测试文件范围随最终规划审批。
