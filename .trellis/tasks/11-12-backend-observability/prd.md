# Backend-observability-and-error-contracts

## Goal

从请求、业务操作、数据库、第三方和后台任务的全量基础记录中重建执行链路，定位真实结果和原因。提供可复用、可插拔、低侵入的统一入口，统一错误码与实际响应语义，并建立后续功能接入门禁。

## Requirements

- R1 所有 HTTP 入口用统一切面记录安全来源、请求/响应摘要、耗时和实际终态，内部方法、DB 与第三方使用统一机制。
- R2 核心与 Fastify、Pino、Sentry 和业务目录解耦，其他项目可通过宿主装配复用。
- R3 请求、trace、span、父子操作和业务关联覆盖并发、重试、异步、回调、补偿与 SSE。
- R4 shared 统一定义错误码并迁移现有处理，覆盖所有业务域、模型供应商、支付商户和数据库。HTTP、业务码、日志与特殊协议语义一致。
- R5 当前记录点逐批收口，支持 Pino/Railway、Sentry 及后续插件，字段、策略、脱敏、缓冲与输出故障集中管理。
- R6 用户确认生产所有链路全量记录，优先保证终态与可排查。成功、失败、拒绝、取消、恢复和结果未知都覆盖；采样仅适用于额外诊断或可选输出。
- R7 全 backend 建立方法/入口/依赖覆盖清单，含直接调用、特殊协议、后台任务和生产脚本。
- R8 日志接入保持 frontend、数据库、第三方连接、交易、幂等、重试和流式协议正确，接口性能通过基线对照验证。
- R9 CI 门禁确保后续新增与修改功能接入统一日志及错误目录。
- R10 用户确认扩展低侵入，新增出口、公共字段和策略集中改基础设施，业务模块零修改；新增业务复用受控入口，补最少边界登记与必要语义事件。
- R11 整体设计及需要用户选择的方案经用户确认后实施。
- R12 状态码、日志等级、规范错误码、业务结果与耗时支持组合策略，覆盖后续告警、诊断选路及观测指标；规则/动作集中扩展，保持全量基础记录独立。告警优先级与日志等级分开，实际 HTTP、依赖状态及 SSE/后台终态不得混用。
- R13 策略支持单事件与明确口径的窗口评估、去重、静默/冷却、升级/恢复、影子验证、版本灰度及独立回滚。告警优先复用现有 Publisher/outbox；跨实例、重放、策略失败与通知投递均可追踪，不能改变业务执行或造成递归告警。
- R14 日志告警由环境变量 LOG_ALERTING_ENABLED 总控，默认 false，只有显式 true 才启用；不使用运营配置覆盖。关闭时停止该来源评估、新发布及待投递/重试项外发，保留基础记录和既有业务告警。开关随相关服务/worker 重启生效，已在途通知可能完成。
- R15 全局错误码按 docs/backend-error-code-review.md 处理：采用其模块目录、操作状态、日志等级、处理动作及协议例外，第 13 节差异逐项纳入迁移，第 14 节作为专项验收。技术设计不维护平行候选目录，旧公开码/状态经消费者兼容后分批迁移；告警建议仍受 R14 总开关控制。

## Acceptance Criteria

- [ ] 每个请求/作业可定位开始和唯一逻辑终态，每个业务/依赖操作及 attempt 有关联终态，以独立执行数核对可查询覆盖率。
- [ ] 404/500、框架早退、SSE 200 后错误、支付 ACK、超时和结果未知均保留正确语义。
- [ ] 并发不串线，重试/恢复可区分且原失败可查询，进程中断保持未知事实。
- [ ] Pino/Sentry/新模拟插件完成选路、去重、脱敏及故障隔离，关闭 Sentry 或详细采样时基础记录完整。
- [ ] 新增出口和调整公共字段/策略时业务模块零修改，新普通路由和既有 DB/第三方 client 自动覆盖。
- [ ] 峰值与约定故障窗口内全量记录可检索，查询延迟、缓冲、重放恢复满足批准阈值；缺失阻断发布。
- [ ] 消费者回归及适用检查通过，双平台/API P95 符合批准阈值。
- [ ] 门禁识别未登记错误码、绕过受控输出/客户端入口及关闭全部基础记录出口的配置。
- [ ] 固定输入验证状态码/等级/错误码/结果组合、SSE 200 后失败、上游凭据异常、取消、兜底恢复和结果未知的策略判定，新增规则/模拟动作业务模块零修改。
- [ ] 验证单事件/窗口口径、多规则组合、跨实例与重放去重、静默/升级/恢复、无流量和迟到；日志等级提高与诊断采样关闭不影响策略所需事实。
- [ ] 坏配置保留有效版本，影子/灰度/回滚可执行；动作超时、持久化失败、队列积压和策略自诊断不递归、不改变业务或基础记录，TEST 区分告警 accepted 与 delivered。
- [ ] 验证 LOG_ALERTING_ENABLED 未配置/false/true/非法值及 observe/active；默认关闭时日志告警评估/发布为零，待投递/重试项暂停，已有业务告警和全量记录正常。验证全部实例重启、重新启用及事故状态恢复，实施时同步环境示例和运维文档。

- [ ] 错误码专项逐项完成评审清单第 14 节，并将第 13 节全部差异追溯到分支、目标/兼容状态与公开码、outcome/outcome_known、日志等级、Sentry 去重、消费者验证及发布/回退批次；无证据项保留待核对，不能因设计对齐标记实施通过。

## Android/iOS 性能 P95 门禁

- 受影响页面包括大厅/角色、聊天、钱包/充值、图片/语音、短剧、创作者及其他 Backend 消费页面。
- 受影响接口为全部 Backend API 和出站路径。普通响应、SSE 首字/完整终态及媒体分开统计。
- Android、iOS 页面 P95 和 API P95 基线当前均无可见样本，保留 null。
- 目标提案为同平台/路由和相近负载 P95 相对回退不超过 5%，最终阈值随整体设计审批。
- 数据源拟为现有 Grafana/Faro、Sentry Metrics 与 TEST 对照。发布前后按 release/平台/路由观察两个完整 24 小时窗口，低样本延长观察。
- meta.mobile_performance 暂为 pending，待口径、阈值和验证方案完整后进入实施。

规划完成后同步填写 `task.json.meta.mobile_performance`：有影响使用 `required`，确实不影响移动端页面加载和接口性能时使用 `not_applicable` 并填写具体理由。门禁未完成时 `task.py start` 会阻断。
