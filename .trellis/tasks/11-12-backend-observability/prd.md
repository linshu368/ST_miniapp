# Backend 日志与错误契约整改

## 已确认范围（2026-11-13）

按核心与 HTTP、DB/第三方、生成与媒体、支付与后台任务、错误码消费者、告警与 CI 的顺序实施并分模块 commit。公开错误码和状态先保持兼容，验证消费者后再切换。

用户确认运行时日志由 Railway 捕获和查询。不新增日志存储、持久化出口、缓冲补传、部署资源或费用。LOG_ALERTING_ENABLED 默认 false，关闭时不匹配规则、不发送；开启后按配置匹配日志并通知。不引入窗口聚合、告警 outbox 或暂停/恢复协议。

## 要求与验收

- HTTP、DB、供应商、生成、支付和后台任务记录安全摘要、耗时和链路上下文；并发上下文隔离，操作终态不重复。
- 保留 Pino/Railway JSON 与开发 pretty；正常基础事件不受诊断 LOG_LEVEL 过滤。可选遥测故障不能改变业务结果。
- 不输出凭证、完整 URL query、个人信息、SQL 参数、用户内容或大正文。原始错误以 { err } 交给安全序列化器。
- HTTP/SSE 实际状态、生成 attempt、业务结算及任务交付分别记录；HTTP 200/回调 ACK 不等于业务成功。
- 按 docs/backend-error-code-review.md 第 13 节核对原因、生产者与消费者；保留无法确定原因的兼容分支，不凭字符串猜测资金结果。
- 默认关闭、规则命中、规则不命中、超时、发送失败、并发容量和无递归均可重复验证。
- 每批执行相关测试、typecheck、lint、复杂度和 diff 检查。跨包契约改动执行 shared 测试及全部消费者 typecheck。
- Railway 查询与真实 Android/iOS/API P95 发布后验证单独记录；无真实样本不得宣称通过。

## 2026-11-14 补充：Railway 业务定位字段

用户确认直接补充现有规划并修改代码。请求、业务、DB 和供应商日志除链路 ID 外，应能通过用户、模块、角色卡/创作、短剧和会话定位故障。

- 保留 `request_id/trace_id/span_id`；增加受控 `business_module`、`user_id`（内部 UUID）、`telegram_user_id`（已验签身份）、`session_id`、`character_id`、`creation_id`、`drama_id`、`video_id`，按实际可得信息输出。匿名/鉴权失败不伪造用户，解析身份前的日志用同一 trace 关联后续事件。
- 角色创作当前以 `character_id` 为主键；创作操作的 `creation_id` 与它相同，不虚构独立项目 ID。聊天会话 ID 与客户端播放诊断会话不是同一概念，不混用。
- HTTP 终态（含失败/断开/SSE）能看到本次已取得的关联信息；子调用继承，独立请求/后台任务及并行业务作用域不得串用户或对象。
- Railway stdout JSON 实际保留这些字段，不被白名单二次过滤或统一替换成 REDACTED；不输出姓名、昵称、邮箱、正文、凭证、initData、签名 URL 或任意 DTO。新增标识不进入告警通知、Sentry 或指标标签。
- 不为日志新增数据库查询、外部调用、存储、业务重试或公开 API。记录的请求目标 ID 不代表授权成功；错误码/结果仍是权限与业务结果的依据。
- 扩展既有日志/HTTP/用户缓存测试，覆盖实际 Pino JSON、并发与共享身份查询、首次创建、身份失败、非法 ID、SSE 和敏感值过滤；真实 Railway 检索留待部署后验证。
