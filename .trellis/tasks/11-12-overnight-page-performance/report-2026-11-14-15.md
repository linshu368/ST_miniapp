观测窗口：**2026-11-14 00:00:00—2026-11-16 00:00:00，Asia/Shanghai（北京时间）**，完整48小时，结束边界不包含在内。对应 UTC：`2026-11-13T16:00:00Z ≤ timestamp < 2026-11-15T16:00:00Z`。

分别统计14日（周六）、15日（周日）及两天合并结果。报告格式与指标口径参考[原报告](./report.md)，本次重新通过 Grafana、Sentry、Railway MCP 采集，未复用旧窗口计数。两天P95来自整个48小时合并样本的独立查询，**不是每日P95的平均数**。Railway资源72小时汇总与主窗口不同，单独注明。

## 结论

- **聊天、会话列表冷启动和Android主页面仍应优先跟进。** 两天聊天导航P95为 Android **4.57 / 781**、iOS **3.51 / 128**；剧场列表 **3.42 / 355**。以上单元格均为秒 / N，四个分组均达到100个样本。
- Android从 **5.96s / N251 → 4.14s / N530**；iOS从 **6.03s / N39 → 2.66s / N89**，iOS两天单日仍低样本
- Grafana页面终态 **ready=7319、error=58、page_left=197**；卡住 **434次**。已知成功/错误终态中错误占比为 **58/(7319+58)=0.79%**，不是全量用户失败率。聊天贡献30次error；会话列表153次卡住、大厅135次、聊天66次。卡住可随后成功，不能与error相加。
- **客户端失败与服务端错误均有实收。** Grafana逻辑API记录 **252次timeout**；Sentry `api.request.duration`独立记录 **974次timeout**（大厅252、聊天详情183、增长提示117），不可相加。Railway固定48小时 **337662次HTTP、43次5xx（0.0127%）、1074次4xx（0.32%）**；5xx的18次发生在14日、25次发生在15日，主要涉及会话及首token回报。
- Sentry固定窗口有 **229次error/fatal**，包括聊天详情AbortError131次、TelegramGameProxy接收事件异常35次、ResizeObserver27次、首token观测写入失败11次、Worker脚本加载失败4次、`crypto.randomUUID`不可用2次。慢请求告警5997次不等于5997次页面打不开。
- 低样本长尾仍需保留：Android创作数据导航 **8.88s / N20**、角色编辑 **8.19s / N18**；短剧详情 Android **5.37s / N34**、iOS **6.18s / N9**。服务端角色润色P95约 **99.79s / 估计N168.0**，属于长业务操作，不是页面加载或聊天首字P95。

## 口径与限制

1. 主表沿用 Grafana Faro：`engineering_v1`、`production`、全部release、成功 `ready` 且 `foreground`，主指标为 `st_page_navigation`。单位秒，单元格为 **P95 / N**。保留查询返回的聚合值，不将每日分位数平均。
2. **N<100均为低样本线索**；—表示没有对应成功样本，不写0。极小正值保留三位小数。根入口及部分业务页无样本，不能据此断言没有访问或没有故障。
3. 失败/卡住使用全部平台及全部导航类型，范围不同于Android/iOS成功前台P95；不得用主表N作失败率分母。started=7547、terminal=7574，存在窗口边界、迟到或缺报，不直接计算缺报率。
4. `st_page_launch`为文档开始到内容可用；`st_page_ready`为挂载到内容可用；Sentry `startup.shell_ready.duration`为壳可展示。三者不互换，也不以自动pageload span代替内容ready。
5. Sentry SDK distributions没有与Grafana相同的visibility筛选，覆盖、接收及聚合也不同。只作交叉证据，不混合P95或N；异常次数使用本窗口事件聚合，不使用issue生命周期累计数。
6. Sentry实际执行查询均保留两个固定timestamp条件。Metrics的外层7d只是容纳查询的上界，实际结果同时受48小时/单日谓词约束。最初一条自然语言查询因格式校验失败已弃用；报告只采用成功返回且边界已核验的查询。
7. Railway请求统计采用**完整落入每个本地日的2小时桶**，每个24小时12桶、48小时24桶，无边界残桶；4xx分四段12小时明细独立校验、5xx固定窗口明细43条，均未触及500条上限。只保存脱敏聚合，不保存原始日志。
8. Railway响应时间是各2小时桶P95，不能平均成全窗口P95。Prometheus服务端P95先合并窗口内histogram buckets，再计算近似分位数；N为`increase`外推估计，不是整数原始请求数。
9. production标签不等于已逐事件核验正式域名；Grafana页面投影无Origin维度。额外尝试按`app_release`分组未返回可用标签，未获得可信的前端release拆分，不能把14/15日差异归因某次部署。
10. 后台、混合可见性不进入页面主表；遥测关闭、丢报、JS尚未启动即失败的访问不能据此排除。告警受覆盖、节流、投递影响，不能代替页面终态。
11. 保留原报告27个登记业务页面与根入口记录；Admin仍无本次同口径页面P95。未查询数据库业务行、Replay或用户正文，未做真机逐事件复现。
12. 原报告约15小时，本次48小时，版本、流量与样本构成不同；不按两份报告的总数或两个独立P95直接判断优化收益。单日差异亦不构成因果证明。
