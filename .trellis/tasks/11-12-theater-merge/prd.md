# 剧场合并放映、底栏拆出对话

## Goal

短剧模块用户反馈平平，「放映」(`/watch`) 和「剧场」(`/dramas`) 两个一级页面合并为一个：视频流并进剧场列表。底栏空出的位置给「对话」(`/chats`)，秘境（角色大厅）保持居中凸起。

用户 2026-11-12 在三套交互稿中选定 B「点开即放映」；剧场列表页按 B 稿做，放映页与底栏在现有 UI 上微调，不照搬 demo 的样式。

## 决策依据（Loki Faro 近 7 天）

- 放映页 613 次访问，开播约 1500 次（自动播 838 + 上下滑 650）
- 剧场页 537 次访问，点封面开播仅 115 次
- 118 部剧中 67 部只有 1 集
- `/chats` 601 次访问，和原两个短剧页同量级，是底栏外最高频的独立页面

## Requirements

1. 底栏五项：剧场 `/dramas` · 对话 `/chats` · 秘境 `/characters`（居中凸起）· 创作 · 我的。样式沿用现有底栏，只换入口和新增对话图标。
2. 秘境入口固定到 `/characters`，不再记忆「发现/对话」最后栏目；角色模块顶部去掉「发现 | 对话」切换，每页只显示自己的栏目名，其余（创作角色按钮、新手提示）不变。
3. 剧场列表（B 稿）：
   - 搜索栏下方新增「随便看看」条：叠放三张封面 + 「从精选开始连播 · 上下滑换剧」+ 播放钮，点击进入放映，按全部短剧精选顺序连播，从上次放映停留的那部开始。
   - 点剧卡封面进入放映（不再进详情页），上下滑按点击时的列表顺序（当前分类/搜索/排序）换剧。
   - 从放映返回剧场时，列表停在最后看的那部，并用香槟金描边闪一下。
   - 「接着看」和追剧库行仍进详情页（按集续看）。
4. 放映页（`/watch`）保留现有播放器与顶栏，只加左上返回按钮回剧场；不再出现底栏。
5. `/watch` 地址、埋点路由、Telegram 竖滑接管、Cloudflare 播放实验不变；旧链接直接打开 `/watch` 仍按全部短剧连播。

## Acceptance Criteria

- [ ] 底栏五项顺序与高亮正确；在 `/chats` 时高亮「对话」，在 `/characters` 时高亮「秘境」；重复点当前项回到顶部。
- [ ] 剧场点任一封面进入放映，首部即点击的剧；上下滑顺序与点击时列表一致；分类/搜索下点击只刷该结果。
- [ ] 「随便看看」从上次放映停留处开始，顺序为全部精选。
- [ ] 放映返回剧场后，最后看的那部在可视区内并闪金边一次；没离开首屏时不跳动。
- [ ] 放映页全屏无底栏，返回、追剧、搜索、观看完整短剧、详情返回放映均可用。
- [ ] 秘境顶部只显示「发现」，对话页只显示「对话」；聊天返回来源栏目不变。
- [ ] typecheck / test / lint / build 通过；`@drama`、`@roleplay` ui-tests 回归。

## 追加需求（2026-11-13）：对话成为老用户落地页

用户决定：「接着之前的角色对话」属于对话页，不放在秘境；有对话记录的用户打开小程序直接进对话。

1. 冷启动 `/`：本设备记录过「有对话记录」的用户跳 `/chats`，其余仍跳 `/characters`。深链（支付回流、邀请）行为不变。
2. 秘境顶部「接着聊」卡删除；对话页列表第一行即最近对话。
3. 对话页作为落地页时：启动框架有对话页骨架并走早期原生 ready；列表结算后放行次要请求（不等 8 秒兜底）。

验收：带 cookie 打开 `/` 落 `/chats`，不带落 `/characters`，Telegram 启动参数随跳转保留；读到会话列表（total>0）或会话详情（message_count>0）后写 cookie，列表为空时清除。
