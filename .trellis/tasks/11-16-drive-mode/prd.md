# 剧情模式：四档剧情主导权

## 背景

用户反馈“需要玩家主导事件，模型太老实”。根源在主体模板 `system_instructions` 第一层“绝对防抢话”：它把“不替玩家说话/决定”和“不主动引入人物、事件、转折”混在一起，并且优先级高于用户偏好，任何“让角色主动”的偏好都会被压住。

## 需求（用户已确认，2026-11-16）

1. 在对话页「回复偏好」抽屉最上方新增「剧情模式」，四选一，全局（所有对话通用）。
2. 四档按“谁可以开启新的剧情线”逐级放开（id / 按钮名）：
   - `follow` 我来带（**默认**，2026-11-16 用户改定：最接近旧版 v13 的防抢话，影响面最小）：剧情只听用户的，角色只反应。
   - `active` 等 TA 撩：角色有自己的心思，会主动开口、提要求、出手。
   - `plot` 来点意外：除角色主动外，剧情会出新事件、新人物、转折。
   - `novel` 替我演：用户定方向，连用户角色的言行也一起写。
3. 共同底线（写在主体模板，任何模式都不能突破）：用户写下的言行一律成立；关键决定（表态、改变关系性质、重大或不可逆行动）只能由用户做出，替我演也一样；不写与用户输入矛盾的用户心理；剧情正文结尾停在用户能接话的地方。
4. 偏好分两层：用户**手写**的“我的偏好”是真实需求，高于共同底线和剧情模式；界面**勾选**的回复风格是弱偏好，低于剧情模式。
5. 界面：一排四个按钮 + 上方两色渐变线（香槟金“你来带”→ 玫瑰粉“角色来带”，同亮度同饱和，四个等大点标位置），下方一句白话说明。不出现“AI”字样，不加“推荐”角标。
6. 剧情模式的名称、说明、规则由运营平台维护；模型每次只看到所选的一档。

## 约束

- 不改变富文本协议、计费、模型路由。
- 配置缺失或损坏时退回上线前行为（保守规则），不能让槽位空着或原样发出占位符。
- 主体模板缺少 `{{DRIVE_RULES}}` 而剧情模式已配置时必须告警（回复风格曾因占位符未注入而静默失效 342 个用户）。

## 验收标准

- 选择任一档后，下一轮生成的 prompt 中 `{{DRIVE_RULES}}` 被替换为该档规则；未选、已停用、未知 id 一律回落默认档。
- 生成偏好 GET/PATCH 返回启用档位的公开字段（不含规则正文）；PATCH 只接受启用档位。
- 每轮在 `chat_history.rich_reply_metadata.drive_mode` 记录实际使用的档位。
- 390×844、320×568 下抽屉布局正常，切换后刷新仍保持选择。
- 离线评测（虚构对话、主力模型、LLM 评审抽样）：前三档替用户说话/做决定的比例不高于现状；替我演替用户做关键决定接近 0；同一句“继续”的推进程度逐档递增；富文本解析成功率不低于现状。
