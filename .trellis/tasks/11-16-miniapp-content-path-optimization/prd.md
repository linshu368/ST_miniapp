# MiniApp 内容链与适度客户端缓存

用户授权按 code-grounded-optimization-design.md 优化，并补充“可以适当补充客户端缓存”“修改后不需要启动本地UI验证”。

## 范围与验收

- A：会话页只读已缓存的大厅摘要，无快照不拉全量大厅；补缺详情等待关键列表结算并使用 normal 槽，保留按会话版本读取。
- 缓存：复用现有公开摘要 storage key/TTL，校验损坏/过期数据；详情仅在既有用户+会话 Query key 中短期内存复用。禁止持久化私人列表/正文、钱包、权限、支付和个人推荐。
- B：仅分组只读 RPC 的自身期限及稳定依赖超时码映射已有503/folders_unavailable；未知错误和鉴权拒绝不伪装。summary失败/超过短预算不拖主体，真实取消下游。
- C：自动open/resume总预算1500ms，手动refresh/undo及手动兼容open仍5000ms；旧批次/公开头降级和幂等意图保持。
- 复用既有并发3槽、首屏critical、ready时刻、日志/脱敏；无迁移、无线上写入、无新依赖。
- 类型检查、单元/路由/契约测试、构建、日志与复杂度检查通过。按用户指令不启动本地UI/Playwright，记录未验页面交互。
- D预热/私人持久快照及E缓存头需要发布后证据，不在本轮无证据叠加。A/B/C先做隔离本地候选，发布仍按原设计门禁。

## 最终执行约束

用户在验证期间明确要求“停止相关本地测试，主要完成修复内容”。收到后停止追加本地测试；当时启动的测试已自行结束，未发现仍运行的相关测试进程。保留此前实际结果与全量后端未通过项，不以定向通过替代全量结果，不再为了收齐检查启动测试或UI。
