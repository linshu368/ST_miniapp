# 角色卡深度体验计数接入大厅

## Goal

把角色卡的真实深度体验次数累加到大厅已有的点赞展示数中，让一张卡被用户认真体验过的次数能被看见，同时不把聊天历史扫描放进大厅请求路径。

## Requirements

- 按用户 × 角色卡，以连续聊天消息间隔超过 30 分钟切分 session。
- 同一 session 内超过 20 轮，也就是至少 21 轮，计为 1 次深度体验。
- 结构化聊天记录按 `(session_id, turn_index)` 去重，重生成不重复计数；旧的无 session 记录按物理行计轮。
- 深度体验次数累计保存，统计刷新失败时继续使用上一版摘要。
- 大厅显示的 `like_count` 继续包含角色卡点赞和回复点赞，再加深度体验次数。用户点赞状态仍只表示用户自己的角色卡点赞。
- 统计只在现有大厅每日刷新任务中执行，使用已有专用数据库连接。大厅和社交批量接口只读取按角色的摘要，不扫描 `chat_history`。
- 首版不新增前端字段和单卡请求，复用现有社交批量接口及卡片展示。

## Acceptance Criteria

- [ ] 21 轮计 1 次，20 轮不计，两个合格 session 计 2 次。
- [ ] 间隔恰好 30 分钟仍属于同一 session，超过 30 分钟才切新 session。
- [ ] 同一逻辑轮的多个 revision 只计 1 轮，旧记录口径可重复计算。
- [ ] 社交 RPC 返回的 `like_count` 等于角色卡点赞 + 回复点赞 + 深度体验次数，其他字段语义保持不变。
- [ ] 无摘要的角色卡按 0 计，最多 40 张批量查询保持有界；读路径执行计划不触碰 `experience.chat_history`。
- [ ] 后台刷新成功覆盖摘要，刷新异常、超时或空结果保留上一版摘要，不阻断大厅和社交接口。
- [ ] 运行迁移回归、Backend/Shared 相关测试、typecheck 和日志门禁。

## Android/iOS 性能 P95 门禁

- 受影响页面：无新增页面加载路径，角色大厅复用既有社交批量请求。
- 受影响接口：`GET /api/characters/social`、`GET /api/characters/:id/social`、`PUT /api/characters/:id/like` 的摘要读取部分。
- Android 页面加载 P95：不适用，页面请求数量和前端等待链不变。
- iOS 页面加载 P95：不适用，页面请求数量和前端等待链不变。
- 接口 P95：当前没有可见生产基线，基线记录为 null；目标为不超过 1200ms。
- 数据来源与观测窗口：发布前后使用 Railway HTTP 终态及同一生产版本的 `character-social` 日志，在至少一个完整日窗口比较批量社交请求 P95。低样本时标记低样本，不补零。
- 发布后验证、无可见样本/低样本及不适用说明：若生产样本不足，保留 null 基线并记录样本量；通过 EXPLAIN 和真实批量接口确认摘要表索引读取，确认没有历史聊天扫描。

## Logging integration

复用现有 `runObservedJob('lobby_ranking_refresh', ...)`、`lobby_ranking.completed/failed/skipped_*` 和 `character-social` 请求终态日志，不新增日志存储或告警规则。刷新成功日志增加有界的摘要卡数/深度体验总次数，失败与超时沿用原错误投影；不记录用户、角色正文、聊天内容或 session 明细。
