# Design

Inspected wallet listSpending, wallet-mapping, shared WalletSpendingRecord, spending page, video submit/terminal invalidation, real production reserve/debit/publish function catalog, and current repository/UI fixtures. Confirmed reserve reference is omitted; live helper is bonus-first and publish rejects missing debit/refunded tasks. User confirmed actual deduction.

Reuse existing billing wallet_ledger and optional main_delta/bonus_delta/source_label/refund_of fields; no new DB key/object or wallet DTO field. Extract media ledger reads from oversized wallet repository into a private wallet-spending helper, retaining separate100-per-voice/image limits and adding video100. Run independent reads concurrently, each with5s abort deadline, no retries. Existing LLM and LLM-refund reads stay unchanged. No write or authority change in spending.

Video debit ID is video:<attempt ref>, refund is video-refund:<attempt ref>, with ledger ID fallback, so same-attempt rows cannot collide. Preserve positive magnitude charged_amount convention; source_label=original-refund marker and refund_of identify the refund. UI uses these existing fields for plus sign and shows signed main/bonus deltas when present. Do not silently net away debit/refund. Do not accept share rewards/recharges/other users as consumption.

Reliability: query failure propagates existing error instead of showing partial history. Bounded reads keep capacity controlled; concurrency adds no state. External calls bounded5s, no retries/transactions/locks/compensation needed because read-only. Existing wallet invalidation covers submit and terminal; no duplicate polling or wallet rewrite. Coordinate Backend optional source-field/ledger reader first and Frontend cover/sign consumers next, no migration/backfill. Existing open pages need refresh for the new renderer. Roll back reader/renderer independently; ledger facts unchanged.

Reuse HTTP observation/DB transport and sanitized {err}; no logging of amounts, ledger metadata, tokens or business content. No new alerts. Baselines null; /profile/spending Android/iOS visual target2000ms, spending API800ms, compare before/after24h by platform/release/route, N<100 extend72h. Local fixture is not production P95.

## R2V quote correction

Reuse existing video API request helper module and shared input-mode type. Extract mode selection into a pure helper: required_reference alwaysr2v for quote, optional_first_frame usesi2v only with reference, optional_reference usesr2v only with reference, none remains t2v. The cover scope below enables generation when a current cover is available and prepares its explicit reference before submitting. No production config/price edit, extra endpoint, provider call for quoting or new polling. Unit matrix covers all modes with/without image. Add studio/quote to performance/logging scope; retain studio ready1500ms target, no visible baseline.

## Cover reference implementation

Expose existing conversation source_work_id as an optional nullable shared DTO field, no DB column/migration. On generation only, use lib/api React Query fetchQuery for a source-work cover, or the selected retry/latest ready artifact cover already in authorized conversation data. Never select another conversation/global asset. Download only that trusted API-supplied cover with bounded HTTPS fetch, stream limit20MiB, then reuse existing image payload validation and authenticated reference-upload mutation. Submit the returned explicit reference_artifact_id, preserving existing authorization/idempotency/billing. No implicit reference substitution inside billing or server attempt lookup. Manual image wins; an in-progress/failed manual upload is not silently replaced. Reject missing/broken cover before quote submit/paid task. Preserve user draft and show actionable errors. Quote continues existing configured price matrix and is independent of cover download; no supplier call for pricing.

No added initial page query: resolve cover only on explicit Generate, use existing Query cache for work metadata. New reference write reuses existing E reference upload owner/timing/lifecycle, no new data property. No automatic retry; partial unused upload follows existing unused-reference lifecycle, never charge to recover it. New shared field requires shared tests and all-consumer typecheck. Legacy Backend without source_work_id can still use existing message covers, otherwise requires manual upload.
