## 1. 原则

1. **我们提供零件和骨架，作者填内容。** 状态栏不限于人物：任务、背包、修仙境界、经营数据都用同一套零件拼。限制只为保证能解析，不限制题材。
2. **格式归代码。** 每轮发给模型的规则全文由代码按模板生成，版本受控。
3. **渲染只看输出，不查模板。** 每种零件的写法本身可区分（`68/100` 是进度条、`45%` 是百分比、`暧昧（3/5）` 是阶段）。作者改了、删了状态栏后，历史消息照样显示；渲染路径不多一次查询。
4. **逐行独立解析。** 一行写歪只影响这一行，退化成普通文字。
5. **外层不变。** 继续用 `[status]…[/status]`，复用别名、全角括号、拆围栏、编辑保护与历史尾巴处理。

## 2. 谁来定义、能定义什么

### 2.1 已定决策（2026-11-19 用户）

- 创作者建卡/编辑卡时作为一个栏目插入，状态栏跟着角色卡走。
- **玩家也能改（2026-11-19 追加）**：聊天页工具箱"对话设置"里加"状态栏"模块卡（在"我的人设""补充设定"之后），在预览卡上点点点改；只对自己、只对这张卡，下一轮生效，可"恢复作者的版本"。玩家侧没有 AI 生成。全局开关（回复偏好里的"状态栏"）保留。
- **编辑入口定为"预览卡上直接点"**（用户选定，列表改法放弃），创作者和玩家共用同一个预览卡和编辑弹层。
- 示例全部成人向（恋爱、情欲升温、调教、后宫、偷情、女性向），不做冒险类。
- 角色卡创建时要求写状态栏，所以新卡基本都有初始状态栏；没有状态栏的旧卡用"自动"兜底。
- 变化量（+3）全部由大模型写，代码不计算、不校验。
- 状态栏规则完全由代码生成，运营平台不能再改这部分文案。
- 状态栏输出写多长都可以（默认折叠）；零件默认不带"N 字内""最多 N 条"之类限制，作者想限可以写在说明里。
- **（后续定）正文模型完全不管状态栏，状态栏单独走一个模型、玩家点"更新"才生成，显示在聊天页常驻的状态面板里**，见第 6 节。正文的每轮系统指令里不再有状态栏规则，原来"规则长度"的顾虑随之消失。
- 平衡原则：玩法多样 vs 创作门槛。

### 2.2 降低创作门槛（玩法多，但要学的少）

| 层     | 作者要学什么                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------ |
| 直接用 | 栏目默认放一套起步模板，或从官方示例（恋爱、情欲升温、调教、后宫、偷情、女性向）里选一套，改名字就能用 |
| 改内容 | 每项只填三样：名称、类型（4 选 1）、说明（可不填）                                                     |
| 换样式 | 在类型里点缩略图换样式，编辑时实时预览                                                                 |
| 分区   | 进阶：加【场景】【背包】这类分区；分区可设"每个\_\_\_各一组"                                           |

作者面对的只有 **4 个类型**，样式是第二层且有默认值：

| 类型 | 样式（加粗为默认）                | 设置项                                                               |
| ---- | --------------------------------- | -------------------------------------------------------------------- |
| 数值 | **进度条** / 百分比 / 星级 / 数字 | 进度条：上限（默认 100）；星级：满星数（默认 5）；数字：单位（可空） |
| 文字 | **一句话** / 标签 / 一段话        | 无                                                                   |

每项可选写"说明"；整个状态栏可选写"整体说明"。

### 2.3 结构与上限

```
状态栏（随角色卡保存；玩家可在工具箱里覆盖成自己的）
├─ 整体说明（可选）
└─ 分区 × 1–4（默认 1 个、无标题）
   ├─ 标题（可带 emoji）
   ├─ 方式：固定 ｜ 重复（每个___各一组，最多 1–3 组）
   └─ 项目（全卡 ≤12）：名称（≤8 字，可带 emoji）、类型+样式、说明（必填）、开局值（可选）
```

**说明必填**（2026-11-19 用户强调：字段不定义好，AI 根本不知道输出什么）。写法见 2.5。

上限（创作者和玩家完全一样；2026-11-19 用户确认玩家在工具箱里添加也要有上限）：

- 项目最多 12 项（超了"加一项"提示"最多 12 项，先删掉一项再加"）；名称最多 8 字；每条说明最多 200 字，弹层里显示"n / 100"。
- 12 项 × 100 字基本保证含义块不超 1200；保存时再用同一个生成函数核一次总量，超了不让保存，提示"删掉一些项目，或把说明写短一点"。
- 玩家只看到"已用 N / 12 项"和说明字数。

篇幅上限（编辑器用同一个生成函数实时算）：

- 状态栏定义（整体说明 + 各项说明）合计 ≤ 1200 字（常见 250–460 字），作为状态栏模型输入的一部分，见 6.2。

| 百分比   | `45%`、`45%（-10%）`                  | 细条 · 大号 45% · ↓10%                   |
| 星级     | `★★★☆☆`                               | 实心/空心星                              |
| 数字     | `1200金币`、`1200金币（-300）`        | 大号数字+单位 · ↓300                     |
| 一句话   | `微醺`                                | 短的两列（名称 \| 内容），长的自动占整行 |
| 标签     | `紧张、害羞、期待`                    | 一排胶囊                                 |
| 一段话   | 一段话                                | 整行，名称在上                           |

### 2.5 说明怎么写（示例、AI 生成、AI 润色都按这个）

名称只是标签，模型靠说明才知道这一项写什么、怎么变。每条说明通俗、直白、具体，按三句写：

1. **这是什么**：谁的、记的是什么。
2. **怎么变 / 写什么**：按样式写到位——
   - 进度条、百分比、数字：什么情况涨、什么情况掉、一轮最多变多少（或到多少会怎样）。
   - 星级：什么情况加星、减星，满星会怎样。
   - 分段条：剧情里发生什么才往前走一格，会不会倒退、能不能跳级。
   - 一句话：写哪些内容、写多细（比如"从外到里写清楚"），什么时候要更新。
   - 标签：写哪一类词、几个，举两三个例子。
   - 一段话：写什么、用谁的口吻、第几人称。
   - 打勾清单：列什么、几条、什么算完成、什么时候加新的。
   - 普通列表：列什么、什么时候加、什么时候删。
3. **特殊规则**（可选）：比如"到100%会失控""不会倒退""心结没解开前每轮最多涨3"。

不合格的例子：`好感度：好感` / `衣着：她的衣服` / `心情：心情`——模型只能乱猜。

**AI 一键生成 / AI 润色说明**

- 生成：AI 必须给每一项按上面三句写说明；输出结构化结果，由代码校验。
- 润色：作者只写了名称或粗糙说明时，"AI 帮我写"（单项）/"AI 补全说明"（整栏，只补缺的）按同一标准改写；名称、样式不动；结果先给作者看，可恢复上一版（沿用现有 AI 润色的交互）。
- 代码校验（不合格让 AI 重写一次，仍不合格就标出来让作者自己补）：
  - 说明非空，且不少于 8 字；不能只是名称的重复。
  - 进度条、百分比、数字的说明里要同时出现"涨/升/加/增"类词和"掉/降/减/少"类词。
  - 分段条的说明里要写到"往前走/进入下一阶段"之类的条件。
  - 含义块合计 ≤ 1200 字，超了先让 AI 精简。
- 编辑器：缺说明的项在预览卡下方提示"有 N 项还没写说明"；创作者有"✦ AI 补全说明"，玩家没有 AI，弹层里按样式给出写法提示，说明不填不能保存。

## 4. 解析规则

外层定位沿用现有 `[status]` 解析。中间正文：

1. 含 `<details>`/`<summary>` → 走旧解析（旧消息、模型写回旧格式都能显示）。
2. 否则按行切分（≤80 行，每行截到 300 字），去掉空行和残留围栏行，逐行按顺序判断：

| 顺序 | 行类型                                 | 正则（单行、锚定、有界、无嵌套量词）                                                                                             |
| ---- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 分区标题                               | `^(?:【([^【】\[\]<>\r\n]{1,20})】\|#{1,4}[ \t]{0,3}([^#\r\n]{1,20}))$`                                                          |
| 2    | 清单条目                               | `^(?:[-*•][ \t]{0,3})?(?:\[([ xX✓√])\]\|([☑✅✔☐□⬜✗✘]))[ \t]{0,3}(\S.{0,200})$`                                                  |
| 3    | 字段（先去序号、列表符号、`**加粗**`） | `^(名称字符{1,12})[：:][ \t]{0,3}(.{0,280})$`，名称字符 = 非 `：:【】[]<>`、非标点、非换行；值为空 → 小标题（清单/列表的名称行） |
| 4    | 列表条目                               | `^[-*•·][ \t]{1,3}(\S.{0,200})$`                                                                                                 |
| 5    | 其余                                   | 备注行，原样文字                                                                                                                 |

字段值按顺序判零件（先把全角数字、`／`、`％`、`＋`、`－` 换成半角）：

| 顺序 | 零件   | 正则要点                                                                           |
| ---- | ------ | ---------------------------------------------------------------------------------- |
| 1    | 进度条 | `^数/数(（±数%?）)?$`，上限 > 0；比例截到 0–100%，按 5% 取整（21 档）              |
| 2    | 百分比 | `^数%(（±数%?）)?$`                                                                |
| 3    | 星级   | `^[★⭐]{0,10}[☆]{0,10}$`，合计 1–10 个                                             |
| 4    | 阶段   | `^非数字开头的文字{1,12}（n/m）$`，2 ≤ m ≤ 10，1 ≤ n ≤ m                           |
| 5    | 数值   | `^数 单位{0,4}(（±数）)?$`，需有单位、变化或 ≥3 位数（"26" 当文字，"26岁" 当数值） |
| 6    | 标签   | 按 `、`/`｜`/`\|` 切出 2–12 段、每段 ≤10 字、整句无句读标点                        |
| 7    | 文字   | 其余；≤12 字为短文字，更长为描述                                                   |

**缺 `[/status]` 时的恢复**：中间每一行都是规范行（分区/字段/清单/列表）且至少一项时才恢复；混进一句散文就不恢复，交给现有 `strip-orphan-close` 去掉孤立标签行，其余按正文显示——不吞正文、不露标签。

原型：会话 scratchpad `status-v2/parse.mjs` + `test.mjs`，7 组用例全过：28 个值的零件判定互不混淆、任务型完整示例、人物型 + 跑偏写法（列表符号/加粗/半角冒号/全角数字/emoji 标题）、旧格式分流、散文不恢复、HTML 当文字、12 种恶意输入各 < 50ms。

  - 正在打字时点入口：先收起键盘再打开面板；键盘弹起时入口隐藏，不挡输入框和回复偏好条。

  - 遵循系统"减少动态效果"设置（不做滑动和闪烁动画）。

### 6.2 更新时喂什么（用户定：最近 5 轮完整对话 + 之前玩家说过的话）

| 内容             | 来源                                      | 上限                                  | 为什么                                                                       |
| ---------------- | ----------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------- |
| 角色名 + 简介    | 角色卡 name / description                 | 简介 500 字                           | 知道"她"是谁；不喂完整角色卡（可能几万字，和状态无关）                       |
| 主角人设         | 玩家这张卡用的主角人设                    | 800 字                                | "你"是谁                                                                     |
| 补充设定         | 玩家在这张卡的补充设定                    | 600 字                                | 常定义其他人物，"每人一组"要用到名字                                         |
| 状态栏定义       | 状态栏模板                                | 受模板上限约束                        | 整体说明 + 输出骨架 + 每项"样式写法 + 说明"，不压缩                          |
| 上次记录的状态   | 当前分支路径上最近一次记录（截至第 a 轮） | —                                     | 数值要"接着变"，不带上次记录的话每次都从头估、忽高忽低；从没记录过就用开局值 |
| 之前玩家说过的话 | 最近 5 轮之前的所有轮，只取玩家输入       | 每轮 100 字，从新往旧放，合计 3000 字 | 字少、最能说明剧情走过哪些事，帮模型综合判断（比如关系走到哪一步）           |
| 最近的对话       | 最近 5 轮，玩家输入 + 角色回复正文        | 玩家每轮 500 字；回复每轮末尾 4000 字 | 最新状态主要由这几轮决定                                                     |

每一轮都标【新】（第 a 轮之后，要计入变化）或【已计入】（已经算进上次记录，只作参考）。自动更新每 5 轮一次，所以通常最近 5 轮正好都是【新】；手动更新后再自动更新时，5 轮里会有一部分是【已计入】，靠这个标记避免重复计算。若上次记录很久以前（比如自动更新连续失败），"之前玩家说过的话"里 a 之后的那些也标【新】，按玩家输入推断。

实测（情欲升温）：每轮回复约 1900 字时，一次输入约 1.2 万字（约 8 千 token）；聊到第 200 轮也只有约 1.5 万字（之前玩家输入封顶 3000 字）；回复特别长（每轮约 4000 字）时约 2.2 万字。输出约 200–500 token。每 5 轮一次 + 玩家手动，费用平台承担。

| 主通道 | `deepseek-v4-flash`                                                                | DeepSeek 官方接口，复用语音写稿那组 `DEEPSEEK_API_KEY / DEEPSEEK_URL / DEEPSEEK_MODEL`（`platform/config.ts` 的 `voice.draft`，注释改成"写稿和状态栏"） | 语音写稿已经在用它处理同样的成人向回复                                       |
| 兜底   | 通用兜底：模型目录的 `fallback_model_id`，默认 `deepseek/deepseek-v4.1-flash-1017` | OpenRouter，优先供应商用 `resolveFallbackProviders`（默认 Together → Crusoe）                                                                           | 和正文首字兜底是同一个配置；运营在模型目录里换兜底型号或供应商，状态栏跟着变 |

调用参数：

- 主通道**关闭思考模式**（用户已确认）。DeepSeek 默认开思考（强度 high），思考 token 按输出价计费，而且开着思考时 temperature 不生效；状态栏本质是抽取和累加，语音写稿实测关思考同样准、快很多。temperature 0.3（求稳定）；max_tokens 1500。
- 兜底模型同样不开推理（实现时按 OpenRouter 该型号支持的参数确认）。
- 不新增运营配置 key：模型走现有环境变量和模型目录，超时、字数上限等写在代码常量里。以后要调再加 `status_bar_config`。

### 6.6 校验、重试与兜底

- 同一个解析器解析；按模板检查：项目名齐全；进度条/百分比/星级/阶段写法对得上；没有杂行。
- 第 1 次：主通道。超时（30 秒）、接口报错、或输出不合格 → 第 2 次：**通用兜底模型**；如果第 1 次是输出不合格，把问题清单（如"缺了「衣着」""「好感」写法不对"）附在后面。最多 2 次调用。
- 第 2 次仍不合格：能解析的项照用，缺的项由代码沿用上次记录的值（只是不变，不算变化量）；全都解析不出来就不更新，保留原状态（手动更新提示重试，自动更新不打扰，下一轮再试一次）。
- 主通道失败要留痕：每次都记日志（见第 8 节，带 `fallbackUsed`），避免 DeepSeek key 失效之类的问题被兜底悄悄盖住。
- **状态栏更新不消耗星尘**（自动、手动都不扣；2026-11-19 用户定），模型费用由平台承担。手动更新按钮限频（1 分钟 1 次）防止被刷。

### 6.7 正文模型这边的改动

- 正文模型完全不再管状态栏：主体模板的状态栏槽位固定为"不输出状态栏"、模块顺序里去掉状态栏（主体模板 v18 改几行，运营发布需确认）；协议常量删掉状态栏条款。每轮系统指令因此少掉状态栏的全部篇幅。
- **第一版不把状态喂回正文模型**：状态每 5 轮才更新一次（或玩家手动），最多落后好几轮，喂回去反而会让剧情按过期的数值走；正文本身已经包含了发生过的事。以后如果创作者需要"数值驱动剧情"（比如情欲到100%必须失控），再考虑把"截至第 N 轮的状态"作为参考喂回。

### 6.8 更新策略：每 5 轮自动 + 随时手动（用户决定）

- 每 5 轮自动更新：状态不会落后太多，玩家点开时大多已经是新的；也让"最近 5 轮"正好覆盖两次更新之间的全部对话。
- 随时手动：想马上看最新的就点；手动更新后重新起算 5 轮。
- 收起时不显示数值、只亮"新"点：状态栏是辅助玩法，不抢正文的注意力，又能提示玩家有变化可看。

### 6.9 2026-11-19 追加决定

- **手动更新仅限 VIP**；每 5 轮自动更新所有人都有。非 VIP 点"立即更新"给出开通 VIP 的提示（接口返回 `STATUS_VIP_REQUIRED`，状态数据里带 `manualUpdate: 'vip_required'`）。VIP 读取失败按非 VIP 处理。
- **创作者 AI 的模型改为 `google/gemini-4-carbon`**：改的是 `creator-polish-prompts.ts` 的 `MODEL_ID`，开场白/背景的 AI 润色、建卡 AI 审核、状态栏 AI 生成共用这一个常量，一起换。
- **状态栏提示词不再受每轮系统指令篇幅约束**：说明上限放宽到每条 200 字、定义合计 3000 字、整体说明 500 字；AI 生成时把字段解释写得更丰富（是什么、怎么变、写什么、写多细、边界和例子）。

### 6.10 去掉通用模板，存量卡批量生成（2026-11-19 用户定）

- **不再有"模型自己挑项目"的通用模板**（原 `STATUS_AUTO_DEFINITION` / 来源 `auto` 删除）。生效来源只有：玩家改过的 > 卡自带；都没有就是 `none`——不显示状态面板、不自动更新（玩家仍可在工具箱里自己加一个）。
- **存量卡用 `google/gemini-4-argon` 批量生成初版**，只跑**收藏量前 300**（成本考虑），其余先不管。走运营 CLI：
  `status-bar top`（看排行与已有情况）→ `status-bar generate --top 300 --out <文件>`（只生成到本地文件，不改线上；逐张落盘，可断点续跑；后端同时最多 4 张，CLI 默认并发 3，单张最多再试一次）→ 抽查 → `status-bar apply --file <文件>`（先给差异，再 `--yes`；默认跳过卡上已有状态栏的）。
- 生成资料：存量卡没有建卡草稿，把卡的内容列（description / personality / scenario / character_persona_and_style / system_prompt / mes_example）拼成"背景"，creator_notes 作公开简介，first_mes 作开场白，走建卡同一个生成提示词与校验（不合格带问题清单重试一次）。
- 写入 `app_core.set_character_status_bar(uuid, jsonb)`（service_role）：写 `characters.status_bar_detail`；创作卡如果作者草稿里还没有状态栏，同一事务里补进 `draft.statusBar` 与 `draft_runtime.status_bar`（否则作者下次保存草稿会把它冲掉），不推进 revision。
- 已发布的创作卡版本快照不可变，状态栏上线前的版本里没有状态栏：会话绑定的版本没有状态栏时回落到卡上现在这份（`StatusBarRepository.readCharacterRuntime`）。
- 观测：`admin.status_bar.top_listed`、`admin.status_bar.generated`（outcome succeeded/failed、code、model、itemCount、durationMs）、`admin.status_bar.saved`（mode set/clear、outcome card_only/draft_patched）。

## 7. 出错兜底

| 情况                            | 处理                                 | 用户看到                         |
| ------------------------------- | ------------------------------------ | -------------------------------- |
| 没输出状态栏                    | 不补                                 | 没有状态栏（按既定标准不算问题） |
| 缺 `[/status]`，后面全是规范行  | 严格恢复                             | 正常                             |
| 缺 `[/status]`，混了散文        | 不恢复                               | 孤立标签行被清掉，其余按正文显示 |
| 整块套了代码围栏                | 现有拆围栏                           | 正常                             |
| 写回旧 `<details>` 格式         | 旧解析                               | 旧样式，不乱码                   |
| 某一行写歪                      | 该行当备注                           | 这一行是普通文字                 |
| 零件写法跑偏（进度条只写了 68） | 按实际写法判                         | 退化成数字或文字，不报错         |
| 超上限 / 负数 / 阶段越界        | 条截到 0–100%；阶段越界当文字        | 数字照原样                       |
| 名称改字、多写项目              | 照样显示                             | 正常；统计里记为未命中           |
| 内容里有 HTML                   | 只生成文本节点                       | 原样文字，不执行                 |
| 超长 / 恶意输入                 | 80 行、每行 300 字封顶；正则逐行有界 | 不卡顿                           |

## 8. 观测

每次点"更新"一条 `status_bar.update`（Railway 日志）：`mode`（card/player，即用的是卡自带还是玩家改过的）、`expectedCount`（模板项目名数）、`matchedCount`（命中的项目名数）、`noteCount`、`gapTurnCount`（隔了几轮）、`inputCharCount`、`attemptCount`、`fallbackUsed`、`durationMs`、`outcome`（ok/partial/failed）、触发方式 `trigger`（auto/manual，按 safe-log 白名单命名）。字段名按 safe-log 白名单，不记内容。

## 9. 兼容与上线顺序

1. 数据：状态栏模板（卡自带 / 玩家覆盖）与状态记录（按会话、截至哪一轮哪个版本）各自落表，按 `docs/db/CONTRACT.md` 定坐标后再写迁移（TEST 先跑，生产需确认）。
2. 代码：解析器支持新旧格式；状态栏模型通道（提示词、组装、校验、重试）；更新接口；聊天页状态面板；创作者栏目与玩家工具箱卡；正文模型去掉状态栏槽位。
3. 运营发布（需确认）：主体模板去掉状态栏相关几行、槽位固定"不输出状态栏"；旧状态栏 CSS 保留给历史消息。状态栏模型不需要运营配置（主通道走现有 DeepSeek 环境变量，兜底读模型目录的通用兜底）。
4. 上线前离线评测：`deepseek-v4-flash`（关思考）和通用兜底模型各自 × 7 套示例 × 不同"隔几轮更新"（1 / 5 / 12 轮）回放真实风格的对话；看格式严格通过率、项目名命中率、阶段是否乱跳、有没有把参考轮的事重复计算、数值走向是否符合说明。目标：严格通过 ≥95%，命中率 ≥95%。
5. 停用 `status-open-1..5` 等只服务旧格式的兜底规则（新回复不再带状态栏后即可）。
6. 回滚：正文模型的模板回滚即恢复旧状态栏；状态面板与状态记录独立，可整体关掉不影响聊天。

## 10. 第一版范围与下一阶段

第一版（只给创作者）：

- 创作者编辑器加"状态栏"栏目（与简介、开场白、背景、预设并列），存进草稿 `CharacterDraft`，发布时随角色卡运行时数据一起生效（不拼进 `system_prompt`，规则由代码每轮生成）。具体存储形态按 `docs/db/CONTRACT.md` 另定。
- 栏目默认带起步模板；作者可选官方示例；编辑时实时预览（复用渲染）+ 实时显示规则字数。
- 可选给每项写**初始值**（同样写法、同一解析器校验）；状态面板在玩家第一次点"更新"之前显示开局值，第一次更新时开局值作为"上次记录的状态"喂给状态栏模型。初始值不写进开场白正文。
- 状态栏的名称、说明一并进入创作者 AI 审核的材料。
- 用户侧：只用现有全局开关；有状态栏的卡按卡的来，没有的卡不显示状态（见 6.10，收藏量前 300 的存量卡批量生成）。

创作者构建流程（演示稿 https://claude.ai/artifact/URzvGSfcdboBLrZqaZvobd）：

- 位置：编辑器"预设"之后、"标签"之前，必填；样式沿用现有栏目（标题 + 说明 + 卡片）。
- 空状态：主按钮"AI 根据角色资料生成"；其次 6 套成人向示例；"从空白开始"。
- 生成后随时可"换一套"：回到选择区（AI 重新生成 / 6 套示例 / 空白），也可"← 不换了"；换了之后可"恢复上一版"回到原来那套，作者的修改不会丢。
- 生成后：上方是玩家看到的预览卡（带开局值），栏目标题右侧显示"已用 N / 12 项"；缺说明的项在预览卡下方提示，可"✦ AI 补全说明"。
- 个性化两条路：①点某一项打开编辑弹层（名称 → 类型 4 选 1 → 样式缩略图 → 类型设置 → 开局时 → 说明，底部单项预览）；②一句话让 AI 改（输入当前状态栏 + 作者那句话，输出整套新状态栏）。都有"恢复上一版"。
- 入口：预览卡本身可点（点项目改项目、点分区标题改分区），分区末尾"加一项"，卡下"加分区"。
- AI 生成/修改：沿用 AI 润色的调用通道，即 OpenRouter 上的 `google/gemini-4-carbon`（`creator-polish-prompts.ts` 的 `MODEL_ID`，作者工具不扣费）；只输出结构化结果；每项必须带合格说明（见 2.5）；代码校验样式合法、名称无标点、定义合计 ≤3000 字（超了先让 AI 精简说明）；不合格重试一次，仍失败提示且不动已有状态栏。

玩家侧（工具箱）：

- 第三个模块卡"状态栏"，色调用鼠尾草绿（`--success`，呼应状态卡底色），标签"只对这张卡"；标题行小字"用的是作者的版本"/"已按你的改过 · 下一轮生效"。
- 展开后是同一张预览卡（点着改）+ "撤销" + "恢复作者的版本"；新加的项可填"从多少开始"。
- **玩家侧不加任何 AI（2026-11-19 用户定，出于成本）**：说明由玩家自己写；弹层按样式给写法提示，说明必填并做同样的合格性校验（不少于 8 字、数值类要写到涨和掉）。
- 建议（待用户确认，零成本）：说明栏下给一句"填空模板"，按样式插入，比如数值类插入"她的***。***会涨，**_会掉，每轮最多变_**。"，玩家只填空。
- 生效：玩家覆盖版 > 卡自带 > 自动。改完后状态面板立即按新结构显示（没有值的新项显示开局值或"暂无"），下次点"更新"就按新定义生成；历史消息照常按原样显示（渲染只看输出）。
- 存储：用户 × 卡 的覆盖版，同 `user_character_preferences` 性质（S，用户在卡上的偏好），具体按 CONTRACT 定。篇幅上限同创作者；玩家新加的项说明同样必填（无 AI，弹层按样式给写法提示）。

以后：玩家把改好的状态栏存成模板、跨卡复用（用法同人设）。
