# Sentry错误治理流程与每周二五汇报模板

## 目标

建立从指定时间范围错误收集到排查、修复、上线与复验的可重复流程，每周二、周五给出可追溯的修复情况说明。

## 需求与约束

- 验证当前连接的组织、项目和绝对时间范围查询能力，保留安全的聚合核验记录。
- 交付中文错误报告、修复汇报两个Markdown模板，支持任意起止时间、环境和版本。
- 每项问题关联Sentry、任务、commit、部署和复验；代码修改不能直接算作线上修复成功。
- 明确每周二、周五的建议时间、连续统计窗口、失败处理与积压移交。
- 复用现有Sentry连接、日志、Trellis和本地验收，不新增SDK、服务、依赖、业务代码或定时部署。
- 不保存秘密、个人身份、业务正文或未经脱敏的事件原文；已有未提交工作保持原状。

## 验收标准

- [x] 现有连接可以读取组织、项目及指定绝对时间范围的错误聚合。
- [x] 两个模板覆盖统计口径、iOS/Android、数据缺口、优先级、责任人、修复证据与上线复验。
- [x] 提供可复制的指定范围取数及周二/周五汇报指令，明确尚未配置自动执行。
- [x] 保留查询实际执行范围，合计和分组数量能够核对；无样本和缺失用户标识不补零下结论。
- [x] 文档格式、链接与Trellis声明检查通过，副本放入用户指定的Sentry文档目录。

## 性能与日志

纯文档不影响页面、接口、采集或日志运行行为，三个元数据声明已说明不适用原因。未来修复任务必须独立声明性能、日志和模块影响，不能复用本任务的豁免。
