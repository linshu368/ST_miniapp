# 剧情记忆压缩诊断与稳定性优化

## 目标

让 Railway 能回答压缩输出了多少字、真正按什么限制拒绝、重试是否奏效；减少超长结果重复生成以及任务排队租约过期造成的失败。压缩模型仍可能拒绝、超时或输出不合格，目标是降低可避免的失败并保留可诊断、可恢复的终态，不承诺外部模型零失败。

## 实施前确认的源码事实

- `compress-job.ts` 已实现 85% 目标、旧记忆预精简、最多三次主校验调用及最后一次精简兜底；不能把这些已有机制当作本轮新增。
- `worker.ts` 传出的 `outputChars/maxChars/historyChars/oldMemoryChars/shrinkPass` 不在 `safe-log.ts` 白名单；`promptVersion/rangeStart/rangeEnd/chunks/attempts` 等摘要也存在过滤问题。
- 旧记忆预精简按 `memoryTargetChars(max)` 校验，拒绝日志却填 `max`，混淆实际限制与总上限；预精简异常被吞掉。
- 当前每轮同时领取三个任务、逐个执行，领取时各自开始 15 分钟租约；一次分块最多预精简 120 秒加主调用 3×120 秒，多块任务会更长。后面的任务可能尚未执行就已过租约。这是源码推导的风险，尚无生产样本证明其发生频率。
- `20261120_story_memory_retry_guard.sql` 已存在，目的为防止新消息重置失败退避；本轮未确认各环境是否执行，不能当成生产已生效。

## 需求与验收

| ID  | 需求                 | 可观察验收                                                                                                                                                                                                                              |
| --- | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 完整、安全的压缩观测 | 成功、校验拒绝、上游异常、截断、预精简回落均有阶段、尝试次数、耗时、模型/prompt 版本；真实 Pino JSON 保留字段，不含正文/密钥/个人信息。                                                                                                 |
| R2  | 长度与限制口径准确   | 明确非空白 Unicode 字符数；同时输出实际 output_chars、hard_max_chars、validation_max_chars、target_chars、over_limit_chars、prompt/history/recent/old_memory 字数；不能把字符数和 token 数混用。无输出/未知 usage 不填零冒充测量。      |
| R3  | 超长时减少无效重做   | 第一次 too_long 后立即精简已有、结构完整的输出，第二次与第三次分别给 80% 和 60% 总上限的目标；仍按总上限及原质量规则验收；主阶段最多三次，预精简最多一次。                                                                              |
| R4  | 租约与提交结果真实   | 每次只领取马上执行的一条，每轮最多处理三条；下一条在上一条收尾后再领取。逐块提交/续租、原 CAS 不变；租约丢失或 finish 失败不得报成功。已提交的部分进度不能在后续失败时被归零。                                                          |
| R5  | 恢复与告警           | 原记忆保留，拒绝内容不提交、不推进覆盖；不增加上游自动重试/模型切换/用户计费；保留现有数据库退避及第三次连续失败告警，只有中间可恢复尝试使用 warn，不把失败改成成功来消音。                                                             |
| R6  | 可重复验证           | 扩展现有 compress-chunk/logger/story-memory 测试；新增 transport 与 worker 回归测试由风险评估确认必要，覆盖取消、截断、安全输出、租约及部分提交。Backend typecheck、全量既有测试及日志/复杂度检查通过。真实供应商与移动端结果另行验证。 |

## 范围

仅后端记忆压缩、worker、现有日志投影及相应测试/说明。保留现有分块、配置入口、模型、计费、窗口规则、版本存储与权限；不改 UI、shared 对外契约、线上运营配置、告警路由或数据库对象。本轮不执行任何远端 migration、发布、扣费回放或通知。
