# 聊天会话历史优先优化需求

## 目标与范围

用户进入聊天会话时，优先看到正确的历史记录和必要会话信息，减少多轮串行读取。结合Railway对话错误，设计首屏、分页、缓存、恢复和日志的分步优化；功能正确性、可定位性和数据库负载优先于减少RPC数量。本次仅交付规划，不修改产品代码、不执行迁移或部署。

## 确认事实

北京时间11月21日至22日的实际聊天导航P95：Android4480.804ms（741例），iOS3153.736ms（138例）。服务端分组串行读取已由同请求Railway证据确认。完整数值、源码依据和局限统一见design.md第2节与research.md，不用合并聊天模块值替代实际聊天页。

Railway同窗口可见165个最终首字超时请求、5次交付选择PT409、2次流中终态写入失败；事件重复计数及错误语义边界见design.md第4节。safe-log.ts会过滤嵌套phases和未登记phase，仅改logger调用参数不足以保证可见。数据库具体SQL计划、精确冲突守卫仍是实施验证项，不把推测当事实。

## 需求与验收

| 编号 | 用户要求/约束              | 验收                                                                                                                                                                       |
| ---- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | 优先显示真实历史与必要信息 | 最近10轮先显示，开场/空页状态正确；不等模型目录、工具箱、余额或头像下载；不提前记ready                                                                                     |
| R2   | 减少串行读取               | 对照验证小范围聚合或最小必要并行读取，保留身份/归属/角色访问/版本及昵称规则，不强制一次RPC                                                                                 |
| R3   | 更早记录与操作完整         | 200轮分页无遗漏/重复，滚动锚点、草稿、编辑/删除/点赞/分支/重生成/取消定位回归通过                                                                                          |
| R4   | 可靠恢复且不影响账务       | GET移除恢复前，证明24小时前孤儿、跨副本/重启、有限批量/公平推进及失败恢复；保留开轮门禁、CAS和额度收口顺序                                                                 |
| R5   | 对话错误可定位和恢复       | 正常停止、首字截止、上游网络、DB读写、交付冲突分别归类；未知写结果不重发生成、不重复扣费，真实失败不吞掉                                                                   |
| R6   | 双端性能和失败共同验收     | 目标Android导航≤2500ms、iOS≤2200ms；GET分别≤1500/1300ms。稳定48小时、各端至少100同类导航，不足延长；同步报告失败/stall/离页与积压                                          |
| R7   | 兼容且可回退               | 原HTTP DTO与旧客户端默认语义兼容；不增加私人持久缓存；先TEST再生产人工迁移，含停止条件和兼容应用回退                                                                       |
| R8   | 功能正确先于提速           | 固定快照下新旧DTO语义等价，仅允许页大小差异；权限/版本、全部交互、并发及结算专项通过才能发布，性能提升不能抵销功能失败                                                     |
| R9   | 聚合职责有界，不变成慢接口 | 禁止引入生成、计费、恢复、钱包、模型、完整设置/角色及全量历史统计；无N+1/先全量JOIN再LIMIT；同条件读取P95、SQL计划和DB负载不退化，否则缩小范围或最小并行                   |
| R10  | 日志真实可分析             | 固定用途/路径/阶段/原因及实际耗时、规模、结果经白名单进入stdout/Railway；未测到不补0、不伪造SQL子阶段，不按HTTP200判生成成功；失败全量、正常摘要有限采样且保留完整成功分母 |

以上是拟议验收目标，未宣称已实现或保证零故障。实现设计见design.md，功能矩阵/聚合对照/日志字段/等级/采样/重试截止见acceptance-and-observability.md；步骤与可执行验证见implement.md，交付状态见task.md。需求已收敛，无阻塞产品问题；实施前技术验证均有明确失败停止路径。

## 不在本次范围

角色/影像创作页面重构、全局冷启动改造、更换数据库或供应商、通用聚合接口框架、私人聊天持久缓存、自动生产写操作。实际代码和日志调整需在本方案进入实施后交付，当前仅规划。
