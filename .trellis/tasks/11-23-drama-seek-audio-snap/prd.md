# 短剧快进吸附对齐音频分片边界

## Goal

无缓冲快进 3s 恢复率（含放弃）是 P0 主指标，目标 95%。Android 近 72h（2026-11-20T09:40Z～11-23T09:40Z）为 92.9%（222/239）。`11-18-drama-seek-snap-lowlevel` 的落点吸附只按视频分片计算：落点放在视频分片起点 +0.05s。Cloudflare Stream 的音频是一条独立轨，音频分片起点比视频晚约 0.1–0.4s，而且逐片漂移，所以吸附后的落点正好落在上一音频分片的最后约 0.15s。只缓冲这么一点，浏览器起不了播，要等下一音频分片请求并装入缓冲后才能恢复。音频控制器按顺序请求分片，这一步是串行的。本任务让吸附同时避开音频分片的尾段，只需下载一片视频加一片音频（两者并行）就能恢复。

## 现状证据（后端 `drama.seek_diagnostic`，Android hlsjs_mse，72h，分母 253）

- 吸附后、目标处音频剩余 <500ms：18 条，不达标 5 条（27.8%），P50 2.28s。吸附后音频剩余 ≥500ms：11 条，全部达标，P50 1.15s。
- 不论是否吸附，音频剩余 <500ms 的样本中，21/22 条要等下一音频分片装入缓冲才开始播放。视频和音频都装入缓冲后，还要多等 P50 0.70s / P90 1.19s 才恢复（对照组为 0.12s / 0.44s）。
- 反事实估算：去掉这段额外等待后，26 条不达标里有 5 条能回到 3s 以内，约 +2pp。剩余不达标中约一半是弱网首字节，不在本任务范围。

## Requirements

- 只改 `createHlsSeekPlanner` 的落点计算。作用范围和 `11-18-drama-seek-snap-lowlevel` 相同：hls.js 路径、目标未缓冲的用户快进。原生路径、已缓冲快进、续播定位都不变。
- 吸附规则对视频轨（当前档位的分片）和当前音频轨（`hls.audioTracks[hls.audioTrack].details.fragments`）都适用：落点在某一轨所属分片最后 20% 以内、且该轨后面还有分片时，后移到该轨下一分片起点 +0.05s。两轨交替检查，直到都不在尾段，最多 3 轮。只会向前移，最多约 1.2s，用户已接受这个精度损失。
- 没有独立音频轨（音视频复用，或音频轨清单还没加载）时，结果和现在一样。
- 后移后的位置超过视频时长时，返回原值，与现在一致。
- 临时降档、档位保持、`restartStalledAudioOnSeek` 都不变。降档对应的是吸附后落点所在的视频分片。
- 不改 shared 契约，不新增上报字段。

## Acceptance Criteria

- [x] 单测（在现有 `drama-hls-seek.test.ts` 中追加）：先吸附视频再落入音频尾段时，继续后移到下一音频片；视频不在尾段、只有音频在尾段时，也会后移；音频尾段后面没有分片时不动；没有音频轨时与现在一致；原有用例全部通过。
- [x] `pnpm --filter frontend typecheck`、相关 vitest、lint、`pnpm lint:complexity` 都通过。
- [x] 离线回放（72h 后端诊断中真实的分片边界）：256 条里有 23 条会在现有吸附基础上再后移 64–424ms，全部仍在原目标视频分片内，也都没有落入视频尾段。
- [ ] 上线 3–7 天后按版本对比：后端诊断中「目标处音频剩余 <500ms」的占比从 32/231 明显下降；Android hls.js 恢复率提升方向与估算（约 +2pp）一致。样本噪声约 ±3–4pp，只看方向和机制命中，不单独下显著性结论。
- [ ] 护栏：快进 `error`/`switched` 占比不上升；卡顿占比不劣化。

## Android/iOS 性能 P95 门禁

- 受影响页面：`/watch`、`/dramas/:id` 播放器的无缓冲快进
- 受影响接口：无
- Android 快进含放弃 P95：基线 ≥3530ms（3s 恢复率 92.9%，N=239）/ 目标 3000ms
- iOS 快进含放弃 P95：基线 2840ms（96.2%，N=80）/ 目标不劣化（≤3000ms）
- 接口 P95：不适用（不新增、不改接口）
- 数据来源与观测窗口：Faro `st_drama_seek`（`drama_seek_resume_v1` final，未缓冲、向前、resume_expected=true），2026-11-20T09:40Z～11-23T09:40Z；上线后 3–7 天，按 app_version 是否为合入提交的后代切分
- 发布后验证与低样本说明：iOS 分母约 80/72h，只报方向；吸附命中可从后端诊断识别（目标 − 覆盖音频分片起点 ≈ 50ms），不需要新字段

## 不做

- 降档后被 hls.js 切回高档、中止重下（方向 2，暂缓）；弱网拖动中预取；按将要加载的档位（而非当前档位）取视频分片边界；iOS 原生 HLS；看板改动。
