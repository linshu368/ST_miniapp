# 记忆栏拆出正文模型：独立生成、放进右侧面板

2026-11-23。用户已定方向：记忆栏和状态栏一样由独立模型生成，放在右侧面板状态栏下面；格式由我们内定，不开放给用户调；状态栏的提示词和格式不动。

## 1. 为什么拆

近 3 天 DeepSeek 应写记忆的成功回复约 8160 条，只有约 49% 写了记忆栏。和用户设置、剧情模式、轮次、篇幅都无关；漏一次后下一轮只有 22% 会写。不是正则漏抓（没出记忆栏的回复里有记忆内容的不到 3%）。每轮都带着约 1750 字的记忆规则也只有这个水平，加严格式没有用；历史回复里记忆区还占约四分之一篇幅，白白占上下文。

## 2. 用户看到的样子

- 右侧面板：状态栏下面加「记忆」区，三块可折叠：**工作记忆**（最近的互动，最新在上）、**历史档案**、**里程碑**。样式先出对比稿再定（沿用面板雾面玻璃风格）。
- 面板入口：状态栏或记忆栏有一个开着就显示；卡没有状态栏、或玩家关了状态栏时，面板里只有记忆。
- 回复末尾不再出记忆栏；**老回复里的记忆区直接隐藏**（和旧状态栏的处理一致）。
- 「记忆栏」开关（`pref_show_memory`）保留：关了就不生成、不显示记忆区。
- 记忆内容只读，玩家不能改格式或内容。

## 3. 什么时候生成、用什么模型

- 和状态栏**同一时机**：每 3 轮自动（距上次记忆记录满 3 轮），VIP 点「立即更新」时一起更新。不扣星尘。
- 和状态栏**分开调用、同时发出**：状态栏提示词一字不动；记忆有自己的提示词和校验。两个调用并行，不多等；一个失败不拖累另一个，失败的那个下一轮回复结束时自然重试（同状态栏现在的做法）。
- 模型同状态栏：Surplus Gemini 3 Flash 首发（首字 4 秒），失败或没过校验立刻 DeepSeek 兜底。

## 4. 累加怎么做（核心）

以前正文模型每轮都能看到前面所有轮次（历史里带着上一份记忆区），自己把记忆往下续。拆出来以后记忆模型只看得到最近 10 轮完整对话 + 更早的玩家发言，所以改成**在上一份记忆上追加**：

- **存结构化记忆**，不存文本：
  - 工作记忆：每条 = 所属轮次 + 时间 + 感情进展 / 做过什么 / 留下状态 / 悬念与承诺；
  - 历史档案：每条 = 时间范围 + 感情线走向 / 亲密经历概述 / 累计变化 / 仍有效的悬念与承诺；
  - 里程碑：每条 = 时间 + 对象 + 节点内容。
- **每次更新模型只写新增**，不重写已有内容：
  - **每次更新写一条工作记忆**，概括上次记录之后的这几轮（自动更新通常 3 轮一条；玩家点「立即更新」就立刻写一条，覆盖到当前为止的新轮次）；
  - 这几轮触发了里程碑节点（沿用现行 6 类：关系阶段变化、表白/确立/破裂、与某角色首次亲密、新玩法被开发、重要承诺、重大情感事件）就输出新增里程碑；
  - 工作记忆超过 10 条时，**由代码挑出最早的 10 条**，同一次调用里让模型合并成一条历史档案，合并后这 10 条移出。
- **只读部分由代码保管**：历史档案、里程碑平时只增不减，模型输出里只有新增项，已存的不交给模型改写；只有被挤出上限时才并进前情概要（见下）。
- **长度封顶，越久远越粗**（防止越聊越膨胀）：

  | 层       | 上限              | 单条                        | 超出时                                                        |
  | -------- | ----------------- | --------------------------- | ------------------------------------------------------------- |
  | 工作记忆 | 10 条（约 30 轮） | 四项各 ≤50 字，整条 ≤160 字 | 最早 10 条合并成 1 条历史档案                                 |
  | 历史档案 | 6 条（约 180 轮） | ≤220 字                     | 最早 1 条并进前情概要                                         |
  | 里程碑   | 20 条             | 一句话 ≤40 字               | 最早 5 条并进前情概要                                         |
  | 前情概要 | 1 段              | ≤400 字                     | **可改写**：每次有内容并进来时由模型重写整段，仍不超过 400 字 |

  整份记忆封顶约 5000 字，不随对话轮数增长。哪些内容要合并、并进概要，由代码按上限判断后放进本次任务；模型只负责写合并后的文字。

- **新轮次超出 10 轮窗口时**（连续失败、隔很久才更新），记忆模型额外拿到这些新轮次的回复正文（截断到上限），保证每个新轮次都有据可写，而不是只凭玩家发言。
- **输入**：角色名 + 已有记忆（历史档案只给最近 20 条、里程碑全给、工作记忆全给，标轮次）+ 之前玩家说过的话 + 最近的对话（每轮标【新】/【已计入】，同状态栏）+ 记忆规则。不喂正文模型的 system prompt。
- **输出**：固定 JSON（`entry / milestones[] / archive / summary`，后两项只在本次有合并任务时出现），代码校验四项齐全、字数上限、合并任务有没有完成，不合格转兜底并附问题清单。

## 5. 老会话怎么接上

某会话第一次生成新记忆时，如果当前路径上还没有新记忆记录：取当前路径上最近一条带 `[memory]` 的回复，把它的记忆区原文作为「旧记忆」交给模型，这一次先整理成新结构再追加；没有就从空开始。一次性，之后都走结构化记忆。

## 6. 存储、分支、撤销

- 新表 `experience.chat_memory_snapshots`：每次记忆更新一行（会话、锚点轮次、结构化记忆 jsonb、触发方式、替换的那条），沿用状态栏同一套规则——锚定到当时最新一轮的那一版回复，**只认当前路径上的记录**：重新生成、切分支看到的是那条路径上的记忆；同锚点重算替换旧记录。
- 面板的「撤销这次更新」：状态和记忆一起撤回上一次。
- 迁移只加表和读写函数，走 GitHub Actions 迁移流程（TEST → 生产）。

## 7. 正文模型这边

- 提示词：`{{MEMORY_RULES}}` 填空（同 `{{STATUS_RULES}}`），协议常量去掉记忆部分；主体模板里提到记忆区的文字由运营改（只改文字，不动占位）。
- 历史：旧回复里的记忆区从入模历史里剥掉（省约四分之一的历史回复篇幅）；选项照旧保留。
- **新记忆不喂给正文模型**（用户定）：正文的连贯性由已经进入消息序列的「长期记忆压缩」负责；记忆栏是给用户看的，让用户心里有底。
- 选项不动（后续看效果再决定是否同样处理）。

## 8. 成本

- 正文：每轮少写记忆区（平均约 350 字），少带约 1750 字规则，历史少约四分之一回复篇幅；按提示词平均 3–4 万 token 估，每轮输入下降一到两成。
- 新增：每 3 轮一次记忆调用，输入约 1.2 万字对话 + 已有记忆，输出约 300 字；Gemini 首发很便宜，兜底 DeepSeek 也远低于正文模型每轮写记忆区的开销。

## 9. 上线步骤

1. 记忆提示词 + 校验 + 生成（后端），先在开发环境用真实会话离线跑一批，看结构和质量（只做统计 + 用户抽看样例）。
2. 面板记忆区对比稿 → 用户选定 → 前端。
3. 迁移（新表）TEST → 生产。
4. 一次发布切换：正文去掉记忆规则、历史剥记忆区、老回复隐藏记忆区、面板显示记忆。

## 10. 用户已定（11-23）

1. 工作记忆每次更新一条（自动约 3 轮一条），点「立即更新」立刻写一条。
2. 老回复里的记忆区直接隐藏。
3. 新记忆不喂正文模型（长期记忆压缩已在消息序列里）；记忆栏是给用户看的。
4. 要有长度限制：久远的记忆要能舍弃或被改写，不能越聊越膨胀（见第 4 节表格）。
