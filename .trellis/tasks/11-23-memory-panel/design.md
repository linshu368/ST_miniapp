# 记忆栏拆出正文模型：独立生成、放进右侧面板

2026-11-23。用户已定方向：记忆栏和状态栏一样由独立模型生成，放在右侧面板状态栏下面；状态栏的提示词和格式不动。

## 0. 记忆栏的定位（用户 11-23 纠正后）

- **状态栏**记「现在是什么样」：固定的项、固定的格式。
- **记忆栏**记「发生过什么」：这段故事的剧情记录，像连载小说的前情提要。用自然的文字写，**不规定字段和格式**（不定义事件的时间、人物、感情等字段）；人物多、关系复杂、世界观大时，每条线、每个有变化的人都要写到。**剧情记录第一，好看其次**，纯文本也可以。
- 只限定大致结构：剧情记录（段落）、里程碑（一句话一条）、前情概要（压缩后的段落）。这些结构只为控制长度。
- **越近越详细，越远越简略**：按远近分四档（近 / 中 / 远 / 很远）决定详细程度，整份最多 4000 字（见 §4）。
- **玩家可以写「记忆要求」**（比如"着重记录好墨尘和我的关系"）：内容上优先级最高，一律照办；只有结构和字数上限不变（见 §4a）。

## 1. 为什么拆

- 近 3 天 DeepSeek 应写记忆的成功回复约 8160 条，只有约 49% 写了记忆栏；漏一次后下一轮只有 22% 会写；不是正则漏抓（<3%）。每轮带着约 1750 字的记忆规则也只有这个水平；历史回复里记忆区占约四分之一篇幅。
- 用户反馈（11-21，房东模拟器，人物多）：里程碑显示不全、自己乱变，80 条往后常出问题。查实：近 7 天该卡 1890 轮，记忆区写到最多 99 条里程碑，95 轮撞上单条回复约 5400 字的上限被截断（85 轮记忆区写一半就断）；正文模型每轮整份重写记忆，前面的内容会被改写或漏掉。拆出去后记忆由代码保管、只追加，不再占正文长度。
- 同卡另有 733 轮（39%）是 Gemini 3.1 Flash Lite Preview 内容审核中断，与记忆无关，另行处理。

## 2. 用户看到的样子

- 右侧面板：状态栏下面加「记忆」区，用对比稿 **B 时间线**（用户 11-23 选定）：近、中两档的剧情记录按时间排成一条线（最新在上，中档字小一号、颜色淡一点），里程碑插在对应位置；远档（一句话一条）和前情概要收在最下面可展开的「更早的记忆」。
- 记忆区标题右边「记忆要求 ›」：打开底部弹层写要求（≤300 字，保存 / 清空）；写了的话在记忆区顶部显示一行「按你的要求记：…」，点它也能改。
- 不显示轮次。
- 面板入口：状态栏或记忆栏有一个开着就显示；卡没有状态栏、或玩家关了状态栏时，面板里只有记忆。
- 回复末尾不再出记忆栏；老回复里的记忆区直接隐藏（和旧状态栏的处理一致）。
- 「记忆栏」开关（`pref_show_memory`）保留：关了就不生成、不显示记忆区。只读，玩家不能改。

## 3. 什么时候检查、用什么模型

- 和状态栏**同一时机检查**：每 3 轮自动看一次；VIP 点「立即更新」时立刻看一次。不扣星尘。
- 检查 ≠ 一定记：**有进展才记，没进展就不动**。点「立即更新」时没进展，提示「这几轮没有新进展」。
- 和状态栏**分开调用、同时发出**：状态栏提示词一字不动；两个调用并行，一个失败不拖累另一个。
- 模型同状态栏：Surplus Gemini 3 Flash 首发（首字 4 秒），失败或没过校验立刻 DeepSeek 兜底。

## 4. 怎么记（核心）

- **按剧情记，不按轮次记**：剧情真的往前走了才记一段（感情变化、关系确立或破裂、首次亲密或尺度升级、承诺约定或悬念有结果、重要事件和转折）；闲聊、日常、重复、原地打转不记。没进展就不写，不为了记而记。聊 100 轮没进展就是没进展。
- **该记的都记全**：人物多时每条线、每个有变化的人都写到，写清谁和谁、发生了什么、结果怎样、留下了什么；宁可具体，不要笼统。
- **看的范围从上一段记录之后算起**：判断「没进展」不挪起点，零碎变化攒到真有进展时一起记；最多看最近 40 轮（最近 10 轮完整，更早的截短）。
- **已有内容只读**：模型只写新增；里程碑平时只增不减。
- **越近越详细，越远越简略**：按每段往前数第几段分档（不按轮次），整份记忆封顶 **4000 字**：

  | 档位   | 放几段       | 详细程度                                       | 每段字数（要求 / 校验上限） | 面板位置         |
  | ------ | ------------ | ---------------------------------------------- | --------------------------- | ---------------- |
  | 近     | 最新 4 段    | 完整叙述                                       | 300 / 360                   | 时间线           |
  | 中     | 再往前 6 段  | 两三句话                                       | 100 / 120                   | 时间线（淡一点） |
  | 远     | 再往前 12 段 | 一句话                                         | 35 / 45                     | 更早的记忆       |
  | 很远   | 更早的全部   | 并成一段前情概要，只留仍然重要的，不重要的丢掉 | 380 / 450                   | 更早的记忆       |
  | 里程碑 | 最多 20 条   | 一句话                                         | 30 / 35                     | 插在时间线上     |

  每记下新的一段，前面的都往远挪一位：跨档的那段由模型压短（近→中压成两三句，中→远压成一句），挪出「远」的并进前情概要；里程碑放不下时最早 5 条也并进前情概要。哪段要压、压到多短由代码算好放进本次任务，模型只写文字。没记新的就不挪、也不压。各档放满、每段写到上限，合计 3850 字，不会超过 4000（单测覆盖）。

- **输入**：角色卡名 + 已有记忆（只读）+ 上一段记录之前 2 轮（标【已记过】）+ 之后的对话 + 本次任务。不喂正文模型的 system prompt，不写轮次。
- **输出**：`{"record", "milestones", "compress", "summary"}`，compress 按编号给压短后的文字；只检查长度、该写的有没有写，不检查内容格式；不合格转兜底并附问题。

### 4a. 玩家的记忆要求

- 玩家在面板里写一段对记忆的要求（≤300 字），比如"着重记录好墨尘和我的关系""阿杰那条线也别漏""亲密的细节记详细点"。
- 提示词里放在【已有记忆】前面，标「优先级最高，内容上一律照办」：记谁、哪条线、哪些细节记或不记、口吻、详略都听玩家的；玩家在意的线有一点变化也算进展；压缩旧记录时优先保留玩家在意的内容。
- 不能改的只有输出结构（JSON 四个字段）和字数上限，由代码校验兜住；和它们冲突时，模型在结构和字数内尽量满足。
- 每人每张卡一段（同玩家改过的状态栏），从下一次更新开始生效，已经记下的不回头改。所有玩家都能写，不限 VIP。

草稿代码（本地分支 feat/memory-panel，未推送）：`packages/shared/src/memory-bar/`（schema / plan / prompt / apply），单测 `__tests__/memory-bar.test.ts`（12 条通过）。

## 5. 老会话怎么接上

第一次检查时当前路径上还没有新记忆：取最近一条带 `[memory]` 的回复，把记忆区原文并进前情概要，起点从那条回复之后算；没有就从空开始。

## 6. 存储、分支、撤销

- 新表 `experience.chat_memory_snapshots`（数据性质 D：由对话派生）：每次有变化的检查落一行（会话、锚点轮次、记忆 jsonb `memory_detail`、触发方式、替换的那条）；只认当前路径上的记录：重新生成、切分支看到的是那条路径上的记忆。落位卡与 registry 登记在 PRD 里补齐（CONTRACT §2.2）。
- 另记检查点（最后一次检查到第几轮），避免没进展时每轮都检查。
- 玩家的记忆要求：`app_core.user_character_preferences` 加一列 `memory_request`（text，NULL = 没写），和玩家改过的状态栏同一行；读写走 RPC，生成时随卡设置一起读。
- 面板「撤销这次更新」：状态和记忆一起撤回。迁移只加表和读写函数，TEST → 生产。

## 7. 正文模型这边

- `{{MEMORY_RULES}}` 填空，协议常量去掉记忆部分；主体模板里提到记忆区的文字由运营改。
- 入模历史剥掉旧回复里的记忆区；选项照旧。
- 新记忆不喂正文模型：正文连贯性由已在消息序列里的长期记忆压缩负责；记忆栏给用户看，让用户心里有底。

## 8. 上线步骤

1. Trellis 规划门禁补齐（prd / implement / task.json 的移动端性能与日志接入声明、落位卡）→ 用户审过后开工。
2. 后端检查任务、存储、接口。
3. 用真实会话离线试跑一批看质量（需用户同意：只读生产对话、用生产模型 key）。
4. 前端：B 时间线 + 记忆要求弹层。
5. 迁移 TEST → 生产 → 一次发布切换。

## 9. 用户已定（11-23）

1. 记忆栏是剧情记录，不是状态栏：不规定字段和格式，里程碑只限大致格式；剧情记录第一，好看其次。
2. 按剧情记，不按轮次记；没进展不更新，提示词不为了记而记。
3. 人物多、关系复杂、世界观大时要记全；可以丢弃过于久远的记忆，新的要记好。
4. 老回复里的记忆区直接隐藏；新记忆不喂正文模型。
5. 面板用 B 时间线。
6. 玩家可以写记忆要求，内容上优先级最高；只有格式（结构和字数）不变。
7. 整份最多 4000 字；按近 / 中 / 远 / 很远分档决定详细程度，久远的显示在「更早的记忆」，过早的压成一句话、再早的并进前情概要。
