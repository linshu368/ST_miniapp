# 记忆栏拆出正文模型：独立生成、放进右侧面板

## 目标

记忆栏不再由正文模型在回复末尾输出，改由独立模型记录，显示在聊天页右侧面板状态栏下面。解决两件事：

- DeepSeek 只有约一半回复写了记忆栏（用户反馈"三次里有一次不出"）；
- 人物多的卡（房东模拟器）里程碑显示不全、自己乱变（正文模型每轮整份重写、撞单条回复长度上限被截断）。

技术方案见 [design.md](design.md)，执行计划见 [implement.md](implement.md)。

## 需求（用户 11-23 已定）

1. **定位**：记忆栏是这段故事的剧情记录（发生过什么），不是状态栏（现在是什么样）。自由文字，不规定事件、时间、人物关系字段；里程碑只限"一句话一条"。剧情记录第一，好看其次。
2. **按剧情记，不按轮次记**：每 3 轮检查一次，剧情真有进展才记；没进展记忆不动，不为了记而记。
3. **记全**：人物多、关系复杂、世界观大时，每条线、每个有变化的人都写到。
4. **长度**：整份最多 4000 字，按远近分档定详细程度：近（完整一段）/ 中（两三句话）/ 远（一句话，收在「更早的记忆」）/ 很远（并进前情概要）。可以丢弃过于久远的细节，新的要记好。
5. **玩家的记忆要求**：玩家可以写一段对记忆的要求（≤300 字），内容上优先级最高、一律照办；只有结构和字数上限不变。每人每张卡一段，所有玩家都能写。
6. **面板**：用对比稿 B 时间线（https://claude.ai/artifact/FZ25CBU5PGGcRyLt2HG7pP）；不显示轮次。
7. **老回复**：回复末尾不再出记忆栏；老回复里的记忆区直接隐藏。
8. **不喂正文**：新记忆不进正文模型的提示词（正文连贯靠已有的长期记忆压缩）。
9. **不动的**：状态栏的提示词和格式不动；格式由我们内定，玩家只能写内容上的要求。
10. **开关**：沿用「记忆栏」开关（`pref_show_memory`），关了就不检查、不显示。
11. **成本**：检查不扣星尘；自动检查所有人都有，「立即更新」沿用状态栏的 VIP 限制和冷却。

## 验收标准

- [ ] 正文模型的提示词里不再有记忆规则，新回复末尾不出 `[memory]`；入模历史里旧回复的记忆区被剥掉。
- [ ] 老回复里的记忆区在聊天页不再显示（含兼容解析出来的），正文、选项不受影响。
- [ ] 记忆每 3 轮检查一次，只在有进展时追加；没进展不写库、起点不挪。手动「立即更新」同时更新状态和记忆，没进展提示「这几轮没有新进展」。
- [ ] 卡没有状态栏、或玩家关了状态栏时，面板里只显示记忆；记忆开关关掉时不检查、不显示。
- [ ] 任何一次检查后整份记忆 ≤ 4000 字，档位与远近一致（库约束 + shared 校验双重保证）。
- [ ] 玩家写的记忆要求进入提示词并排在已有记忆前面；保存、清空后下一次检查生效。
- [ ] 重新生成、切分支后，面板显示的是当前路径上的记忆。
- [ ] 老会话第一次检查：把最近一条旧记忆区的内容整理进前情概要，从那条回复之后接着记。
- [ ] 主通道失败或没过校验时转兜底；两次都不行，记忆保持原样、只记日志。状态和记忆一个失败不影响另一个。
- [ ] 离线试跑（需用户同意用生产 key）抽看：多人物的卡每条线都写到；没进展的检查不乱写；压缩后仍保留重要的人和事。
- [ ] 发布后 48 小时：记忆检查成功率、有进展比例、兜底比例可从日志看到；聊天页与状态接口 P95 不劣化（见下）。

## Android/iOS 性能 P95 门禁

- 受影响页面：`/chat/:id`（右侧面板多一块记忆区；面板本身是点开才加载的抽屉，不影响进页）。
- 受影响接口：`GET /api/conversations/:sessionId/status`（多读一次记忆）、`POST /api/conversations/:sessionId/status/refresh`（多一个并行的记忆检查）、新增 `PUT /api/conversations/:sessionId/memory-request`。正文生成接口只少了记忆规则，不加耗时。
- Android `/chat/:id` 站内导航 P95：基线 3764 ms（N=960）/ 目标不劣化（≤ 3950 ms，+5%）。
- iOS `/chat/:id` 站内导航 P95：基线 2766 ms（N=138）/ 目标不劣化（≤ 2900 ms）。
- 接口 P95（服务端，Cloud Metrics `st_http_server_duration_seconds`，不分平台）：`GET …/status` 基线 312 ms（N≈22,481）/ 目标 ≤ 400 ms；`POST …/status/refresh` 基线 8561 ms（N≈446）/ 目标 ≤ 9000 ms（两个调用并行，取较慢者）。客户端 `conversation_detail` 参考：Android 2324 ms、iOS 1892 ms，本任务不改它。
- 数据来源与窗口：Faro `{service_name="st-miniapp"}` `st_page_navigation`（engineering_v1、ready、foreground、production），2026-11-21 ~ 11-23 的 48 小时；接口取同窗口 Cloud Metrics。
- 发布后验证：按新 release 等长 48 小时复查同口径；iOS 样本不足 100 只看方向；状态接口在客户端归在 `other` 组，以服务端指标为准。

## 不做

- 记忆的「撤销这次更新」（撤销后下一次检查会从同样的对话再记一遍，意义不大）；面板撤销仍只撤状态。
- 玩家直接编辑记忆文字；记忆格式开放给玩家调。
- 记忆喂回正文模型。
- Surplus Gemini 截断被当成功的问题、Gemini 3.1 Flash Lite Preview 内容审核中断问题（另行处理）。
