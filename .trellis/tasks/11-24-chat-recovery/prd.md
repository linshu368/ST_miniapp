# 出字后兜底：中断或拒答 → 擦掉重写

## 背景（生产数据，2026-11-21 ～ 11-24）

- 现有兜底只管「首字前」：哪一路先出字就用哪一路，出字后其余各路全部取消。出字后出问题，用户只能拿到半段或一段拒答。
- 写到一半断掉：近 24 小时 OpenRouter · gemini-3-flash-preview 17.7%（186/1048），Surplus · gemini-3-flash-preview 18.3%（186/1014），其余模型接近 0。
- Surplus 断流时先发 `error.code = stream_incomplete` 的数据块再发 `[DONE]`，现有 SSE 解析忽略该块，于是记成 success（近 3 天 613 轮）。
- 用户要求：不依赖供应商返回的结束原因（太晚、不可靠），用我们自己的规则当场识别，规则可以有瑕疵、误判也接受；识别到就立刻启用兜底。

## 需求（用户逐条定）

1. **中断识别**：出字后连续 `stall_ms`（3000ms）没有新的可见增量（正文或已显示的思考）即判中断；流里先出现异常（错误数据块、非正常结束原因、无 `[DONE]` 断开）以先到者为准。
2. **拒答识别**：正文照常实时输出（允许用户看到拒答内容），只在正文前 `check_chars`（30）个字里找运营词池关键词（子串匹配，不要求句式，不放「抱歉」这类剧情词），命中当场判拒答、掐断首发。
3. **兜底 = 擦掉重写**：不续写。兜底模型按原 messages 从头写；兜底出第一段正文时通知客户端清空这条回复已显示的正文与思考过程，之后输出重写内容。
4. **兜底时限**：兜底模型 `fallback_first_token_ms`（3000ms）内没出第一个字就放弃；兜底不再兜底。没出字就失败时不擦，用户已看到的保持不变。
5. **计费**：救回来的按正常一轮扣费；没救回来的维持现行中断免扣。
6. **未成年人**：用户要求全部交给供应商。实现：卡顿、断开、报错等技术故障不做任何判断；只有供应商自己拒绝或内容过滤（我方拒答命中、`content_filter`）
7. **配置**：运营托管 `chat_recovery_config`：中断、拒答各一个开关；`stall_ms`、`fallback_first_token_ms`、`check_chars`、拒答词池。运营平台有专门编辑器，CLI 可读写。
8. **记录**：交付那一路出字后的结束方式（`ops.llm_calls.stream_end`）按「平台 + 模型」可 SQL 聚合；兜底调用 role = `rewrite` 单独一行记成本。

## 不做

- 首字前竞速逻辑不改（`first-token-fallback.ts`）。
- 第 2 层小模型判官（用户：成本高，暂不做）。
- 每天 LLM 抽检纠偏、「总体失败率」看板（下一个任务）。
- 按平台/模型分别配置阈值。

## 验收

- 四种中断（Surplus `stream_incomplete`、`content_filter`/`error`、无 `[DONE]` 断开、卡顿）都触发重写；重写成功 → 客户端先清空再显示重写内容，status=success 并正常扣费；兜底没出字就失败 → 不清空、与现行中断一致（保留半段、免扣）。
- 拒答命中 → 当场掐断、清空后显示重写；未命中不影响输出。
- 供应商拒绝/内容过滤且涉及未成年人 → 不重写；技术故障不做未成年人判断。
- 配置关闭时行为与现状一致（Surplus 错误块除外：关闭时也按中断记）。
- 用户停止、5400 字上限、110 秒执行上限不触发兜底。
- 旧前端不认识清空事件：流式期间显示「原内容 + 重写」，done 后按落库内容（只有重写）恢复。
- `ops.llm_calls` 能按平台+模型算出中断率、拒答率（含被救回的）与重写成功率。
