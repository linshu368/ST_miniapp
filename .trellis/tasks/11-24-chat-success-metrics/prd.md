# 聊天成功率与首发失败率监控

## Goal

用户（2026-11-24）：在 Grafana 上把聊天的成功率监控起来。大盘直接对应用户体验；同时能按首发「平台 + 模型」看失败率及其构成。数据不经 Supabase 中转，用更适合 Grafana 的时序指标。

## Requirements

1. **口径（每次调用 = 用户发起的一轮聊天，含重新生成）**
   - 用户视角失败 = 报错、中断、拒答、超时等任何原因导致用户最终没拿到正常回答；首发 + 首字兜底 + 出字后重写共同作用之后的结果。
   - 首发失败 = 首发模型自己的报错 / 中断 / 拒答 / 超时：
     - 超时：真正被首字兜底取代（兜底交付）或谁都没出字才算；兜底启动了但首发先出字不算。
     - 报错：首发出字前就失败（含由兜底交付的）。
     - 中断：首发出字后流异常结束（卡顿、流内错误、断开、供应商错误、被截断）。
     - 拒答：正文开头命中运营词池（与出字后兜底同一份，开关关着也判），或供应商内容过滤。
   - 不计入：余额/VIP 拒绝、用户停止。
2. **看板（用户定）**
   - 视图 1：每个模型的整体失败率（用户视角），直接挂钩用户体验。
   - 视图 2：每个首发模型的失败率横向柱状图，从高到低；顶部「失败类型」下拉（全部/报错/中断/拒答/超时）。选全部时按四类分色堆叠，条长 = 总失败率；选单类时只比该类。
   - 视图 3：明细表，每行一个首发模型：调用数、报错率、中断率、拒答率、超时率、总失败率，按阈值标红黄绿；调用数必须有。
   - 视图 2、3 同一行左右挨着；共用时间范围与栏目筛选（全部/付费聊天/畅聊）。
3. 所有在架模型都出现在视图 2/3 中（有调用即出现）。

## Acceptance Criteria

- [ ] 生产后端每轮聊天结束时上报 `st_chat_turns_total`，标签只含平台、模型、栏目、两个结果和救回方式，不含正文/用户。
- [ ] Grafana 看板三块视图按上面布局可用，数字与 `ops.llm_calls` / `chat_history` 抽样核对一致（允许 Prometheus 外推带来的小数误差）。
- [ ] 上报失败不影响对话（不阻塞返回、异常吞掉）。

## Android/iOS 性能 P95 门禁

- 受影响页面：无（只在服务端每轮结束后计数）
- 受影响接口：POST /api/v1/conversations/:id/messages（SSE）——出口多一次内存计数，不阻塞返回
- Android/iOS 页面加载 P95：不涉及
- 接口 P95：不变（计数在 finally 里异步执行，读的是已缓存的配置）
