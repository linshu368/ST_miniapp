# 创作者删除自己的角色卡

## Goal

创作者在「我的创作」里可以删除自己创作的角色卡。目前只能在公开和私密之间切换，删不掉。

## Requirements

- 「我的创作」卡片封面右上角加「⋯」按钮，点开是底部确认框，确认后删除（2026-11-24 用户从三种位置里选了这个）。
- 删除后：
  - 不再出现在作者的「我的创作」列表里，作者也打不开这张卡的编辑页；
  - 不再出现在任何公开页面：大厅（推荐、精选、最新、搜索）、作者主页、心愿墙的回应卡，角色详情里的作者主页链接也随之消失；
  - 已经收藏或聊过这张卡的玩家可以继续使用：收藏列表还在、旧会话能继续、能新开会话，内容保持删除前已发布的那一版；
  - 作者自己和这张卡的旧会话保留，照常可用。
- 草稿卡（从没发布过）也能删。
- 删除不能撤销，界面上不提供恢复入口。
- 删除接口按 id 幂等：重复删除返回成功；删完后再保存、发布或改可见性都返回 404。

## 2026-11-24 第二轮：删除放进「管理」

上线后用户反馈：封面 ⋯ 一点就问删除，不符合常识。对比稿里选了方案 A + 横三点：

- 卡片底部「可见性」换成只有图标的横三点 ⋯（无文字），封面不再放按钮；草稿卡也有。
- 点 ⋯ 打开管理面板：标题=卡名，副标题=状态；已发布卡有「设为私密 / 公开你的角色」，所有卡有红色「删除角色」，最下「取消」。
- 设为私密/公开 沿用原来的可见性确认框；删除沿用原来的删除确认框。

## Out of scope

- 只存在本机的草稿（「本地草稿」「修改备份」）不加删除，它们不是服务端的卡。
- 「创作数据」页的历史统计和收益记录照旧包含已删除的卡（钱要对得上，不擦历史）。
- 运营后台不加新入口：已删除的卡在运营侧表现为一张私密卡。
- 不做物理删除，也不收回玩家已有的使用权。

## Acceptance Criteria

- [ ] 公开卡删除后：作者列表没有它；大厅、作者主页、心愿回应都看不到；角色详情里的作者主页链接在作者没有其他公开卡时消失。
- [ ] 删除前收藏或聊过的玩家：收藏列表还在，能继续旧会话，也能新开会话。
- [ ] 删除前没收藏也没聊过的玩家：拿着链接也打不开（与私密卡一致）。
- [ ] 删除后对同一 id 调保存、发布、改可见性、编辑页读取，都返回 404；重复调删除返回 200。
- [ ] 别人的卡、不存在的 id：返回 404。
- [ ] 确认框可以右滑或点遮罩关掉；删除中按钮不可重复点击；失败时在确认框内提示，卡片保留。

## Android/iOS 性能 P95 门禁

- 受影响页面：`/creation`（「我的创作」列表多一个按钮和确认框，不新增首屏请求）
- 受影响接口：`GET /api/creator/characters`（多一个 `deleted_at IS NULL` 过滤）；新增 `DELETE /api/creator/characters/:id`
- Android 页面加载 P95：基线 958 ms（N=765）/ 目标 ≤ 1010 ms（不劣化，+5% 以内）
- iOS 页面加载 P95：基线 771 ms（N=207）/ 目标 ≤ 810 ms
- 接口 P95：`GET /api/creator/characters` 服务端基线 241 ms / 目标 ≤ 260 ms；新接口没有基线，目标 ≤ 500 ms（一次事务内的单行更新）
- 数据来源与观测窗口：Grafana Loki Faro `st_page_navigation|launch|ready`（engineering_v1、ready、foreground、production、context_route=/creation），接口用 Prometheus `st_http_server_duration_seconds`；窗口为 2026-11-22～2026-11-24 的 48 小时
- 发布后验证：用同样的口径，在新版本上线后复查 48 小时；删除接口样本少，只看有没有 5xx 和超时，样本不足 100 时只看趋势
