# 创作与新手引导界面验收用例失效排查

## Goal

`pnpm test:ui` 的 `@creator`、`@onboarding` 在 dev 上大面积失败（2026-11-24，干净 dev `3e5ff99c`：两种屏宽合计 23 失败 / 24 通过）。先查清每条失败出在哪、是测试过时还是产品问题、该不该修，再定修法。

## 背景

- `packages/ui-tests` 不在 CI 里跑（`.github/workflows` 没有引用），产品改动后没人同步更新，所以坏了没人发现。
- 失败都出现在 11-18～11-19 的两次产品改动之后：状态栏 v2（发布必须有状态栏、聊天页多了状态接口）、工具箱精简（「玩法小贴士」重写）。

## 结论：该修

- 都不是线上功能坏了：#1、#2、#4–#8 是测试没跟上产品；#3 是代码和项目约定不一致，用户侧暂无影响。
- 但这套用例是创作、新手引导、聊天改动后唯一能一键回归的手段，现在坏着等于没有；#4/#6 一个缺失接口就让所有进聊天页的用例失败。
- 修起来都很小：测试辅助函数补一步、改两处文案/数字、模拟服务补一个接口、`newStatusId` 改用 `createUuid`（一行，产品代码）。

## Requirements

- `fillCharacter` 选一个状态栏示例；157 的必填数改成当前值。
- 模拟服务补 `GET /api/conversations/:id/status`：放在已有的 `fixtures/memory-panel.ts`，非记忆场景返回"卡无状态栏、记忆栏关闭"（与 fixture 的 `pref_show_memory: false` 一致，面板不出现，不改变现有页面布局）。refresh/memory-request 只有面板打开后才会调用，非记忆场景用不到，不补。
- roleplay 3 条改成点角色名进详情、再切「评论」页签。
- 愿望种子卡补状态栏示例。
- onboarding 62 的断言改成新版小贴士里的文案。
- `newStatusId` 改用 `createUuid()`，和项目里其他 ID 生成保持一致。
- 不改用例的验收意图，不删用例。

## Out of scope

- 把 ui-tests 接进 CI（单独讨论：跑一次 7–8 分钟，要不要进 PR 门禁需要用户定）。
- 全量跑出的、与上述原因无关的失败（只记录，不在本任务修）。
