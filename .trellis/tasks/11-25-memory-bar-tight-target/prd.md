# 记忆栏压短目标收紧 + 记忆栏首发模型单独配置

## 背景

11-25 记忆栏整体成功率约 81%，失败主要是兜底内容检查没过；兜底尝试里约 28% 是「压短后仍超长」（compress_too_long：中档上限 120 字、远档 45 字）。

离线重放（40 个线上真实案例，提示词与参数同线上）：

| 模型                                 | 现提示词（中档目标 100 / 远档 35） | 收紧（70 / 25，并写明原文字数） |
| ------------------------------------ | ---------------------------------- | ------------------------------- |
| deepseek-v4-flash（OpenRouter 兜底） | 通过 71%，压短超长 22/80           | 通过 94%，压短超长 5/80         |
| deepseek-v4.1-flash-1017（Surplus）  | 通过 90%，压短超长 8/80            | 写完整的输出里压短超长 0        |

根因：deepseek 系（关思考）输出长度以目标为中心、方差大，上限只比目标宽 20%/28%，尾部超限。提示里的目标收紧后，分布整体下移，尾部落进上限。

用户 11-25 定：记忆栏首发以后用 Surplus 的 deepseek-v4.1-flash-1017；状态栏不跟着换（状态栏刚上线显示修复，正在按 release 复核）。

## 需求

1. 记忆栏压短的提示目标：中档 100→70 字、远档 35→25 字；每段压短任务写明原文字数。校验上限（120/45）不变。首发、兜底同一套提示词。
2. `status_memory_model_config` 增加可选字段 `memory_primary_model`：记忆栏首发用它，没填就沿用 `primary_model`。状态栏不受影响；兜底仍两者共用 `fallback_model`。
3. 运营后台的模型编辑器能填写/清空这个字段；admin CLI 随 admin-client 注册表自动支持。

## 约束

- 配置 schema 是 `.strict()`：旧后端读到新字段会整体判配错、退回默认模型（Gemini）。**必须先发后端，再发布运营配置。**
- 不改通道参数（Surplus 流式、4 秒首字、关思考；OpenRouter 非流式）。

## 不做

- 远档记录近似重复（同一件事记几段）的问题。
- Surplus 卖家内容审核拦截（`data_inspection_failed`，时有时无，实测 0%~32.5%）：被拦按首发失败转兜底，上线后看看板再定。

## 验收

- shared 测试：压短任务提示含「原文 N 字」和新目标；超长问题文案用新目标。
- backend 测试：记忆栏首发用 `memory_primary_model`，没配时用 `primary_model`；状态栏首发始终用 `primary_model`。
- 上线并发布配置后：st-panel-quality 看板记忆栏 compress_too_long 明显下降（基线：兜底尝试约 28%）；记忆栏首发错误码分布可观测。
