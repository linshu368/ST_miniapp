# 聊天看板加兜底模型视图（付费 / 畅聊分开）

## 背景

看板「聊天｜成功率与首发失败」（Grafana `st-chat-success`）只按首发模型记每轮结果和「被谁救回」（`st_chat_turns_total`），兜底那一路自己的结果和失败原因没有记录。付费轮次兜底走 OpenRouter 1017，畅聊（11-26 起）走 Surplus 1017，要分开看。兜底之后再没有补救，所以用户关心兜底成功率与失败原因。

## 需求（用户 2026-11-26 原话要点）

- 新增「兜底模型」视图，付费与畅聊分开记录、分开展示。
- 关心兜底成功率；失败时看到失败原因。
- 「没用上」（兜底发出后首发先出字）不算失败、也不记：对大盘失败率没有贡献，不看。

## 口径

- 只记「兜底真正决定用户结果」的调用：
  - 首字兜底：只在首发没能交付（首发各路都报错或没抢到首字）时记；
  - 出字后重写：每次真正发出重写都记（开关关着、来不及等没发出的不记）。
- 维度：栏目（付费 chat / 畅聊 free_zone）、兜底种类（首字兜底 / 出字后重写）、启动原因（首字兜底：首发超时 / 首发报错；重写：中断 / 拒答）、兜底平台 + 模型、结果、细分原因。
- 结果：成功、报错（出字前失败，细分到上游状态码，如 404 / 429 / 5xx / 网络错误）、超时（到首字总上限没出字）、中断（出字后卡住 / 流内出错 / 断开 / 被截断）、拒答（内容过滤或命中拒答词池）。用户自己停止的不计。
- 兜底成功率 = 成功 ÷ 记下的兜底次数。

## 验收

- 后端指标 `st_chat_fallbacks_total` 按上述维度计数；首发交付的轮次不产生记录。
- 看板新增一组视图：付费 / 畅聊兜底成功率（首字兜底、出字后重写分开）、明细表、失败原因分布、按小时走势；「口径说明」补兜底段。
- 仓库 `docs/grafana/st-chat-success.json` 同步。
- 数据从部署起开始累计，之前的不补。
