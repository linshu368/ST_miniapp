# 畅聊保上 + 畅聊专用兜底通道

## 背景

11-24 起畅聊只剩手动上下架 + 连续拒单自动下架（≥10 次且首尾隔 ≥10 分钟）。保上随旧评估机制一起删了。
1017 在 11-25 20:01 因连续 28 次拒单被自动下架，用户 11-26 10:35 手动上架。
畅聊兜底与付费档位共用模型目录的兜底（OpenRouter deepseek/deepseek-v4.1-flash-1017，供应商 Together/crusoe）。

## 需求（用户 2026-11-26 原话要点）

### R1 保上

给模型加了保上以后，不再检查、不再下架。

- 保上的在架模型：连续拒单不自动下架（照常计数、记日志，不落库下架）。
- 手动下架仍可用，同时取消保上（沿用 #1074 的语义）。
- 点保上时没在架：顺手按「立即上架」的默认规则上架；上不了也保留标记并提示。
- 运营平台状态面板显示保上标记和按钮；CLI 有对应命令。

### R2 畅聊专用兜底通道

畅聊的兜底单独开一个模型通道，不和付费模型的兜底混在一起；运营平台上区分体现。

- 暂定 Surplus 平台的 `deepseek-v4.1-flash-1017`。
- 调用参数仿照现在畅聊调用 1017 的方式（Surplus、钉住供应商 mistral、思考参数按供应商处理、流式带 usage），区别：
  - **不设折扣底线**：作为兜底时不限折扣，原价也照样调用，不能因为折扣不达标不派单（这是它和畅聊候选身份的区别）；
  - **性能优先**：Surplus 路由目标用 `latency`（同价格带内按实测 p50 最快排），价格带放宽。
- 兜底不计入连续拒单、没有上下架状态。
- 覆盖畅聊轮次的全部兜底：首字前兜底（超时 / 报错）和出字后擦掉重写（中断 / 拒答）。付费轮次完全不变。
- 运营平台：畅聊页新增「畅聊兜底」；模型目录里原兜底标成「付费档位兜底」。未配置时沿用模型目录兜底（即现状）。

## 验收

- A1 保上的在架模型连续拒单不下架，日志可见被跳过；未保上的行为不变。
- A2 手动下架取消保上；取消保上不改在架状态；保上未在架的模型会尝试上架。
- A3 配置畅聊兜底后，畅聊轮次首字兜底和出字后重写都发往 Surplus 1017：请求不带 `X-Min-Discount`，带 `X-SI-Route-Objective: latency` 和配置的价格带，钉住配置的供应商；付费轮次仍走 OpenRouter 1017。
- A4 Surplus 兜底赢得交付时，交付、扣费（畅聊 0 星尘）、首发记录、调用台账都正确，不与首发 Surplus 记录冲突。
- A5 兜底调用的成本能补上（按 Surplus 请求号查请求记录），汇总进每轮成本。
- A6 畅聊兜底留空 = 回到现状；运营平台能一键恢复。

## 范围外

- 不改付费档位兜底、首字时限参数、出字后兜底开关与关键词。
- 不恢复旧的初筛、评估、自动换供应商、冷却。
- 不加兜底的兜底。

## 追加（2026-11-26 晚，用户）：Gemini 3 Flash 首字优先挑供应商

- 用户原话：调用 Surplus 的 Gemini 3 Flash 时改为首字耗时优先来确定供应商，在折扣 85% 以上的时候。
- 做法：候选加 `route_objective`（留空 = 统一可靠优先；latency = 首字优先），设了就把价格带放到最宽，让底线以上的卖家都按首字排；价格上限仍是候选的折扣底线。运营平台线上状态表加「派单」列。
- 配置（发布前给用户看差异）：Gemini 3 Flash Preview `min_discount_pct` 70 → 85，`route_objective` → latency。
- 验收：首发请求头带 `X-Min-Discount: 85`、`X-SI-Route-Objective: latency`、放宽的价格带；白名单 google、屏蔽阿里不变；其他候选不受影响。
