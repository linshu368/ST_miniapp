# 立即更新改为所有人可用、每次 6 星尘

## 背景

聊天页右侧状态面板的「立即更新」（状态栏 + 记忆栏一起更新）现在仅限 VIP，不扣星尘。
2026-11-26 用户决定：取消 VIP 限制，所有人都能用，每次 6 星尘；要让用户知道收费，但日常使用时尽量没有付费感。
对比稿：`ST_miniapp/labs/status-refresh-pricing/状态面板-立即更新收费-对比稿.html`（选定 B 版）。

## 用户已定

1. 所有人（含 VIP）点「立即更新」每次 6 星尘；VIP 不再免费。每 3 轮的自动更新照旧免费。
2. 先扣专项星尘，不够再扣通用星尘（`main_then_bonus`）。
3. 面板用 B 版「只在第一次说」：第一次点弹一张说明卡（6 星尘 / 次、自动更新不花星尘、没更新成功不扣），之后按钮只写「立即更新」；标题旁「每 3 轮自动更新」后面加小问号，点开看价格。

## 沿用的默认（已向用户说明，未反对）

- 状态和记忆一起更新，只收一次。
- 没更新成功、什么都没变，不扣。
- 撤销不退星尘。
- 60 秒限频保留。
- 价格写在代码常量里（改价要发版），不进运营平台。
- 不弹二次确认、不在面板显示余额、扣费时不做「−6」动效。
- 余额不够时才出现「去充值」，充完回到这段对话。
- 钱包明细记一笔「状态更新」，显示通用 / 专项各扣多少。

## 需求

- R1 后端：`POST /api/conversations/:sessionId/status/refresh` 去掉 VIP 校验；调模型前检查余额（通用 + 专项 ≥ 6），不够返回 402 `INSUFFICIENT_CREDITS`，不调模型、不占限频。
- R2 后端：这次请求自己发起的状态更新记下了新状态（ok / partial），或自己发起的记忆检查记下了新记忆（recorded），且接口返回成功时，扣 6 星尘；其余情况（失败、没进展、没有新轮次、撞上进行中的自动更新而只是等它的结果）不扣。
- R2b（用户 11-26 补充）：成功的口径是「状态栏或记忆栏任一处出现了更新」——状态栏有几项没对上格式（partial）也算；状态栏失败但记忆栏记下了新内容，也算成功、照常扣费、接口不报错。两处都没有更新才算失败。
- R3 数据库：一次扣费在 `billing.usage_charges` 记一行（新 `kind = 'status_refresh'`，`subject_id` = 会话 id），同一事务经 `billing.apply_wallet_debit` 写 `billing.wallet_ledger`（新 `entry_type = 'status_refresh'`），专项优先。以 charge id 幂等。
- R4 前端：按 B 版改面板底部与标题；去掉 VIP 角标与跳 `/vip`；余额不够时底部显示「星尘不够了 · 去充值 ›」；失败文案写明没扣星尘；更新成功后刷新钱包缓存。
- R5 钱包明细：新增「状态更新」记录，带通用 / 专项拆分。
- R6 文案：「我的」页专项星尘说明从「轻量档对话专用」改成包含状态更新；代码注释里"VIP 手动、不扣星尘"的描述全部更新。

## 不做

- 不改自动更新节奏、模型通道、提示词。
- 不做次卡 / 每日免费次数 / VIP 折扣。
- 不把价格放进运营平台。
- 不给撤销退款。

## 验收

- A1 普通用户与 VIP 都能点「立即更新」；第一次点出现说明卡，点「更新」才开始，点「先不用」不更新；之后再点直接更新，不再出卡（同一浏览器）。
- A2 更新成功：钱包少 6（专项够时全扣专项；专项不够时专项扣光、余下扣通用）；钱包明细出现「状态更新」；`usage_charges` 一行 `status_refresh / charged / 6`，`wallet_ledger` 一行 `status_refresh / -6`，两者互相指向。
- A3 更新失败、记忆没进展且状态栏关着、撞上进行中的自动更新：不扣费，`usage_charges` 不新增 charged 行。
- A4 余额 < 6：不调模型，返回 402，面板底部显示「星尘不够了 · 去充值 ›」，点了跳充值页并带回跳地址；限频不被占用。
- A5 扣费那一刻余额被别处花掉（或被聊天预留占住）：更新结果照常返回，不扣费，记 warn 日志；不出现负余额。
- A6 同一 charge id 重复调用扣费函数只扣一次。
- A7 迁移在 TEST 与生产执行后：两个 CHECK 约束都包含 `status_refresh`，`apply_wallet_debit` 只改了类型白名单那一行，新函数只授予 `service_role`。
