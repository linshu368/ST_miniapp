# 出字后重写：思考跟开关走、显示出来的思考算出字

## 背景

st-chat-fallback 看板（11-26 晚 → 11-27 上午）上，免费畅聊的出字后重写成功率很低：

|                          | 首发拒答                     | 首发出字后中断               |
| ------------------------ | ---------------------------- | ---------------------------- |
| 付费（OpenRouter 1017）  | 40 次，成功 95%              | 76 次，成功 92%              |
| 免费畅聊（Surplus 1017） | 92 次，成功 50%，首字超时 42 | 54 次，成功 44%，首字超时 30 |

失败几乎全是重写首字超时，只有 4 次是被再次拒答。

根因：

- 重写固定关掉思考（`createRecoveryForward` 里 `thinkingEnabled: false`），而且只认正文首字。
- DeepSeek 在 Surplus 上关不掉思考（11-12 实测 effort=none 照样先想），思考时间全耗在 `fallback_first_token_ms` 里。
- 日志能对上。Surplus 重写成功的那些，正文首字中位 2.66 秒、最长 3.49 秒；失败的都停在当时的 3.5 秒时限。
- 同一个 1017 在首字兜底里，思考算出字：中位 2.3 秒，3.5 秒内出字 86%。

## 需求（用户 2026-11-27 原话要点）

用户定：把「重写不显示思考过程」这条规则去掉（「这是完全不合理的」），重写和首发一样。付费、免费畅聊都适用。

1. **思考开关**：重写给上游的思考参数跟用户的「深度思考」开关走，与首字兜底完全一致。
   - OpenRouter：`reasoning.enabled` 按开关。
   - Surplus：思考强度按开关取 medium 或 none。
2. **显示规则**：重写的思考过程是否显示，与首发同一规则（`revealsReasoning`）。
   - 付费：按用户开关。
   - 免费畅聊：一律显示。
3. **思考算出字**：在 `fallback_first_token_ms` 内出了要显示的思考或正文，就算出字，不再放弃。
   - 卡顿计时（`stall_ms`）从第一次出字起算，思考增量也算进度。
4. **擦除时机**：重写第一次出字时（思考或正文都算）下发 `reset`，客户端清空原来的正文与思考，之后显示重写的思考和正文。
5. **救回判定不变**：重写正常结束且有正文才算救回，按正常一轮扣费。
   - 擦掉后只出了思考、没出正文就失败：没救回，按中断免扣。
   - 这种情况落库正文为空（与屏幕一致：只剩重写的思考），思考不落库，沿用现状。

## 不变

- 首字兜底（出字前）的行为、各路时限、`chat_recovery_config` 契约与取值。
- 未成年人判断、拒答检测（重写那一路仍不做拒答检测）、5400 字正文上限（只数正文）。
- 前端、数据库、运营平台、计费。

## 验收

- 付费、用户关思考：重写请求体仍是 `reasoning: { enabled: false, exclude: true }`，不显示思考。
- 付费、用户开思考：重写请求体 `reasoning: { enabled: true, exclude: false }`，思考显示且算出字。
- 免费畅聊（开关关）：重写先出思考时，思考显示、算出字，不会因为正文首字时限被放弃；`reset` 在第一段思考之前。
- 重写只出思考后卡住：已擦掉，没救回，按中断结算。
- 发布后 24 小时看 st-chat-fallback：
  - 免费畅聊重写的成功率（拒答 50%、中断 44%）明显上升，目标 ≥ 85%。
  - 首字超时（`first_token_deadline`）占比下降。
  - 付费成功率不降。
