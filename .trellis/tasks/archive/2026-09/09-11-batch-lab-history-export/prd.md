# Batch Lab 历史、复用原文与导出

## 1. 目标

实现实验历史、完整配置复制、复用原文实验、轻量备注和可追溯 JSONL 导出。 本任务是父任务的“历史血缘、复用与导出”交付单元，必须独立实现、验证和归档。

## 2. 前置依赖

- 09-11-batch-lab-backend-execution
- 09-11-batch-lab-postprocessing
- 09-11-batch-lab-frontend-workbench

依赖不是目录层级的隐含顺序；依赖任务的契约、迁移或证据未完成时，本任务保持 Blocked，不用临时 mock 冒充集成完成。

## 3. 必须交付

- 倒序历史、分页/筛选、详情直接来源与最初生成来源
- 复制完整 A/B/样本/模式/目的为新草稿并保持深复制隔离
- 全部样本全部轮次 reuse display tasks，generation task=0
- 实验/样本/可选轮序备注与标签 upsert（排期后置时显式标记）
- Backend 流式 JSONL 一样本一行、schema version和 attachment
- 失败/blocked/unknown、完整输入/组合/结果/血缘和备注导出

## 4. 明确不做

- 重新生成模型输出
- 独立展示历史
- 自动评分
- 导出时重新查询源库或临时重算事实

不得借本任务增加父 PRD 和 HTML 原型没有的功能。若实现发现父需求冲突，返回父规划评审，不静默扩面。

## 5. 通用约束

- 应用包之间只通过 HTTP/shared contract 协作；浏览器不使用数据库 row、service-role或密钥。
- 所有外部调用有明确超时；重试有限且仅用于安全操作；关键写入以数据库约束/事务/幂等键裁决。
- test 与 production 分开记录环境、指纹和证据；生产变更不随应用发布自动执行。
- 原始错误以 `{ err }` 记录；日志只含 allowlist 摘要、内部 ID、环境、状态和耗时，不记录 SQL敏感值、完整 prompt/回复或 token。

## 6. 验收标准

- [ ] 复制后修改新草稿不改变来源实验
- [ ] reuse 保存新实验、保留 A/B真实原文来源且模型调用数为零
- [ ] 部分失败仍可导出且每个失败项明确存在
- [ ] JSONL 每行通过 shared schema且无需源库即可还原本次输入/组合/窗口/结果
- [ ] 大实验流式导出有取消/超时/容量限制，不把正文写日志
- [ ] 失败、空、部分成功、未授权、超时、重复提交与环境错配路径均有自动测试或可重复人工证据。
- [ ] 受影响消费者、文档和 module facts 已按本任务责任更新或向最终收口任务提供审核 payload。
