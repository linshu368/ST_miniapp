# 预设批量调试平台 V1

## 1. 背景与目标

在 `packages/` 下新增一个内部使用的预设批量调试平台。业务人员可以从真实会话按 SQL 抽取并冻结样本，在相同输入上批量比较 A/B 两套“模型参数 + 输出预设 + 后处理”完整组合，查看单轮或固定用户输入的连续多轮结果，持久化历史并导出 JSONL。

本期目标是建立可追溯的批量比较能力，不自动判断赢家，不把离线结果解释为业务收益。

需求事实来源：用户提供的《批量调试平台 · V1 工程需求说明》（2026-09-10，v1.0）和 `batch-lab-prototype` HTML 原型。需求说明决定业务范围与验收，原型决定页面、布局和已有交互；冲突时以需求说明为准。

## 2. 使用边界

- 面向内部业务/研发人员。V1 不实现用户登录、账号、角色或应用内权限页面；访问范围由 Vercel 项目、域名和现有基础设施控制，不在本需求内扩展身份系统。
- 密钥、service-role、数据库连接和供应商鉴权只存在于 Backend，不进入浏览器、日志或导出。

## 3. 必须交付

### 3.1 独立应用与页面

- 新应用位于 `packages/batch-lab`，使用当前 monorepo 的 Vite、React 18、TypeScript strict、TanStack React Query、Ant Design/Zod/shared contract 等既有技术结构。
- 参考 Admin/CS Platform，作为独立 Vercel 静态 SPA 托管，提供包内 `vercel.json`、SPA rewrite 和独立 Vercel Project；不新增 Railway 前端服务或前端 Docker/GHCR 镜像。
- CI 在现有 quality gate 中显式运行 Batch Lab test/build；根 typecheck、lint 和跨包 import guard继续覆盖新 workspace。
- 主导航保留：实验记录、样本集、富文本后处理；提供“新建实验”。
- 覆盖原型中的列表、创建/配置/确认、进度、逐样本逐轮对比、原文/富文本切换、差异、备注/标签、后处理编辑预览、复用原文和 JSONL 导出交互。
- 尽量复用现有模式或提取最小公共能力；应用包之间不得直接 import。

### 3.2 样本集

- 提供工程预置的只读 SQL 模板；模板参数真实绑定最终 SQL，同时允许直接编辑 SQL。
- 页面包含模板、参数、抽样数（默认 50，可调整）、名称、SQL 编辑和预览。
- 预览显示实际条数、用户数、会话数、角色数，可浏览全部样本与上下文。
- 重复锚点去重；不足数量按实际展示；零条不可创建可运行样本集。
- 保存必须冻结当前预览的同一批 ID 和完整内容，不能重新抽样；SQL/参数改变后旧预览失效。
- 样本保存来源锚点、有序历史、角色和动态输入、原始线上回复/模型配置（可获得时）、还原状态与排除原因。仅有 ID 或 SQL 不算完整快照。
- 保存后不可覆盖修改；变化通过创建新样本集完成。

### 3.3 A/B 完整组合

- A/B 各自编辑模型及真实生效参数、完整预设、对应后处理规则；不支持的参数不得显示为已生效。
- “从 A 复制整套组合”必须复制模型、参数、预设和规则，且复制后 B 修改不影响 A。
- 实验名称必填，实验目的选填；运行时配置冻结，历史配置不可被后续修改。
- 内联修改的后处理必须校验并保存为不可变新版本后才能启动。
- 确认页展示样本规模、排除原因、A/B 完整组合、运行模式、X、计划调用次数及模型/参数/预设/规则真实差异。

### 3.4 批量执行

- 单轮：锚点前冻结历史 + 当前用户输入，A/B 各生成一次；旧回复和锚点后信息不进入请求。
- 连续最后 X 轮：X 为至少 2 的整数，不限于原型中的 2/3；窗口前历史固定，用户输入逐字保留，A/B 分支只接入各自前序新原文。
- 后处理结果不得进入下一轮模型上下文；无法可信还原历史/动态状态的样本须明确排除或标记固定起点策略，不静默缩短 X。
- 计划调用次数为有效样本数 × 2 × 轮数，不包含失败重试；复用原文为 0 次。
- 确认后后台执行；刷新、关闭页面或 Backend 重启后可恢复；重复启动不得创建重复运行。
- 不写真实会话、不更新用户记忆、不扣用户钱包。供应商调用仍可能产生研发费用。

### 3.5 后处理与展示

- 支持“不处理”和不可变规则版本；可复制已有版本、编辑名称/代码、粘贴原文、运行预览、保存新版本、用于实验。
- 首版至少兼容原型的有序 JSON 正则替换协议；是否适配线上其他协议须以开工核对结果为准，不提供任意 JavaScript 执行器。
- 区分语法错误、运行错误和零匹配；错误时保留原文，不以空白替代。
- 富文本只在专用区域按允许列表清洗后渲染；原文、代码按文本转义。
- 尽量复用线上 Markdown、清洗、消息宽度和样式；无法精确还原时明确标注。
- 历史结果可选择新规则对全批次全部轮次重新处理，并保存为统一的“复用原文”实验；原实验不变且新增模型调用为零。

### 3.6 状态、失败恢复与历史

- 实验状态：等待、运行中、完成、部分失败、失败。
- 单轮生成状态：等待、运行中、成功、失败、前序失败阻塞；后处理状态：等待、成功、失败，零匹配为附加信息。
- 单项失败不阻塞独立分支；分支第 k 轮失败则后续轮次阻塞。重试从失败轮继续，沿用已成功前序，不重跑无关成功项。
- 生成成功但后处理失败只重试处理；空输出/截断保留真实内容和 finish reason。
- 实验列表按时间倒序；详情支持全部样本/轮次、上下文、A/B 来源、完整组合、差异、失败入口和复制配置。
- 人工备注/轻量标签保留但不参与评分；排期紧可后置，不阻塞主链路。

### 3.7 导出

- JSONL 一行一个样本，含 schema version、实验/来源关系、样本锚点和上下文、模式/窗口、两套完整组合、每轮固定用户输入、有效请求、A/B 原文、处理产物、状态/错误、结果 ID、配置差异和已保存备注。
- 部分失败也可导出，不能静默丢项；导出不依赖再次查询当前线上库，不包含任何密钥。

### 3.8 Backend、Supabase 域与环境预留

- 所有浏览器业务请求统一访问 `packages/backend`；Batch Lab 不直连 Supabase 数据表。
- 在 Supabase 新增独立 `batch_lab` schema/域，专门保存平台模板元数据、样本快照、后处理版本、实验、组合快照、生成尝试、展示结果和备注。
- Batch Lab 数据不得写入真实 `experience.chat_history`，真实业务域不得反向依赖 `batch_lab`。
- 原型暂不增加 test/production 切换按钮；样本 SQL 来源环境由 Backend 部署配置选择并在 UI 持续显示，默认 test。V1 不包含生产样本合规、脱敏或审批工作流。
- 来源环境连接必须使用专用数据库只读凭据和 `READ ONLY` 事务，对来源业务 schema 只有必要 `SELECT`，无 `INSERT/UPDATE/DELETE/DDL` 权限。SQL 文本检查只是提前反馈，数据库只读权限才是最终边界。
- 平台自身只允许向独立 `batch_lab` schema 写入冻结样本和实验数据；不得使用来源只读连接写任何环境业务数据。来源读取与平台写入使用不同 client/凭据，即使位于同一 Supabase project 也不得混用。
- Backend 配置保持最小：来源环境标识、来源只读连接、现有平台写库配置、Batch Lab 前端 origin、必要的 SQL/生成/worker/后处理硬上限与开关；不为 V1 增加登录、角色、审批、生产 allowlist或通用多数据源配置。

## 4. 明确不做

- 自动大模型评判、评分导入、综合评分、显著性看板或自动判断赢家。
- 线上流量 A/B、自动上线、自动修改真实会话、钱包或记忆。
- 自动模拟用户后续回复。
- 独立“先跑 3 条”流程、可视化条件组合器、SQL/可视化双入口。
- 独立展示历史、独立组合模板库、模板管理后台、通用 BI、复杂权限。
- 用户登录、账号/角色管理、生产样本合规、脱敏和审批流程。
- 任意 JavaScript 后处理执行器、完整 Telegram 外壳、流式动画或未在需求/原型出现的新功能。

## 5. 验收标准

- [ ] S1–S4：SQL 参数/编辑、预览冻结一致性、快照不可变、零条/重复/不足/缺失历史均符合需求。
- [ ] C1–C3：完整组合复制隔离、预设与规则联动冻结、可选实验目的完整保留。
- [ ] G1–G5：单轮/多轮调用数、分支上下文、失败阻塞与恢复、刷新恢复和启动幂等正确。
- [ ] P1–P4：规则不可变版本、错误分类、原文保留、后处理不进上下文、复用原文零生成。
- [ ] D1/R1：真实配置差异和所有样本/轮次/来源可浏览。
- [ ] E1/E2：JSONL 可解析、信息完整、失败项和复用来源准确。
- [ ] 新包遵守 monorepo 边界，所有 API 使用 shared contract 与 Backend，浏览器不含密钥或数据库行类型。
- [ ] 新包可由独立 Vercel Project 构建为静态 SPA；CI 显式覆盖 Batch Lab test/build，且不新增 Railway前端服务或前端镜像。
- [ ] `batch_lab` 域迁移先在 test 单文件验证 shape、权限、锁/容量和回滚；迁移仍按仓库规则手动执行，不随应用部署自动运行。
- [ ] 样本来源环境可通过 Backend 配置选择，UI 显示真实环境，缓存/任务/导出不串环境。
- [ ] 来源连接在数据库权限和事务两层只读；写 SQL、函数副作用及对来源业务 schema 的任何写入均失败，平台写入只发生在独立 `batch_lab` schema。

## 6. 开工阻塞项

以下内容必须在实现对应阶段前通过只读实况或代码核对确认，不能靠猜测：消息到 turn 的有效链路、角色/动态记忆快照可用性、真实生成免用户计费接缝、模型/预设有效参数、初始 SQL 模板与业务口径、线上后处理/渲染协议、来源环境专用只读数据库凭据。

## 7. 子任务交付结构

本需求按独立可验证边界拆为七个 Trellis 子任务：

1. `09-11-batch-lab-foundation`：工程骨架、Shared 基础契约、API client、环境展示、Vercel 与 CI部署。
2. `09-11-batch-lab-data-samples`：`batch_lab` 数据域、只读来源环境、SQL preview 与样本冻结。
3. `09-11-batch-lab-postprocessing`：不可变后处理、安全隔离执行与 renderer/display result。
4. `09-11-batch-lab-backend-execution`：A/B 冻结配置、唯一生成出口、持久 worker、单/多轮和失败恢复。
5. `09-11-batch-lab-frontend-workbench`：原型全部页面、向导、进度和逐样本逐轮工作台。
6. `09-11-batch-lab-history-export`：历史、复制、复用原文、备注与 JSONL。
7. `09-11-batch-lab-integration-spec`：跨子任务验收、容量/安全、Vercel/CI发布恢复和 Spec 收口。

父任务自身不直接承接产品代码。任一子任务不能以“后续集成再补”为由遗漏自己的失败路径、验证、文档 payload 或恢复方案。
