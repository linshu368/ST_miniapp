# Batch Lab 原型一致性修复规划

## Goal

以用户提供的 `D:\download\批量调试平台 · V1 工程需求说明\批量调试平台 · V1 工程需求说明.md` 和 `D:\download\批量调试平台 · V1 工程需求说明\图片和附件\batch-lab-prototype.html` 为权威输入，修复当前 `packages/batch-lab/` 与后端 Batch Lab 接口的偏差，使页面结构、字段、动作、详情查看、富文本后处理、样本集管理和实验配置达到原型 V1 的完整行为。

本任务是已归档父任务 `.trellis/tasks/archive/2026-09/09-11-batch-lab-platform-planning` 的补齐与纠偏任务。原 09-11 任务已完成基础接入、样本冻结、后处理、执行、历史导出等骨架，但当前产品化体验仍缺少原型要求的多个关键入口和详情数据。

## Requirements

- 样本集页面必须补齐原型中的样本集管理体验：
  - 样本集列表提供“查看样本”和“删除/归档”功能。
  - 查看样本必须展示冻结 SQL、参数、统计信息、样本分页、样本上下文、原始在线回复、模型、轮次、revision、角色/用户/会话来源信息。
  - 创建样本时必须提供“当前轮次至少”等轮次条件，并将轮次条件绑定到 SQL 模板参数和最终冻结 SQL。
  - 预览与保存仍必须禁止空样本、禁止来源环境错配、禁止写来源库。
- 实验记录页面必须符合原型：
  - 列表不提供“启动”按钮，页面头部也不提供手动 worker “执行任务”按钮。
  - “查看/查看对比”必须实现原型中的完整对比详情，而不是只显示摘要抽屉。
  - 详情必须覆盖 A/B 配置差异、实验目的、进度、失败摘要、样本/轮次切换、上下文、原文/富文本切换、后处理版本、备注、导出入口、复用原文入口。
  - 历史列表必须区分生成实验和复用展示实验，并显示样本集、模式、状态、时间、来源链路。
- 富文本后处理页面必须符合原型：
  - 预览处理必须展示解析后的富文本，而不是只显示松散 HTML。
  - 预览容器必须按手机消息宽度显示，包含命中数、状态、示例样式和错误降级显示。
  - 保存成新版本后，底部版本列表必须立即刷新并能复制已有版本继续编辑。
  - “不处理”版本仍必须可用于实验。
- 新建对比实验必须符合原型：
  - 增加“本次想验证什么 · 选填”。
  - 模型配置页面收敛为 `url`、`key`、`模块名`等用户要求字段；其中真实 secret 不得进入浏览器、日志、源码或 Markdown，`key` 在实现中只能作为后端配置引用/密钥引用，实际密钥由后端运行时配置或受控存储解析。
  - 补齐原型中的“输出预设 · 规定内容与格式”和其他运行参数。
  - 继续支持 A/B 完整组合、单轮/连续多轮模式、确认页、运行规模、差异表和启动前校验。
  - 创建流程的“启动/运行”行为必须按原型集中在新建实验确认流程中，实验记录页不再重复启动。
- 后端和共享契约必须提供前端所需的真实数据，不允许用 mock、JSONL 下载结果或前端拼凑替代详情接口。
- 所有新增 API 必须先在 `packages/shared/src/api/batch-lab.ts` 定义契约，再接入 backend route 和 `packages/batch-lab/src/api/client.ts`。
- 所有 route 必须保留附近 `@frontend-ready: true|false` 注释。
- 所有数据库变更只能新增迁移到 `packages/shared/migrations/`，手动执行，附带测试环境验证与回滚/forward-fix 说明。
- 不得记录 token、API key、完整 prompt/source row、大响应正文或个人敏感信息。

## Acceptance Criteria

- [ ] 样本集列表可查看冻结样本详情，并支持安全删除/归档；已有被实验引用的样本集不能破坏历史实验。
- [ ] 样本创建表单包含轮次条件，模板参数、预览请求、最终 SQL、冻结样本集详情均能追踪该条件。
- [ ] 实验记录页面移除启动和 worker 按钮，仅保留原型中的查看/复制/导出/复用等历史操作。
- [ ] 查看对比页面/抽屉实现原型完整信息架构：差异、目的、进度、样本导航、轮次导航、上下文、原文/富文本、备注、导出和复用原文。
- [ ] 富文本后处理预览使用手机消息宽度容器渲染解析后的富文本，显示命中数和状态；保存新版本后版本列表立即刷新。
- [ ] 新建对比实验包含目的、模型 URL、密钥引用、模块名、输出预设、后处理、运行模式、确认页和差异表。
- [ ] 后端详情接口返回样本、尝试、display result、annotation、lineage、导出所需摘要，不依赖前端下载 JSONL 才能查看。
- [ ] 复用原文实验可在不产生新模型调用的前提下更换后处理版本并生成可查看的对比结果。
- [ ] 所有新增契约有共享层 schema；后端返回通过 schema 或等价结构校验；前端 client 使用统一 request helper。
- [ ] 现有 `pnpm --filter @miniapp/shared test/typecheck`、`pnpm --filter @miniapp/backend test/typecheck`、`pnpm --filter @miniapp/batch-lab test/typecheck/build` 或仓库等价命令通过；不能运行时记录原因和剩余风险。

## Non-Goals

- 不改变线上聊天业务表写入路径。
- 不把 Batch Lab 纳入用户计费或真实用户历史写入。
- 不在浏览器端保存真实第三方 API Key。
- 不重写历史 migration；只允许新增 forward migration。
