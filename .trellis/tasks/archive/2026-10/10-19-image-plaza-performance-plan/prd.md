# 图片广场排序与创作交互性能优化规划

## 目标与交付边界

在最小改动、快速加载和稳定性优先的前提下，规划图片广场排序、工作室滚动、作品详情响应和参考图即时预览优化。

用户已授权“开始按规划执行”。分阶段实现并验证本规划；不部署、不执行远端 migration。TEST 验证与 production 发布须各自通过门禁。

## 需求

1. 标签下新增“推荐 / 最新”，默认推荐；搜索、标签筛选与排序共同生效。
2. 先以 TEST 现有作品按“模型内热度排名、跨模型逐轮交错”计算并固定初始顺序，仅用于零赞作品分页，禁止每次翻页重算。有赞作品按点赞数降序，同赞沿用现有分享时间/ID 降序，固定序位不参与；所有有赞作品先于零赞作品。来源热度不得变成站内点赞数。
3. 最新按分享时间降序。排序必须在服务端分页前完成，禁止客户端对已加载页局部排序冒充全局排序。
4. 工作室发送文本、生成状态更新、图片加载和键盘变化时，处于底部的用户稳定跟随；阅读历史的用户不能被轮询强行拉回。
5. 详情图片、“用同款”和点赞提供及时反馈，保留正确鉴权、失败提示和缓存一致性。用户确认“收藏”就是现有作品点赞，并要求提高处理速度：同时优化点击反馈、服务端确认及确认后的缓存同步，不能只用动画掩盖慢请求。先量测，不能把推测当作延迟原因。
6. 选中合法参考图后立即展示本地预览，上传中/失败/成功可辨识；只有上传成功的服务端引用可用于生成。

## 约束与非目标

- 不重构整套聊天、推荐、上传或缓存框架，不新增第三方依赖，不改生成计费、返利和导入逻辑。
- 不把私有 Storage 改成公开桶，不记录签名 URL、图片内容、提示词或身份凭据。
- “收藏”已确认是现有作品点赞，不新建收藏功能、接口或数据表，不改角色收藏。
- test/production 数据库结构、数据量、CDN 套餐和真实延迟均未现场确认；仓库 migration 不代表远端已部署。
- 一次初始化固定顺序、后续点赞优先已确认；固定序位不是点赞快照，跨页点赞移动的边界仍须明确。TEST 初始化结果不能未经映射验证直接复制 production。

## 验收标准（未来实现）

- [ ] 推荐/最新切换、搜索和标签组合正确；查询缓存隔离，不混用旧游标，不出现“最新”标签展示推荐结果却无过渡提示。
- [ ] 静态数据跨多页无重复/遗漏；任意有赞作品先于零赞作品。有赞同分只按时间/id，改变固定序位不能改变有赞排序；获赞进入有赞区，取消至零赞恢复固定顺序。
- [ ] 初始化序列按模型内热度及逐轮交错确定；空热度、同分、单模型、模型耗尽有确定结果。初始化只执行一次且可安全重跑/拒绝重跑，失败不留下部分编号；运行时查询不再计算窗口排名。
- [ ] 点赞/取消/删除/热度修改不重编号；筛选沿用初始顺序的子集，不承诺过滤或点赞变化后仍逐轮均衡。新增作品有明确且可分页的兜底规则。
- [ ] 明确并验证点赞/新增/下架发生在翻页期间的实时一致性限制和刷新恢复行为，不承诺未实现的快照语义。
- [ ] 连续轮询无新增内容时不重复平滑滚动；上滑历史、图片延迟加载、发送、切会话及键盘开合符合设计。
- [ ] 本地参考图预览与交互反馈在约定设备上目标 p95 ≤ 100ms（预览容器和状态反馈，不含大图解码/网络）；失败不伪装成功，晚到响应不能覆盖新的选择。
- [ ] 详情缓存预览不因原图请求清空；原图失败可重试，已下架/无权限不能继续作为有效作品操作。
- [ ] 点赞失败回滚，不覆盖其他作品的并发变更；“用同款”不自动重试非幂等创建、不导航到虚构会话。
- [ ] 点赞视觉反馈目标 p95 ≤ 100ms；成功响应直接校准 liked/count，无须等待详情/feed refetch 才完成反馈。单次操作不触发全量已加载页立即重取；对照记录写请求及服务端确认耗时，量化瓶颈优化收益。服务端改善幅度在基线后确定，不能将仅“不恶化”视为提速完成。
- [ ] 使用同设备、网络、样本和冷热缓存条件记录优化前后数据；目标路径 p95 不恶化超过 10%，否则阻断发布并分析。该阈值是建议门槛，不是现有实测成绩。
- [ ] shared 测试、消费者 typecheck、相关既有测试及 frontend lint/build 通过；涉及数据库时完成 TEST 单文件验证、权限/容量/回滚检查后再独立审批生产。
