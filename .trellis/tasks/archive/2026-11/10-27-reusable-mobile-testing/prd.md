# 可复用移动端预览与验收

## 目标与授权

用户已接受上一轮提出的「固定预览入口、固定测试状态、固定验收流程」方案，并明确要求完成搭建。日常页面修改可直接复用，不再逐次创建临时后端和一次性浏览器脚本。本次在独立分支基于 origin/dev 实施；用户已追加授权把较大功能主动提醒规则写入根AGENTS，并将本次验收工具通过dev发布main。初始基线a2b36e85，发布前已更新到7b53d65d。

## 范围

- 一条命令启动真实 Next.js 页面与固定模拟 API，修改源文件后热更新。
- 本地场景入口：普通用户、VIP、已签到、失败、余额不足、空列表、慢回复及图片失败等。
- 固定手机尺寸；按 profile / roleplay / chat / image 分组运行常用验收。
- 复用同一份场景数据、请求协议与启动命令；失败保留截图、网络诊断与 trace。
- 将使用规则放到仓库入口与测试文档，后续会话可以发现、运行和扩展。

## 约束

- 全部虚构数据，不读取真实用户、数据库、支付或模型服务。
- 不改变上游功能、支付、生成、计费或数据库逻辑。
- 未实现的模拟 API 显式失败，不以空对象或真实接口兜底。
- 场景初始状态可重置；自动验收与手动预览使用不同端口，互不重置。
- 模拟验收仅证明前端交互；不能据此宣称真实支付、供应商或手机系统已验证。

## 验收

1. 干净安装后可按文档启动；重复运行复用缓存，服务退出清理子进程。
2. 场景入口可切换 VIP / 签到 / 失败状态并进入对应真实页面。
3. 固定流程覆盖：签到成功与失败、VIP 引导和金额、角色卡进入/返回、聊天开关与流式思考折叠、图片用同款与模拟生成、余额不足。
4. 默认手机宽度及窄屏通过；无横向溢出，关键操作可点击。
5. 类型检查及适用既有测试通过；可见报告记录覆盖边界。

6. 对已被完整取代的一次性测试文件执行清理；保留仍有独立覆盖的测试及历史记录。

7. 较大功能的主动验收提醒以根AGENTS为权威入口；发布仅包含本次变更，不夹带dev尚未上线的短剧内容。
