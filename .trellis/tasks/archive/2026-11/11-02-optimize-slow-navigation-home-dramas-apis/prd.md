# 优化慢页面导航、首页、短剧与接口长尾

## Goal

基于 2026-10-31 与 2026-11-01 性能报告，降低一级页面首次切换、首页与 `/dramas` 的可感知等待，并缩短消息中心冷进入时等待首屏数据的概率；保持短剧播放、追剧位置、通知权威状态和既有 SSE 观测语义不变。

## Requirements

- 一级导航只在当前首屏关键路径结束后、页面可见且网络条件允许时预热，不能重新引入冷启动资源争抢。
- 首页与 `/dramas` 继续共享现有短剧目录缓存；不得预取有时效性的播放签名。
- `/dramas` 首次只挂载有限数量剧卡，临近列表底部再分批增加；筛选、搜索、返回滚动和完整播放队列语义不变。
- `/profile` 已确认存在未读消息时，可在后台预取消息中心路由与对应首屏列表；无未读时不增加列表请求。
- 不改变通知未读的服务端权威性、轮询语义或 shared API 契约。
- 保留当前工作树已有的 SSE 性能观测改动，不重写、不回退、不混入本任务实现。

## Constraints

- 仅修改 `packages/frontend`，不新增数据库 migration、后端缓存、公开 API 或依赖。
- 使用现有 `afterEntryBackground`、React Query 和剧场列表分批渲染模式，不建立通用预加载框架。
- 低速网络、节省流量、离线或后台页面不得主动预热。
- 不自动创建新测试文件；运行现有 Frontend 测试、typecheck、lint、build 与 `@drama`/`@profile` 适用回归。

## Acceptance Criteria

- [ ] 首页、短剧、角色/对话、创作、个人页之间的下一跳路由能在首屏后台阶段按优先级有限预热，且低速/后台条件跳过。
- [ ] `/dramas` 初次渲染的卡片数量有上限，滚动临近底部后可继续展示全部结果。
- [ ] `/dramas` 从详情返回到较深滚动位置时，恢复目标前后的卡片已经挂载；筛选和搜索不保留错误的旧批次位置。
- [ ] `/profile` 仅在相应分类有未读时后台预取消息列表，进入消息中心可直接使用 React Query 缓存并继续按原策略刷新。
- [ ] 首页短剧播放、播放地址实时确认、消息未读权威性和现有 SSE 代码不受影响。
- [ ] 受影响包的既有验证通过；无法执行的真实生产 P95/真机项被明确记录。

## Notes

- 生产 P95 需要部署后复测；本地验证只证明行为、构建和回归安全。
