# 技术设计

## 数据路径

1. 读取 10 月 26 日至 11 月 1 日既有日报和上一份周报，提取项目、查询字段、release 与已知口径切换。
2. 使用只读 Sentry API 对每个 48 小时重叠整窗重新查询；以 API 返回值为准，不用日报的截断窗口替代。
3. 使用仓库既有 Grafana 数据源/查询说明补充上线后的指标；查询无结果时保留缺失状态。
4. 生成逐日矩阵、趋势诊断、问题归因与下周行动项，保存到与现有报告相邻的位置。

## 可靠性与口径

- 所有时间均显式转换为 Asia/Shanghai，再以 UTC 参数请求，避免本地默认时区误差。
- 查询只读、有限重试；任何 API/数据源失败均在报告中标注，禁止将失败解释为零样本。
- 重叠窗口会放大相邻日相关性，报告明确提示不能将相邻列当作独立自然日。
- SSE 指标在埋点 release 前后分段，旧 release 没有新 Metric 时保留“无可见样本”。
- 不新增数据库对象、外部依赖、公开 API 或产品代码；拒绝为一次报告建立新通用框架。

## 恢复与验证

- 报告为新增文件，可直接删除或修订，不影响运行时。
- 交付前复核窗口边界、查询字段、单位、样本数与缺失值，并通过 Trellis 校验后归档。
