# 审计 Sentry 与 Grafana 链路及耗时口径

## Goal

系统性审计当前仓库所有主要用户链路、管理链路、后端接口、SSE、后台任务和外部依赖的 Sentry 与 Grafana 可观测性覆盖，并核对页面与接口耗时埋点是否在正确的业务边界结束。

## Requirements

- 以当前源码、配置、架构文档和可获得的只读观测数据为事实来源，不把文档设想写成已落地事实。
- 盘点 Frontend、Admin、Backend、Next route handler、客服代理、定时任务、CLI、数据库/外部供应商调用等主要链路。
- 对每条链路分别判断 Sentry 错误/追踪覆盖和 Grafana 日志/指标/追踪覆盖；区分“完全未接入”“仅错误”“仅日志”“仅慢请求采样”“已有完整时序”。
- 审计页面耗时的开始点、结束点、取消/后台/路由切换语义，重点识别页面已展示关键内容但计时仍等待次要请求、动画、预取或组件卸载的问题。
- 审计普通 HTTP 与 SSE：普通 HTTP 区分客户端等待、服务端处理和上游耗时；SSE 区分响应头、首事件/首 token、业务 done、流关闭，不把业务完成后的连接存活时间误算为生成耗时。
- 每项发现必须提供源码路径、符号或配置证据，标明影响、严重度、建议口径和是否需要线上数据进一步确认。
- 不读取或输出业务行、token、完整 initData、支付信息、消息正文或其他敏感数据；Sentry 仅使用只读 API。
- 本任务只交付审计报告，不修改产品代码、监控配置、Grafana 仪表盘或生产环境。

## Acceptance Criteria

- [ ] 给出覆盖矩阵，列出所有已识别链路及 Sentry/Grafana 当前状态。
- [ ] 给出未接入或部分接入链路清单，按 P0/P1/P2/P3 分级并说明缺失能力。
- [ ] 给出页面耗时埋点清单，指出起止点正确性、可见性/可交互边界及后台/取消处理问题。
- [ ] 给出 HTTP/SSE 耗时清单，明确首字节、首 token、done、连接关闭等口径是否混淆。
- [ ] 对无法从代码或只读数据确认的项目明确标为“待线上核对”，不得推测。
- [ ] 给出最小修复顺序与可验证方案，但不在本任务内实施。

## Android/iOS 性能 P95 门禁

- 受影响页面：无。本任务仅读取和审计现有实现，不改变任何页面行为或埋点。
- 受影响接口：无。本任务不改变接口、SSE、采样率或上报逻辑。
- Android 页面加载 P95：不适用；不发布产品变更，不虚构现有样本。
- iOS 页面加载 P95：不适用；不发布产品变更，不虚构现有样本。
- 接口 P95：不适用；报告可引用已有观测样本，但不设置变更目标。
- 数据来源与观测窗口：仓库当前代码/文档，以及可用时的 Sentry 只读数据；具体窗口在报告中记录。
- 发布后验证、无可见样本/低样本及不适用说明：无发布；缺少线上可见样本的结论标记为待核对，不补零或推测。

规划完成后同步填写 `task.json.meta.mobile_performance`：有影响使用 `required`，确实不影响移动端页面加载和接口性能时使用 `not_applicable` 并填写具体理由。门禁未完成时 `task.py start` 会阻断。
