# 支付上游建单可用性探测

状态：用户已批准实施；部署、启用及真实请求另行执行。

## 需求与边界

- 独立定时服务，默认每半小时创建一笔 1 元上游待支付订单，仅验证上游建单可用性。
- 复用当前支付网关，不付款、不打开收银台、不查单、不验证回调或到账。
- 不保存探测订单；订单号、上游单号、支付链接只在请求内存在，用完丢弃。不进入用户订单、钱包、支付事件或对账队列。
- 失败默认复用现有飞书告警；处理策略支持一个或多个，后续可新增其他处理方式。
- 每轮最多一次建单，固定 100 分；超时、策略失败及重启均不自动重发。单渠道默认 alipay，可配置 wxpay，不默认扩大成两个渠道。
- 探测开关通过独立服务的环境变量 PAYMENT_PROBE_ENABLED 控制，默认关闭，不接入运营配置。
- 允许复用现有告警事故/outbox 持久化，不新增探测表或调度状态表。

## 验收标准

- [x] 独立服务每半小时运行一轮，有限时间退出，无历史补跑。
- [x] 正常结果通过现有网关校验；HTTP 200/业务失败及非法响应均可识别。
- [x] 一轮仅一次 1.00 元建单；异常不查回、不补单，无本地订单或账务写入。
- [x] 首次失败通知，持续失败去重，成功后恢复；未执行/结果未知不能当作健康。
- [x] 单/多策略均可运行，一个策略失败不阻止其余策略，不重发上游请求。
- [x] 不泄露原始响应、URL、单号、签名或秘密；TEST/production 隔离，PR 默认禁用。

以上为源码、mock 回归及本地 IaC 校验完成口径；真实建单、飞书送达和远端部署验收见 verification.md 的发布交接。

## Android/iOS 性能

本次实现独立后台服务，不增加移动端页面或用户请求链的工作量；网关仅兼容增加可选取消信号，现有用户调用不变。P95 无直接改动目标；Android、iOS 及 API 基线均无可见样本，记录 null，不补零。启用前后各观察 24 小时充值页、用户建单 API P95、DB 连接及上游限流；样本不足延长窗口。以后若修改用户请求链，必须重新声明 required 并填写双端与 API 目标。
