# 聊天历史优先优化（2026-11-23，本地候选）

尚未部署。实现复用原详情接口和分页 RPC，没有新增数据库对象或迁移。线上 P95 改善尚待发布后的真实样本验证。

## 实现

交互补充（2026-11-23，本地候选）：模型、回复偏好和语音仍复用独立接口，打开面板或点击加载时立即放行。未保存的修改照常使用已保存配置；仅实际保存请求在途时短暂暂停发送/重生成/choice，保留草稿。模型选中态等待成功确认，模型读取被取消后不回写旧缓存。语音记录未确认时显示加载/重试，不误发生成请求；已有音频仍可播放。读请求共用10秒逻辑预算，模型/设置写入10秒、语音受理15秒且均不自动重发。没有新增聚合接口、RPC或迁移。详见[交互方案与验收](../.trellis/tasks/11-23-chat-history-first-entry/interaction-followup.md)。

选择最小必要并行读取，避免把钱包、模型、记忆、生成、计费等业务塞进一个聚合接口。分页仍受 owner/角色访问约束；显示名、权限或历史依赖失败不会伪装成空历史成功。GET 中原有同步恢复仍保留。

阶段计时是 Backend 依赖等待耗时，包含传输和映射边界，不能解释为数据库内部 SQL 时间。页面指标、GET 分位数不能相减推算阶段成本。

服务端等待截止会停止后续编排并中止可传递 signal 的分页；已经发出的共享身份读取或恢复写入可能继续，其结果仍由原数据库保护收口。客户端 abort 不能证明 SQL 已终止或写入回滚。

## 日志约定

- `history_page_kind=entry|older|poll|refresh|unknown`，`read_path=parallel`。用途由前端提供，只用于诊断；旧客户端缺失值记 unknown。
- `identity_ms/owner_ms/settings_ms/recover_ms/opening_ms/page_ms/map_ms` 仅记录实际运行的阶段；缺失阶段不补零。
- `conversation.detail.read`：正常 entry 抽样 10%；正常 poll/refresh 不额外打印摘要。慢读至少 1 秒或发生内部重试时全量 warn；失败/中断使用同一终态守卫，HTTP 基础日志保留。
- `failed_stage/failure_kind/cancel_source/delivery_conflict_reason` 为固定枚举。PT409 只确认交付状态冲突，具体拒绝条件仍记 unknown；不新增盲目重试。
- 保留既有 request/trace 关联和安全 `{ err }` 序列化。禁止正文、昵称、密钥、initData、任意错误文本及嵌套诊断对象进入日志；日志输出异常不改变详情结果。

执行结果见[任务验证记录](../.trellis/tasks/11-23-chat-history-first-entry/verification.md)。按用户要求，本轮不启动本地 UI 测试；此前被中断的 UI 尝试不能记为通过。

发布前仍需在已确认的隔离 TEST 环境核对真实 DTO、权限、版本、占位符、分页完整性、并发恢复与额度收口；核对 stale 查询计划和历史积压容量。未完成前不移除 GET 同步恢复。

建议后续扩展既有 `packages/ui-tests` 的 `@chat` 场景：长会话连续分页、刷新后历史保留、跨设备补页、切换会话晚响应、编辑/删除/点赞/分支/草稿与滚动定位；这次不启动该系统。

兼容顺序为 Backend → Frontend（允许独立部署兼容版本）。本次不要求 SQL 迁移；回退应用代码可恢复原串行调度和首屏大小，后台游标仅在内存中，重启从头扫描。出现错误增多、恢复不收口、DB 负载或页面 P95 退化时停止扩大发布并回退应用；不手工重发生成或重复扣费。
