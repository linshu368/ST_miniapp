# M5 — Image Registry & Push Strategy (GHCR)

This milestone turns the four M4 images into a repeatable, traceable, multi-arch
publish flow on **GitHub Container Registry (GHCR)**.

- **Registry:** `ghcr.io` — private packages are free, auth is wired to GitHub
  permissions, and CI gets a built-in token (no operator PAT to manage).
- **Architectures:** `linux/amd64` **+** `linux/arm64`. arm64 is published so the
  Apple-silicon (M2) dev box runs native images during the heavy local-debug phase.

---

## 1. Image namespace

All images live under the repository owner's GHCR namespace with a `st-miniapp-`
prefix:

| Service (compose) | Dockerfile                        | Build context | GHCR image                                |
| ----------------- | --------------------------------- | ------------- | ----------------------------------------- |
| `frontend`        | `ops/docker/Dockerfile.frontend`  | `.`           | `ghcr.io/linshu368/st-miniapp-frontend`   |
| `backend`         | `ops/docker/Dockerfile.backend`   | `.`           | `ghcr.io/linshu368/st-miniapp-backend`    |
| `st-backend`      | `ops/docker/Dockerfile.st-bundle` | `.`           | `ghcr.io/linshu368/st-miniapp-st-backend` |
| `nginx`           | `ops/nginx/Dockerfile`            | `ops/nginx`   | `ghcr.io/linshu368/st-miniapp-nginx`      |

> The CI workflow derives the owner from `${{ github.repository_owner }}`, so a
> fork automatically publishes under its own namespace.

## 2. Tag strategy

Every push publishes **at least two** tags per image:

| Tag               | Example       | Purpose                                                                    |
| ----------------- | ------------- | -------------------------------------------------------------------------- |
| `sha-<short>`     | `sha-5aed728` | Immutable, pinned to the exact commit. Use this for reproducible deploys.  |
| `<branch>-latest` | `dev-latest`  | Moving pointer to the newest build of that branch. Convenient for `up -d`. |

Tags are generated by `docker/metadata-action`:

```yaml
tags: |
  type=sha,prefix=sha-,format=short
  type=raw,value=${{ github.ref_name }}-latest
```

When the branch name contains characters that are illegal in a Docker tag, the
local script (`scripts/m5-push.sh`) sanitizes them to `-`; on CI the branch names
in use (`dev`, `dev_stage5_*`) are already tag-safe.

## 3. CI flow — `.github/workflows/build-and-push.yml`

- **Triggers:** `push` to `dev` and `dev_stage5_*`, plus manual
  `workflow_dispatch` (run it against any branch from the Actions tab).
- **Auth:** the built-in `GITHUB_TOKEN`. The workflow requests
  `permissions: packages: write` — **no operator PAT is required**.
- **Build:** `docker/setup-qemu-action` + `docker/setup-buildx-action` +
  `docker/build-push-action`, `platforms: linux/amd64,linux/arm64`.
- **Matrix:** the 4 images build in parallel (`fail-fast: false`), each with its
  own GHA layer-cache scope.
- `provenance: false` / `sbom: false` keep each manifest list to exactly the two
  requested platform manifests (clean `imagetools inspect`).

### One-time repo setting

GHCR packages default to **private**. For the built-in token to push, confirm:

> Settings → Actions → General → **Workflow permissions** = _Read and write
> permissions_ (or the per-job `permissions:` block, which this workflow sets).

The first successful push auto-creates each package and links it to this repo.
To make a package public later: GHCR Package page → _Package settings_ →
_Change visibility_.

## 4. How to pull manually

```bash
# Authenticate (PAT or GITHUB_TOKEN with read:packages). For private packages only.
echo "$GHCR_TOKEN" | docker login ghcr.io -u <github-username> --password-stdin

# Pull by immutable commit tag (recommended) ...
docker pull ghcr.io/linshu368/st-miniapp-frontend:sha-5aed728
# ... or the moving branch pointer:
docker pull ghcr.io/linshu368/st-miniapp-backend:dev-latest
```

### Verify multi-arch

```bash
docker buildx imagetools inspect ghcr.io/linshu368/st-miniapp-frontend:dev-latest
# Expect a manifest list with both:
#   - linux/amd64
#   - linux/arm64
```

## 5. Switching compose from `build:` to `image:`

`docker-compose.yml` is frozen in M4 (it builds locally). To run the published
images instead, override the `build:` services with `image:` — preferably via a
small override file so the frozen base file is untouched:

Create `docker-compose.ghcr.yml`:

```yaml
services:
  st-backend:
    image: ghcr.io/linshu368/st-miniapp-st-backend:dev-latest
  backend:
    image: ghcr.io/linshu368/st-miniapp-backend:dev-latest
  frontend:
    image: ghcr.io/linshu368/st-miniapp-frontend:dev-latest
  nginx:
    image: ghcr.io/linshu368/st-miniapp-nginx:dev-latest
    # The nginx image already bakes ops/nginx/nginx.conf (ops/nginx/Dockerfile),
    # so the read-only conf bind-mount from the base file is redundant. If you
    # want the image's baked config to win, drop the volume in this override:
    volumes: []
```

Then bring the stack up with both files (later file wins per key):

```bash
docker compose -f docker-compose.yml -f docker-compose.ghcr.yml up -d
docker compose ps          # all 4 containers should report healthy
./scripts/m4-smoke.sh      # drives the stack through the nginx gateway
```

> Pin to `sha-<short>` instead of `dev-latest` for reproducible / production-like
> runs.

Inline alternative (no override file): replace each service's `build:` block with
the corresponding `image:` line above and remove the nginx `nginx.conf` volume —
but that edits the frozen M4 file, so the override approach is preferred.

## 6. Local fallback — `scripts/m5-push.sh`

Single-host equivalent of the CI flow (build + push all 4 images, multi-arch),
for when you need to publish without GitHub Actions.

```bash
export GHCR_USERNAME=linshu368
export GHCR_TOKEN=ghp_xxx          # PAT with write:packages (never written to disk)
./scripts/m5-push.sh

# Build only (no push), e.g. to sanity-check arm64 cross-build:
PUSH=0 ./scripts/m5-push.sh
```

Credentials are read **only** from the environment and piped to `docker login`
via `--password-stdin`; nothing is persisted by the script.
