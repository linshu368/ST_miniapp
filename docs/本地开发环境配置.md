> 面向新加入的工程开发。把 **GitHub 仓库权限 + 本文** 交给新人，应能独立把 miniapp 在本机配好并跑通。
>
> 架构全貌见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)。本文只覆盖「拉代码 → 配环境 → 起服务 → 验收」。
>
> 状态：base 草稿。后续可补密钥发放渠道、Bot 真机联调、admin / cs-platform 专章。

## 0. 先对齐三个「环境」

新人最容易把三套名词混在一起。它们不是一回事：
| 名字 | 是什么 | 新人日常怎么用 |
| ---- | ------ | -------------- |
| Git 分支 `dev` | **代码真相** | 所有 feature 从它新建；本地保持与 `origin/dev` 同步 |
| Git 分支 `main` | **上线快照** | 不要直接推；生产 Railway / 生产 Vercel 跟这条分支 |
| Railway `development` | 跟随 `dev` 的共享测试 backend | 公网：`https://stminiapp-development.up.railway.app` |
| Railway `production` | 跟随 `main` 的生产 backend | 公网：`https://stminiapp-production.up.railway.app`，本地禁止当日常库 |
| Supabase **test** | 测试库 `zoqelpfhurwehlvypryl` | 本地 backend **默认连这里** |
| Supabase **prod** | 生产库 `wbtsfzozlmurljvglhpn` | 本地禁止连接 |
`DATABASE_ENV=development` 和 `DATABASE_ENV=test` **都会连测试库**，没有第三套「开发专用库」。区别见 [§7](#7-开发环境与测试环境怎么切)。

## 1. 你要跑通的是什么

本仓库是 pnpm monorepo。用户侧 Mini App 由两个进程组成：
| 包 | 职责 | 本地端口 | 线上 |
| -- | ---- | -------- | ---- |
| `packages/frontend` | Next.js 页面（大厅 / 聊天 / 创作 / 我的） | **3000** | Vercel |
| `packages/backend` | Fastify API（对话 SSE、钱包、角色卡等）。线上服务名 **`stminiapp`** | **3001** | Railway |
浏览器直连 backend，中间没有 nginx。所以本地必须同时满足：

1. backend 在 `:3001` 起来，`GET /health` 返回 200。
2. frontend 的 `NEXT_PUBLIC_API_URL` 指向你这次真正想打的 backend（本机或共享测试），不能留空后误打到别人的环境。
   `packages/admin`（运营台 :3003）和 `packages/cs-platform`（客服 :3002）**不是**跑通 miniapp 的前置条件，本 base 文档不覆盖。

## 2. 分支规则（拉代码前先读）

1. **`dev` 是代码真相。** 所有 feature 分支从最新 `origin/dev` 新建，不要从 `main`、不要从过期的本地 `dev`。
2. **`main` 是上线快照。** 生产部署跟 `main`。不要直接往 `main` 推日常开发提交。
3. **`dev` 不可落后于 `main`。** 生产 hotfix 合进 `main` 之后，必须回到 `dev`。你拉 feature 之前先 `git fetch` + 确认本地 `dev` 已快进到 `origin/dev`。
4. 合入目标是 `dev`（PR base = `dev`）。不要把未发布的 feature 直接打到 `main`。

```text
origin/dev  ──►  feature/<你的分支>  ──►  PR 合回 origin/dev
origin/main ──►  生产快照（跟 Railway production / 生产 Vercel）
```

## 3. 前置条件

| 项      | 要求                                | 说明                                            |
| ------- | ----------------------------------- | ----------------------------------------------- |
| 系统    | macOS / Linux                       | Windows 建议 WSL2                               |
| Node.js | **22.x**                            | 仓库 `engines` 与 CI 均为 22；不要用 20         |
| pnpm    | **9.15.9**（`packageManager` 字段） | 用 corepack 启用，不要全局乱装一个大版本        |
| Git     | 能访问 GitHub                       | 仓库：<https://github.com/linshu368/ST_miniapp> |
| 密钥    | 团队发放的测试环境凭据              | 见 [§6.1](#61-密钥从哪来不要自己猜)             |

启用 pnpm：

```bash
corepack enable
corepack prepare pnpm@9.15.9 --activate
node -v    # 期望 v22.x
pnpm -v    # 期望 9.15.9
```

## 不需要本机安装 Docker、PostgreSQL、Supabase。本地 backend 连的是**共享测试库**（云上 Supabase）。

## 4. 拉仓库并站住 `dev`

请仓库管理员先把你的 GitHub 账号加进 `linshu368/ST_miniapp`。

```bash
git clone https://github.com/linshu368/ST_miniapp.git
cd ST_miniapp
git fetch origin
git checkout dev
git pull --ff-only origin dev
```

开始做需求时，**从刚拉过的 `origin/dev` 拉分支**，不要基于过期的本地 `dev`：

```bash
git fetch origin
git checkout dev
git pull --ff-only origin dev
git checkout -b feature/<简短英文描述>
```

## `.env` / `.env.local` 已被 gitignore，不会进仓。不要把密钥提交上去。

## 5. 安装依赖

在仓库根目录：

```bash
pnpm install
pnpm --filter @miniapp/backend exec prisma generate
```

- 第一次 `pnpm install` 会装 husky。之后 `git commit` 会跑 Prettier；`git push` 若改了 frontend，会做一次 **不阻断** 的 lint 提醒。
- `prisma generate` 必须做一次。CI 也会跑；漏了的话 backend 启动会找不到 `@prisma/client` 生成物。
- **不要**在本地对共享测试库执行 Prisma migrate / 乱跑 `packages/shared/migrations/*.sql`。迁移由 GitHub Actions「Database Migration」手动触发，见 `packages/shared/migrations/README.md`。

## 6. 环境变量

真实值**不进仓库**。模板只给变量名和结构。

### 6.1 密钥从哪来（不要自己猜）

从 **Railway `development` / 测试库** 拉取整套环境变量，至少包括：
| 变量 | 用途 |
| ---- | ---- |
| `TEST_DATABASE_URL` / `TEST_DIRECT_URL` | Prisma。`6543` 是 pgbouncer 查询串，`5432` 是直连 |
| `TEST_SUPABASE_URL` / `TEST_SUPABASE_SERVICE_ROLE_KEY` | supabase-js（绕过 RLS，只放 backend） |
| `TELEGRAM_BOT_TOKEN` | 真机 / 带签名的 InitData 校验 |
| `LLM_API_KEY` | 对话生成（OpenRouter）。只跑大厅可以暂缓 |
开发时不要碰 `PROD_*`、不要从 Railway `production` 控制台抄连接串到本机。进程启动时有隔离守卫：非 `DATABASE_ENV=production` 时连到生产 project ref 会直接抛错。

### 6.2 backend：`packages/backend/.env`

```bash
cp packages/backend/.env.example packages/backend/.env
```

然后只改你的 `.env`，至少落到下面这份「本地最小集」。`dotenv` 从 **`packages/backend/` 作为 cwd** 读取 `.env`（`pnpm --filter @miniapp/backend dev` 会进到这个目录）。
启动时 `createDatabaseConfig` 会按 `DATABASE_ENV` 把 `TEST_*` 或 `PROD_*` **覆盖**到 `DATABASE_URL` / `SUPABASE_URL` 等标准名上，所以日常只要填对 `TEST_*` 组，标准名可以留空。

```bash
NODE_ENV=development
PORT=3001
FRONTEND_URL=http://localhost:3000
# 本地默认连测试库。development / test 都会选 TEST_* 组。
DATABASE_ENV=test
TEST_SUPABASE_PROJECT_REF=zoqelpfhurwehlvypryl
TEST_SUPABASE_URL=https://zoqelpfhurwehlvypryl.supabase.co
TEST_DATABASE_URL=<团队发放的测试库 pgbouncer 连接串>
TEST_DIRECT_URL=<团队发放的测试库直连串>
TEST_SUPABASE_SERVICE_ROLE_KEY=<团队发放>
# 标准名留给启动时自动覆盖，不要手填生产串。
DATABASE_URL=
DIRECT_URL=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
TELEGRAM_BOT_TOKEN=<团队发放>
LLM_UPSTREAM_URL=https://openrouter.ai/api/v1
LLM_API_KEY=<团队发放，对话功能需要>
# 浏览器直开 localhost、没有 Telegram InitData 时用。
# NODE_ENV=production 时无效。
DEV_AUTH_BYPASS=1
MOCK_AUTH=1
# 本地不必跑 OpenRouter 用量回捞。
CHAT_HISTORY_SYNC_ENABLED=false
PAYMENT_ENABLED=false
```

说明：

- `.env.example` 里的 ST 相关变量（`ST_BASE_URL` 等）是旧链路残留，本地起 miniapp **不用填**。
- 语音（`DEEPSEEK_API_KEY` / `MINIMAX_API_KEY`）缺了只影响「生成语音」，其余功能仍可用。
- `DEV_AUTH_BYPASS=1`：请求没有 `X-Init-Data` 时注入测试用户 `tg id=99999`。这是本机浏览器验收的推荐开关。
- `MOCK_AUTH=1`：有 InitData 但不验签，只解析 `user` 字段。回归脚本依赖它；本机可与 bypass 同时开。

### 6.3 frontend：`packages/frontend/.env.local`

前端目前没有入库的 `.env.example`。在 `packages/frontend/` 下新建 `.env.local`：

```bash
# 本机联调：打你自己起的 backend
NEXT_PUBLIC_API_URL=http://localhost:3001
# 必须为 0。=1 会强制走 mock，看起来「页面能开」但并没有打到 backend。
NEXT_PUBLIC_USE_MOCK=0
```

`NEXT_PUBLIC_*` 在 Next 启动时打进 bundle。改完必须重启 `pnpm dev:frontend`。
**不要留空。** `packages/frontend/src/lib/api/client.ts` 在未配置时会回落到 `https://stminiapp-development.up.railway.app`，你会误以为本机 backend 已经通了，实际打的是共享测试服务。
