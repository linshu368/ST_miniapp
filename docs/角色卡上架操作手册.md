# 角色卡上架操作手册

> 本文面向运营人员，说明如何使用上架工具将角色卡录入系统。
> 不需要理解代码，按步骤操作即可。

---

## 一、首次准备（只做一次）

### 1. 安装项目环境

确保电脑上已安装：

- Node.js（22 或以上）
- pnpm（9 或以上）

在项目根目录执行一次：

```
pnpm install
```

### 2. 配置密钥文件

项目目录下有两个配置文件需要填写，位于 `scripts/` 文件夹中：

| 文件                | 用途                                           |
| ------------------- | ---------------------------------------------- |
| `scripts/.env.test` | 连接**测试环境**（用于试传、验证）             |
| `scripts/.env.prod` | 连接**正式环境**（用于真正上架给用户看到的卡） |

打开对应文件，把 `SUPABASE_SERVICE_ROLE_KEY=` 后面填上密钥（找工程要）。

**填好后不要分享这些文件，也不要提交到 Git。**

---

## 二、上架一张角色卡

### 操作步骤

1. 把角色卡 PNG 文件放到项目根目录（或任意位置，记住路径）

2. 打开终端，进入项目根目录

3. 执行命令：

**上传到测试环境**（先试这个）：

```
pnpm import-character ./角色卡文件名.png -- --env scripts/.env.test
```

**上传到正式环境**：

```
pnpm import-character ./角色卡文件名.png -- --env scripts/.env.prod
```

4. 看到 `✅ 角色卡上架完成` 就成功了

### 命令示例

```
# 最简单的用法——上传一张卡到测试环境
pnpm import-character ./林清音.png -- --env scripts/.env.test

# 指定角色在大厅里的排列顺序（数字越小越靠前）
pnpm import-character ./林清音.png -- --env scripts/.env.test --sort-order 1

# 上传时自定义角色名（不用 PNG 里内嵌的名字）
pnpm import-character ./林清音.png -- --env scripts/.env.test --name "清音小姐"

# 上传到正式环境
pnpm import-character ./林清音.png -- --env scripts/.env.prod --sort-order 1
```

### 批量上架

目前工具一次处理一张卡。如果有多张，重复执行命令即可：

```
pnpm import-character ./角色A.png -- --env scripts/.env.prod --sort-order 1
pnpm import-character ./角色B.png -- --env scripts/.env.prod --sort-order 2
pnpm import-character ./角色C.png -- --env scripts/.env.prod --sort-order 3
```

`sort-order` 数字决定大厅排列顺序，数字小的排在前面。

## 三、上架后验证

### 测试环境验证

上传到测试环境后：

1. 打开 Supabase Dashboard → 切到 test 分支
2. 点 Storage → `character-assets` → `characters/` 文件夹 → 确认能看到新上传的文件
3. 点 Table Editor → `miniapp` schema → `characters` 表 → 确认能看到新增的行

### 正式环境验证

上传到正式环境后：

1. 打开 App → 进入大厅
2. 确认能看到新角色卡（位置、名字、简介是否正确）
3. 点击进入对话 → 确认角色能正常开口
4. 试聊两三句 → 确认对话正常

**任何一步有问题，截图告诉工程。**

## 五、常见问题

### Q：执行命令后报「PNG 解析失败：No chara metadata」

PNG 文件不是合规的酒馆角色卡。角色卡 PNG 里必须内嵌了角色设定数据。请确认：

- 文件确实来自 SillyTavern 或 CharacterHub 等角色卡平台
- 不是普通图片文件改了后缀名

### Q：报「缺少 SUPABASE_URL」

`.env` 文件没有正确配置。检查 `--env` 参数指向的文件路径是否正确，文件里的内容是否已填好。

### Q：报「Storage 上传失败」

- 检查网络连接
- 确认 Supabase 对应分支的 `character-assets` bucket 已经创建
- 确认密钥是否正确

### Q：大厅看到了卡，但点进去报错

可能是 PNG 上传成功但数据有问题，截图告诉工程排查。

### Q：想在正式上架前先测试一下效果

先用 `--env scripts/.env.test` 传到测试环境，验证没问题后，再用同一个 PNG 文件用 `--env scripts/.env.prod` 传到正式环境。两个环境完全独立，互不影响。

## 六、关于「排列顺序」的说明

`--sort-order` 参数决定角色在大厅的排列位置：

- 数字越**小**，排得越**靠前**
- 相同数字的按上架时间排列
- 新上架的卡如果不指定，默认 `sort-order = 0`

建议按 1, 2, 3, 4... 这样顺序编号，方便管理。

---

## 七、关于「系统兜底卡」（一般不需要关心）

有一个特殊参数 `--set-as-fallback`，用于设置"系统兜底卡"。

**什么是系统兜底卡？** 当用户正在聊的角色被下架时，系统需要一个备用角色来替补。这个备用角色就是"兜底卡"。

- 用户完全感知不到这个配置
- 它**不是**"用户打开 App 默认看到的角色"（大厅展示顺序由 `sort-order` 控制）
- 选择标准：**最稳定、最不可能被下架的那张卡**

一般情况下运营不需要动这个参数。如需更换，联系工程操作。
