# 运营平台新增功能开发计划

## 目标

在现有蜜镜AI运营平台上完成三组能力：

1. 每个 OpenRouter 模型独立配置 `markup`，范围 1—4、步长 0.5；展示价格和真实扣费均使用当前模型倍率。
2. 充值页面标题、说明、按钮文案和主题色可发布，并在运营平台中以真实颜色进行移动端实时预览。
3. 角色卡按“上架 / 下架”标签页管理，支持拖拽排序、上下架、软删除；用户大厅第 1—8 个上架角色固定显示流金样式。

最终稳定改动统一更新到 PR #145。蜜镜AI运营平台使用独立 Vercel 项目 `st-admin-platform` 部署。

## 数据规则

### 模型倍率

- 正式模型目录的每个模型保存独立 `markup`。
- 可选值：`1、1.5、2、2.5、3、3.5、4`。
- 展示价：`OpenRouter 每 token 美元价格 × 10000 × exchangeRate × model.markup`。
- 实际扣费：`round(OpenRouter 实际 usage cost × exchangeRate × model.markup)`。
- `llm_pricing_config.markup` 仅作为旧目录或未知模型的兼容默认值，不与模型倍率叠乘。
- 请求开始时快照模型倍率，避免异步拉取 usage 期间发布新配置导致扣费漂移。

### 充值页面

- 新增 `miniapp_recharge_page_config`。
- 字段：页面标题、页面说明、支付按钮文字、六位 Hex 主题色。
- 配置缺失时使用安全默认值，不影响套餐加载和下单。
- 后台颜色选择器、颜色色块、手机预览和用户充值页面必须使用同一真实颜色。

### 角色卡

- 上架角色与下架角色分属两个标签页。
- 下架只设置 `enabled=false`，不删除数据；下架角色可重新上架。
- 删除采用软删除 / 归档，不破坏历史聊天、收藏和 Storage 资源。
- 前八流金规则按已上架且未归档角色的 `sort_order` 计算，不再使用固定 UUID。
- 后台顺序、手机预览、Lobby API 和用户大厅保持一致。

## 实施顺序

1. 增加共享 Schema、幂等 migration、Admin RPC 和兼容读取。
2. 完成模型倍率编辑、展示价换算和真实扣费。
3. 完成充值页面编辑、真实颜色与实时预览，并接入 MiniApp。
4. 完成角色标签页、拖拽、上下架、归档、前八流金和大厅顺序。
5. 执行 shared、admin、backend、frontend、sync-engine 类型检查、单测和构建。
6. migration 先执行测试库并验证，再对生产库备份、校验后独立执行同一脚本。
7. Backend 联调只部署 Railway development；运营平台单独部署 `st-admin-platform`。
8. 按功能建立本地 commit，全部稳定后一次性推送并更新 PR #145。

## 验收标准

- 模型倍率可快捷选择和手动确认，非法步长无法保存或发布。
- 展示价和实际扣费使用同一个模型 `markup`，不会与全局倍率重复叠乘。
- 充值配置可发布、回滚；后台直接显示真实颜色，手机预览与用户端一致。
- 上架 / 下架角色分开显示；下架不删除，重新上架可恢复。
- 角色拖拽后顺序持久化，前八流金位置随排序变化。
- 删除角色需要二次确认并执行软归档。
- 测试库、生产库 migration 均可重复执行且不覆盖后续运营数据。
