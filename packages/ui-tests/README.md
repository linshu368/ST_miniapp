# 移动端预览与固定验收

日常页面修改先复用本环境。真实 Next.js 页面、React Query 和 SSE consumer 照常运行，API 由本机虚构数据提供；无需数据库、Telegram 登录、支付或模型密钥。不是生产联调环境。

## 快速开始

仓库根目录运行，Node >=22，pnpm 9：

```bash
# 首次安装，以后锁文件未变化可跳过
pnpm install --frozen-lockfile
pnpm test:ui:install

# 保持运行，页面源文件修改自动更新
pnpm preview:ui
```

场景选择：[http://127.0.0.1:3121](http://127.0.0.1:3121)。选择状态后进入真实页面；也可直接打开 [http://127.0.0.1:3120](http://127.0.0.1:3120)。浏览器 MCP / Codex 内置浏览器均可访问同一入口，不需要逐次写临时浏览器脚本。

若共享MCP浏览器提示已被其他会话占用，不终止他人的浏览器。独立MCP实例可使用官方 `--isolated` 模式；也可直接用内置浏览器查看预览、用上述固定命令验收。回归测试使用独立浏览器上下文，不依赖共享MCP浏览器的登录或锁状态。

首次访问新页面仍需要 Next 编译；日常让服务保持运行，后续修改热更新。Ctrl+C 停止自己的前端和模拟服务。端口占用时报错，不终止未知进程。模拟接口或场景数据修改后重启预览一次。

## 按修改范围运行

```bash
pnpm test:ui --grep @profile       # 签到、VIP、充值与社群展示
pnpm test:ui --grep @recharge      # 充值金额、到账确认、失败恢复、VIP回流和窄屏
pnpm test:ui --grep @roleplay      # 角色发现、进入对话与返回
pnpm test:ui --grep @chat          # 深度思考、回复偏好、多行输入、余额不足
pnpm test:ui --grep @drama         # 视频首页、双列剧场、选集、追剧、续看与错误恢复
pnpm test:ui --grep @image         # 同款、设置、生成、失败、保存原图入口
pnpm test:ui --project=android    # 390×844，全部固定流程
pnpm test:ui --project=narrow     # 320×568，关键布局流程
pnpm test:ui                     # 两种尺寸全部已配置流程
pnpm test:ui:report              # 可视化结果、截图、请求摘要、失败 trace
pnpm test:ui:fixtures            # 模拟服务本身的协议与隔离检查
```

自动检查自行启动并关闭3130/3131，不会重置手动预览3120/3121。连续复跑时可先运行 `pnpm preview:ui --test` 保留自动检查环境，随后命令会复用；用例会校验服务标识和工作目录。分别使用 `.next-ui-preview` / `.next-ui-test` 缓存，不覆盖普通 `.next` 构建。

每套环境一次一个场景，自动检查 workers=1、每轮重新初始化。运行自动检查时勿手动操作3130，也不要用 `--workers` 增加并发；需要并行时先设计独立状态。

## 固定场景

| 场景               | 用途                                                       |
| ------------------ | ---------------------------------------------------------- |
| `standard`         | 普通用户、可签到、VIP引导、基本聊天与影像路径              |
| `dramas`           | 视频首页、双列剧场、追剧与续看；12部虚构作品和本地演示视频 |
| `drama-list-error` | 短剧目录失败与重试入口                                     |
| `drama-play-error` | 播放地址失败、重试与换剧入口                               |
| `vip`              | 会员身份、签到150、充值与续费展示                          |
| `checked`          | 今日已签到、不可再次领取                                   |
| `checkin-error`    | 点击签到失败、保留重试、模拟余额不变                       |
| `vip-error`        | 权益读取失败，收益未确认时不显示引导                       |
| `community-joined` | 已确认加入及领奖，入口隐藏                                 |
| `empty`            | 角色、会话、短剧及作品为空                                 |
| `chat-slow`        | 发送后先展示思考，正文出现时折叠                           |
| `chat-error`       | 发送后流内失败与重试入口                                   |
| `no-balance`       | 聊天/图片余额不足反馈                                      |
| `image-error`      | 触发生成后失败，保留重试且不扣模拟余额                     |
| `image-pending`    | 触发生成后保持进行中，可返回看记录                         |

`fixtures/data.ts` 是场景与初始数据入口。金额仅为验收示例，不同步线上配置或用户资料。不要将 token、initData、生产响应、聊天或数据库导出放进 fixture / trace。聊天中的语音与附图仅提供静态配置和空记录，本轮不模拟它们的生成。

## 扩展方式

1. 优先在已有分组增加断言，复用 `tests/fixtures.ts` 的场景重置、网络检查和报告。
2. 新状态加在 `fixtures/data.ts`；新接口在 `fixtures/server.ts` 用 shared DTO/schema 适配。不要另起临时 mock。
3. 未实现接口返回 `501 preview_route_missing`，并使自动检查失败。不要用通配空响应或真实后端兜底。
4. 用 role、label、placeholder 定位；等待可观察结果，不固定等待秒数。布局检查关键按钮和横向溢出。
5. 日常按组检查，本工具不自动加入每个PR的完整CI；发布继续遵守既有质量门禁。

## 覆盖边界与清理

验证链路是浏览器 → API请求 → 模拟HTTP/SSE → 真实页面反馈。模拟余额仅验证UI同步，不证明真实记账、OpenRouter/Venice请求参数或支付回调正确。手机尺寸模拟不会产生安卓系统输入法，也不能证明Telegram原生保存、相册权限正常；这些继续专项验收。

既有Vitest、后端计费/并发/SSE/迁移测试有独立覆盖，保留。旧临时UI fixture及浏览器脚本只有在相同行为被接替且实际跑通后才清理；历史截图和验收记录不随意删除。

`output/playwright/` 的结果、日志、截图、trace、HTML报告及Next缓存均不提交。最新报告覆盖旧报告，需要留证时先另存任务指定位置。

依据：[Playwright webServer](https://playwright.dev/docs/test-webserver)、[fixtures](https://playwright.dev/docs/test-fixtures)、[网络控制](https://playwright.dev/docs/network)。

## 短剧移动体验

- `/`：视频首页。底栏五入口按「角色 / AI短剧 / 中央播放符号（首页）/ 生成 / 我的」排列；默认打开立即播放，支持上下滑换剧。
- `/dramas`：双列剧场；下滑仅固定搜索，栏目与分类随内容滚动，封面下仅显示剧名；追剧包含在追和最近看过。
- `/dramas/:id`：完整播放与选集；复用原3个只读API、签名链接和遥测。
- `/characters`：原角色发现页的新地址，UI不变；`/chats`和聊天链接不变。
- 追剧/位置只在当前设备保存；测试覆盖刷新后集数与秒数恢复、无效历史回退、换页旧媒体释放。截图在每条用例的输出目录和HTML报告中同时保留。
- 数据目录/集数/素材均为示例，真实长视频字幕构图、Telegram真机和生产签名服务仍需独立验收。

短剧第二轮场景已纳入 `@drama`：收藏/点赞独立、简介与选集、评论分页/发表/删除、开关评论不暂停/不擅自恢复播放、窄屏和收缩视口提交。`drama-interaction-error` 模拟点赞失败及“评论已提交但响应丢失”，验证草稿保留和同 UUID 重试不重复。仅使用虚构剧友与计数，不连接真实用户内容；真实 Telegram 键盘需产品另行真机验收。

连续观看与手势回归复用 `tests/drama.spec.ts`：评论期间续集/跨剧、草稿与评论提交归属、静音/倍速沿用、旧媒体释放、片尾预取但不抢播、选集等待、无下一条的安静结束；模拟 Telegram 8.0 桥，验证播放路由持续 disable、跨剧不释放、离开恢复。模拟桥与手机视口不等于 Telegram 原生宿主/系统键盘实测。

手感验收继续复用 @drama：真实触屏单击只切纯净、双击只切播放（不能闪控件）、纯净时单击可唤回导航；文字/中央图标上滑无死区、滑后不误点击、按住进度等续播、倍速直达/外点不暂停；两张面板下拉关闭/短拖回弹/正文滚动不误关，390与320宽均覆盖。不要用“单击暂停”替代用户明确的双击心智。

第六轮手感已纳入同一 @drama：画面拖动中真实位移、短拖/取消/多指回弹、快划；全宽进度的预览/提交/原播放状态/后台取消/暂停拖尾；首页完整短剧路由与返回位置、详情只在本剧换集；全局搜索退出恢复分类、试看不抢继续看、追剧整行点击。只扩展既有 drama.spec.ts，不另搭脚本或模拟后端。

发布前收尾仍复用同一文件：重试失败后成功且保留秒数/近片尾位置、新地址只装载一次、迟到重试不抢新集或退出页；首页指定选集参数消费后刷新续看；目录后台失败与同集换签名保留画面/秒数/暂停；已收藏与最近看过独立返回位置；长选集当前集定位及自主翻组。现有「时光旅人」演示扩为66集用于长列表验收，其余短剧不变。

公共导航适配沿用 roleplay.spec.ts 的 `@navigation @layout`：五入口在角色发现/对话、剧场、首页、影像、我的保持统一几何、选中状态和底部空间；首页纯净模式隐藏后退出恢复；末项/作品操作条不受遮挡；工作室、VIP/充值、消息和客服隐藏底栏且无空占位。可运行 `pnpm test:ui --grep @navigation` 复用390/320尺寸，客服空会话使用既有fixture协议，无外部服务依赖。

个人中心视觉验收继续复用 `@profile`：普通/VIP首屏手机截图，余额→签到→会员的层次与主要操作44px触区；保留真实模拟签到到账、两处会员引导、失败重试、社群领奖隐藏与充值跳转。导航可见名称为「AI短剧」「生成」，内部剧场/影像广场业务和路由不变。

## 充值页精修

复用 `profile.spec.ts` 的 `@recharge`：390/320尺寸的双列金额/单套餐全宽、不预选套餐、总到账/含赠送/实付、固定付款栏、客服与说明可达；保留渠道/下单参数、失败后的选择、VIP嵌套回流。金额全部为虚构示例，POST订单固定模拟失败，不发生真实付款。

- `recharge`：四档虚构套餐与VIP搭配展示。
- `recharge-error`：加载失败，保留重试与订单入口。
- `recharge-empty`：空套餐，不可下单。
- `recharge-unavailable`：全部支付渠道关闭时禁止下单。

充值收益展示复验同样运行 `@recharge`：到账字体明显大于卡片价格，赠送独立展示，配置原价后显示原价差额，缺少原价不编造省额；390/320布局不会横向裁切。`recharge`中¥36/¥88/¥168为本地演示原价，与线上配置无关。

首字 v4 回归复用 `@chat`：滚动到旧消息时首字仍交付、滚回不二报；`chat-partial-error` 模拟文字与错误同批返回，验证已到文字保留与首字成功、刷新恢复。该场景仍完全使用虚构数据，真实超时免扣由SQL/TEST接口专项验证。

## 角色互动

角色点赞、收藏数量和公开评论继续复用 `roleplay.spec.ts`，定向运行 `pnpm test:ui --grep @character-social`。`character-social` 提供首个角色已收藏、独立点赞数量和23条虚构评论；`character-interaction-error` 提供首次点赞/收藏写入失败，以及评论写入成功但响应丢失的场景。所有数据均为本地虚构数据，不连接真实评论或用户资料。

固定验收覆盖390/320手机尺寸：三个互动入口的44px触区、点赞/收藏独立及跨卡片/详情/聊天同步、评论直接打开且不跳转聊天、分页/发表/删除/举报、草稿在同一角色跨入口保留与不同角色隔离、关闭面板保留私人聊天输入、失败回滚与丢响应重试不重复，以及收缩视口时发送按钮可达。仍复用既有场景服务器、截图/请求诊断和失败trace；不另写临时mock或一次性验收脚本。

## 历史对话分支

复用 `chat.spec.ts`，运行 `pnpm test:ui --grep @chat-branch`。场景 `chat-branch` 提供200轮虚构聊天，`chat-branch-error` 模拟创建成功但响应丢失。按钮位于完整角色回复下，创建后自动进入独立新对话，原对话保留在现有对话记录列表；无额外“返回原对话”入口。

固定流程覆盖390/320尺寸的44px分支触区、向前分页、200轮回到第20轮、初始最多继承配置低水位（fixture为50）、分支再分支、继续聊/重答/刷新恢复、原对话与草稿隔离、同UUID重试不重复创建。继承内容为文字，原媒体和消费记录不复制；新生成继续使用已有功能。真实SQL原子性、计费事实不复制、权限与后续水位切换由隔离PostgreSQL专项验证，浏览器fixture不替代数据库和真实供应商验收。
